# Dukto Next Mobile 构建与许可证说明

更新日期：2026-11-25。

## 独立构建

移动源码位于本目录，桌面原件及Dukto参考目录不参与改写。使用C++14。固定依赖版本、下载地址和SHA-256在`../scripts/dependencies.json`，下载后核验摘要再解压。

GitHub Actions：`.github/workflows/mobile-build.yml`。Android使用Ubuntu24.04、JDK17、SDK35/build-tools35.0.0、NDK27.2.12479018；iOS使用macOS runner和实际记录的Xcode。Qt5.15.19、OpenSSL3.6.4由源码构建，依赖缓存按脚本和锁文件摘要区分平台。

在有相应工具链的宿主执行，路径替换为本机绝对路径：

```sh
python scripts/build_dependencies.py --platform android --prefix /work/install --work /work/dependencies
python scripts/build_app.py --platform android --prefix /work/install --build /work/build
# iOS必须在macOS上，将两个命令的platform改为ios。
```

Android环境须提供`ANDROID_SDK_ROOT`、`ANDROID_NDK_ROOT`和`JAVA_HOME`。iOS通过xcrun定位iphoneos SDK。应用CMake先编译核心/SQL静态归档，qmake再编译原生桥、Controller和QML并调用平台部署工具。

依赖成功不代表应用成功；应用成功不代表安装成功。`dependency-manifest.json`、`build-receipt.json`分别记录，不将deviceTestsPassed或signedForDistribution自动设为true。失败日志在Actions artifacts和`../evidence/build-attempts.json`保留。

## 主机回归

存储测试使用`cmake -S tests -B build-storage`；超过4GiB的完整复制需设置`DUKTO_TEST_LARGE_IMPORT=1`再执行CTest。测试会实际写入4GiB以上目标文件，磁盘空间不足应显示失败或按测试规则明确跳过，不能伪造通过。

主机界面目标通过`-DDUKTO_MOBILE_HOST_CHECK=ON`启用，链接移动副本的真实核心和控制器，原生选择器使用明确返回“主机测试”的桩。网络回归探针`dukto-mobile-probe`只在主机门禁构建，不随手机包分发。回环测试使用临时端口/临时目录，不连接客户服务端。

## 发行门禁

Android应记录所有原生.so的架构、ELF LOAD对齐及APK压缩/ZIP对齐，真机覆盖16KiB环境。单有`-z,max-page-size=16384`链接参数不能代替最终包检查。

iOS应记录实际SDK、最低部署版本、架构、签名、entitlements、描述文件有效范围；网络组播能力须存在于实际授权/签名中。未签名.app不能改扩展名当IPA。商店动态提交要求在发布前重新核查。

最终产物仅在各项通过后放入release/mobile/版本/android或ios，附校验和、许可证、证据索引；调试日志、缓存、私钥及配对令牌不随客户包分发。
