# Android目录导出崩溃修复

日期：2026-11-26。修复版原始APK完整系统UI复验已通过，真机仍待验。

## 实际现象与定位

原始790afac8 APK在Android15模拟器的run45704468824中，已通过32批接收、文字发送、冷热系统分享、系统单文件选择/导出、目录发送和目录导入逐字校验；首次点击“导出目录”后应用退出。失败收据为`../evidence/android-export-crash-790afac8.json`。

系统日志记录`OPEN_DOCUMENT_TREE typ=application/octet-stream`，随后为`ActivityNotFoundException`及JNI未清除异常导致的`SIGABRT`。目录选择动作被错误地附加文件MIME过滤条件，系统无法匹配处理器。这是产品缺陷，与此前测试脚本的记忆目录导航问题分别保留。

## 修复内容

1. 目录导出仅使用`ACTION_OPEN_DOCUMENT_TREE`；单文件导出继续使用`ACTION_CREATE_DOCUMENT`并设置MIME及建议名称。
2. 文件与目录选择共用启动封装。构造/启动失败时立即清除JNI异常，释放等待回调及目录状态，通过界面显示“无法打开系统文档选择器：…”；用户可恢复系统提供器后重试。
3. 保留所有独立接收器、中文/空格路径、空文件/空目录及导出内容逐字核对，不将显示选择器当作导出成功。
4. 完整目录验收后，在模拟器禁用真实DocumentsUI，核对错误与原进程存活；恢复提供器后重新打开并取消，验证busy状态释放。

修改仅位于独立移动副本，继续使用C++14、中文日期注释及原文件编码/换行。

## 操作说明

在“应用文件”进入要导出的目录，点击“导出目录”，选择系统允许的目标目录并授权。Android下载根目录可能不允许直接授权，需选其中子目录。取消后可重新选择。导出保留源目录结构；同名根目录会明确拒绝，不覆盖现有文件。

系统文档提供器被停用、卸载或策略限制时，先恢复系统“文件”/文档选择器再重试；修复版应显示错误并继续运行。
