## 交付内容与边界

`scripts/source_bundle.py`从指定提交的Git树和blob直接读取原始字节、保存可执行位；不读取工作区文件，不导出未跟踪文件、缓存或Git凭据。导出范围为独立移动项目、移动开发计划和四份移动构建流程。

归档内的`upstream/`包含`scripts/dependencies.json`列明的七份原始Qt/OpenSSL源码归档，全部核对固定SHA256。SQLite及Qt SQL驱动源码和原始压缩包已包含在项目的`shared/third-party/`中。Qt平台修改点、依赖配置、C++14应用构建及扩展构建均由随附脚本记录。

每个源码交付目录包含`DuktoNextMobile-source-提交前12位.tar.gz`、`SHA256SUMS.txt`和`source-verification.json`。包内`SOURCE-MANIFEST.json`记录完整提交及每件文件的摘要、大小、权限；验证器拒绝重复、额外、遗漏、损坏成员、链接和越界路径。外部校验和必须从可信交付来源核对；包内清单不具有数字签名作用。

## 创建与复核

在仓库根目录执行（Python3.12+，路径按宿主替换）：

```sh
python DuktoNextMobile/scripts/source_bundle.py create --ref 完整提交 --output /work/source-delivery --cache /work/upstream-cache
python DuktoNextMobile/scripts/source_bundle.py verify /work/source-delivery/DuktoNextMobile-source-提交前12位.tar.gz
```

同一提交及相同上游原归档产生可重复的包摘要。输出包已存在时拒绝覆盖。缓存命中仍复核摘要，损坏缓存立即失败，不以静默下载掩盖问题。

## 从交付包重建

在Linux构建Android、macOS构建iOS。解包后进入`DuktoNextMobile`目录；设置`DUKTO_SOURCE_ARCHIVES`为同级`upstream/`的绝对路径，随后执行《构建与许可证说明》中的依赖和应用构建命令。

该变量同时供依赖构建和应用阶段的许可采集读取。显式本地模式下，归档缺失、不是普通文件或摘要不符均立即失败，不回退网络；不设置变量时保持原有在线构建行为。上游归档保持原字节，平台修补在解压后由原脚本应用。

“本地源码模式”只覆盖项目锁定的Qt/OpenSSL来源。系统SDK、NDK、JDK、CMake、Xcode及Gradle仓库仍需预装或另行准备，不声称整个工具链可断网安装。iOS安装与签名仍需要有效Apple团队配置。
