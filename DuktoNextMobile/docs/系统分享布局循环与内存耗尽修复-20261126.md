# 系统分享布局循环与内存耗尽修复

更新日期：2026-11-26。

## 故障及证据

原始arm64 APK在Android15模拟器中安装启动、连续32批R6接收及落盘哈希均通过。在通过系统ACTION_SEND分享文字后，界面无法再找到IP连接按钮，最终返回系统桌面。run45673771655 / job139415725771 / artifact15050288616保留了原始logcat、截图、界面树和接收收据。

logcat显示分享后发生大量recursive rearrange和Polish loop，随后Java堆达到192MiB，在QtNative.notifyAccessibilityLocationChange报告OutOfMemoryError，JNI携带未处理异常调用GetStaticMethodID而SIGABRT。此轮没有进入发送，因此不能据此判定传输发送实现错误或将界面发送标记通过。

## 原因与修改

移动窗口header原为ColumnLayout，包含换行标签、动态分享提示、按钮和工具栏。ApplicationWindow根据header隐式高度安排内容，而布局又根据可用尺寸重新分配标签尺寸；系统分享改变横幅可见性后触发持续尺寸重排。大量位置变化还驱动Android无障碍通知，最后耗尽Java内存。

将header改成Column，宽度明确取window.width；换行标签和工具栏宽度取parent.width，指示器单独居中。这样水平尺寸只来自窗口，纵向尺寸由控件实际内容决定。保持无障碍功能启用，不通过关闭辅助服务或增大堆上限掩盖问题。

主机压力门禁加入与系统分享同形的视图快照，在窄屏、横屏和1.5倍字体之间切换。此快照仅用于主机门禁，不代替Android系统真实ACTION_SEND路径。
