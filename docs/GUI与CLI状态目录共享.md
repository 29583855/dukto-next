# GUI 与 CLI 状态目录共享

更新日期：2026-11-08。R127 接入服务器页、后台动作、空闲监听及显式资料诊断。实际验证状态见本轮索引和主计划；普通历史迁移、全部生产写入准入及自动回收仍在实施。

服务器页公开的状态目录就是 CLI 的 `--state-directory`。桌面默认数据目录下的 `remote/` 保持原位置；CLI 要访问桌面保存的服务或资料，传入该 `remote/` 的完整路径。两种入口均在这个实际父目录的 `budget/` 中核对同一持久协调域，并打开其直接 `service/`、`clients/`、`transfers/` 成员。程序不按目录名字猜测其他父目录的域，也不自动合并不同的用户指定状态目录。

已有服务身份、授权、配对资料及传输记录原位使用。第一次业务使用只补充预算控制区和成员标记；已有配置继续沿用，损坏、复制或跨域标记拒绝，不删除重建。上一级普通 `history.sqlite`、`receipts.sqlite` 和用户输出仍保持原位置；它们尚未迁移或进入这个共享账本，不能把服务器页接入解释成全应用总预算已生效。

每次 GUI 后台动作取得业务根时，返回句柄保留协调会话到工作线程完成。普通操作、控制操作和其他同目录 CLI 进程可以共享使用；配置维护需要独占协调资格，活动者存在时明确拒绝。取消在预算锁外响应，不将正在使用的共享锁原地升级为独占。

GUI 本机监听器从启动前取得服务根，到停止并等待全部连接工作线程结束后才归还。没有连接的空闲监听同样占用资格。端口或身份校验失败由局部对象清理，不留下禁止后续维护的会话。析构顺序先清理监听器及动作线程，再释放成员资格，不能靠窗口控件状态推断后台已经退出。

`doctor --profile` 使用只读观察：不为未登记的旧资料建立预算或成员标记；发现已有协调域时则核对标记并在认证期间保留共享资格。诊断不会迁移资料、更新信任或创建业务任务。

新增真实 GUI/CLI 场景从旧身份开始，在中文空格目录中验证：GUI 读取身份后原件保持；空闲监听使独立 CLI 的预算修改返回权限错误；停止后同一修订可用；端口被占用导致启动失败后仍能修改；CLI 与 GUI 公开的服务身份一致。既有 GUI 双向传输、恢复与原始 Qt 测试继续运行，按每个平台的原件登记结果。

这里的共享资格保证状态维护与业务生命周期协调。SQLite、原子替换、临时正文、原生分配量及未知对象的写前额度接入仍未完成，因此 `productionQuotaEnforced` 保持 `false`。后续历史迁移必须单独保护已有普通文件、热日志及中断恢复；最终用户文件不归自动回收。
