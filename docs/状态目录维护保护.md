# 状态目录维护保护

更新日期：2026-11-07。

R104先提供维护互斥基础。过期任务回收、临时数据清理、全局磁盘配额和CLI清理入口仍须分别实现与验收。

普通GUI、CLI、服务工作者和任务结果读取者通过PrivateStore持有共享占用；维护者必须在打开任务数据库及清单前显式构造Use::Maintenance。独占锁不等待已有使用者退出，冲突立即失败，不能通过删除任务锁、忽略SQLite繁忙或暂停某个线程强行进入。独占持有期间，新的普通使用和第二个维护者也失败。所有相关数据库和读取对象须先于PrivateStore析构。

Windows使用LockFileEx；Linux/macOS使用flock。每个PrivateStore增加一个内核文件句柄/描述符，不创建后台线程或计时器；进程退出由内核释放锁。锁文件state-use.lock永久保留且为空，不写PID、不按文件年龄删除。它只用于协调同一机器上采用此机制的进程；状态目录必须位于已验证支持所需锁语义的本地文件系统，不据此承诺跨机器共享网络目录维护安全。

新建锁从一开始使用私有权限；打开现有项时不收紧权限、不截断内容、不跟随链接。重验所有者、普通文件类型、单链接、零字节及私有访问权限；POSIX每次状态访问另比对锁描述符与路径的设备/inode。Windows不分享删除权限，持有句柄时阻止替换。所有普通状态接口保留锁名称及大小写变体，不能通过read/write/remove/exists/validateFile更改或访问锁。

旧版本没有参与此锁。它不能保护仍在运行的旧程序、外部SQLite编辑器或直接操作状态文件的脚本。执行未来维护前必须停止这些使用者，并验证任务锁、恢复/幂等保留期和真实文件身份；仅取得本锁不能作为允许删除所有终态任务的依据。暂不开放任何删除命令。

回收的后续步骤仍包括：有界预览、区分可恢复任务和完成结果、保留有效幂等键、固定临时文件身份、崩溃可重入的回收顺序、SQLite旁路文件和总磁盘预算。用户原文件、已发布最终文件、活动任务及未知身份项不得猜测删除。
