# 状态占用查询

更新日期：2026-11-08（R121）。

在 Windows、macOS、Linux 上使用同一独立 CLI 查询指定状态根的直接普通文件逻辑长度和系统报告分配量。先退出使用该状态根的 GUI、CLI 和服务；查询取得独占维护锁，遇占用立即拒绝，不等待或终止活动进程。

~~~text
dukto-cli client storage --state-directory <客户端状态父目录>
dukto-cli client storage --state-directory <客户端状态父目录> --json
dukto-cli serve storage --state-directory <服务器状态父目录> --json
~~~

客户端命令只检查父目录下的 transfers，服务器命令只检查 service。根必须已经存在并具有当前用户私有权限；查询不会建立这些状态目录。省略父目录时使用该 CLI 的 Qt AppLocalDataLocation。这两个命令不汇总父目录的其他内容，例如 clients 内的配对资料、父目录内的旧版接收记录或独立配置文件。

结果按固定后缀分为七类：SQLite 主库、回滚日志、WAL、共享内存、JSON、锁、其他普通文件。未知普通文件也计入总量。永久的零长度 state-use.lock 计入文件数。类别仅为计量标签，不证明文件属于本程序或可以删除。

--json 输出一条 UTF-8 JSONL，事件为 state-storage、版本为 1。主要字段：

| 字段 | 含义 |
| --- | --- |
| stateDirectory / observedUtc | 实际状态根及开始观察时的 UTC 时间 |
| entries / regularFiles / logicalBytes | 直接目录项数、普通文件数及逻辑长度总和 |
| allocatedBytes / sqliteSidecarAllocatedBytes | 直接普通文件/SQLite旁路的系统分配量按名称合计；不等于独占物理消耗 |
| sqliteSidecarBytes | 回滚日志、WAL 和共享内存三类逻辑长度之和 |
| categories | 固定七项，含 kind、files、logicalBytes、allocatedBytes |
| hardLinkedNames | 链接数大于一的普通文件名称数；各名称长度保守重复计入总量 |
| excludedDirectories / excludedLinks / excludedSpecial | 排除的子目录、链接/重解析点及特殊文件数 |
| directRegularFilesOnly | 没有上述排除项；不代表所有权、删除资格或物理占用精度 |

所有数量及字节字段使用十进制字符串，避免超过 JavaScript 精确整数范围时失真。人类输出同样保留完整整数，状态根路径使用 JSON 转义，文件正文和逐项名称不进入报告。

计量逐项使用原生文件属性，不建立随目录项数量增长的列表，不递归子目录，不跟随符号链接、junction 或其他重解析点，不打开 FIFO 正文，也不打开 SQLite 连接。因此观察热回滚日志不会触发恢复、删除旁路或改变数据库内容。每项响应中断，周期性重验私有根和维护锁，目录项发生可检测变化时明确失败，不输出部分成功报告；长度或计数溢出也失败。

逻辑长度不等于磁盘实际分配量：稀疏文件、压缩和硬链接会造成差别。独占锁只协调遵守本项目状态锁的本机进程；外部程序对已有文件的任意原地修改不能由目录时间戳全部检测。结果不是任意外部写入环境下的原子文件系统快照，也不能据此安全删除未知数据。

R118提供计量基础，尚不强制执行全局总配额或自动 GC。传输正文、子目录及其他状态根的计量与预算协调，活动/历史清单分类、保留有效幂等记录和自动回收继续按主计划实施。

验证覆盖超 4 GiB 稀疏逻辑长度探针、真实热 SQLite 日志原字节保持、原生硬链接、子目录/链接/特殊项、取消/目录变化、4096 项重复计量和真实客户端/服务器 CLI。逻辑长度探针不作为大文件传输验收；本机 Windows 无符号链接权限的用例保留跳过，POSIX FIFO 和原生跨平台结果以对应回执为准。

R121增加原生身份逐项接口及系统分配量，详见[状态文件原生观察](状态文件原生观察.md)。身份不会出现在CLI报告中，也不自动去重或授予删除资格；总配额与自动GC仍未接入。
