不能用以下做法代替总配额：把每个库各256MiB相加却没有全局协调；只在开始或提交后检查大小；把每库最大额度完整预留却未覆盖旁路和临时索引；把 SQLite cache_size 当作磁盘或整体内存硬上限；把 journal_size_limit 当作活动事务日志写入上限。后者主要控制事务结束后保留的日志大小，不能独立保证写事务峰值。

写入接口的探针必须基于各平台实际部署的Qt SQLite插件。若现有接口不能拦截所需写入，应先实现并验证兼容C++14的驱动/文件访问适配，再接入业务；不能以配置声明代替有效限制。对外部任意程序直接写同一目录，不声称应用层预算能代替文件系统原生配额。

至少保留以下验收原件：

- 两个真实进程竞争最后一份额度，合计不越界；不同任务、上传/下载和旧版接收同时执行。
- 主库、热回滚日志、WAL、shm、临时排序索引及原子替换分别触达额度；拒绝后原库、凭据、用户目标与可恢复记录保持。
- 在预留、写入、提交、删除意图、删除后确认及归还各边界真实退出进程；重启对账和重复执行不重复释放或删除同名新对象。
- 历史预算满时仍能查询有效幂等结果、恢复原任务；禁止靠遗忘请求键释放任务数量上限。
- 活动/暂停/终态/未知归属项混合，自动GC只处理证据和保留期均允许的项；中断后可继续，实际释放量独立核对。
- 大量文件多轮执行，RSS/私有内存、句柄、线程、预算账本及临时项数量不持续增长；真实ENOSPC与应用预算不足分别报告。
- Windows、Linux、macOS两架构使用精确源码完成原生验证，保持既有恢复、权限和传输时限门槛。
