# Linux载荷ABI与系统基线

更新日期：2026-11-09。R150补齐包内真实ELF的glibc需求记录和Ubuntu构建基线选项；完整系统兼容、干净系统和最终交付仍按实际结果验收。

旧打包器固定把Ubuntu24.04/glibc2.39写入说明，与实际构建位置、应用及随附库的符号需求没有直接关联。新版分别记录宿主`getconf GNU_LIBC_VERSION`、发行版原文，以及所有实际部署ELF的需求节。导出定义节中的版本不算作需求，数值按整数元组比较。包说明使用全部载荷需求的最大值，不能只检查主程序而漏掉Qt、OpenSSL或其他随附库。

`GLIBC_ABI_DT_RELR`按其glibc2.36加载器需求计入；未知能力和`GLIBC_PRIVATE`等私有需求直接拒绝打包，避免生成无法解释最低环境的包。GNU工具在固定C语言环境执行；路径仍以独立参数传递。`package-manifest.json`的`glibcAbi`记录最低版本、所有数值需求、额外加载器能力及逐ELF来源。数值只表示必要的ELF兼容条件，完整桌面/图形驱动、字体和发行版兼容仍需运行取证。

GitHub Linux打包工作流新增显式`runner`选项，可选择Ubuntu24.04或Ubuntu22.04，默认仍为原有24.04。每个选择都实际编译、部署、迁移，并执行完整核心、X11/Wayland、窗口导航及传输/覆盖/恢复测试，不用新编译成功替代迁移通过。预览包的实际系统基线以该次成功原件为准，不从选项名称推定已支持。

边界专项核对定义/需求节区分、2.9与2.35排序、加载器最低版本和未知/畸形需求拒绝；Linux原生专项还以同一真实ELF分别通过readelf需求节和objdump未定义符号交叉核对。Windows仅显式`--parser-only`检查解析边界，不授予原生ELF资格。独立Ubuntu虚机已完成真实ELF交叉核对：宿主glibc2.39，样本实际需要2.34，说明宿主版本不能替代载荷要求。

原件保存在`docs/validation/2026-11-09/linux-abi-baseline-r150/`。客户最低发行版仍待明确；先补充Ubuntu22.04的构建和运行验证，不将其推定为麒麟、统信、CentOS或musl兼容。生产C++保持R149，本项仅修改Linux打包、原生ABI专项及工作流。

新扫描器还对独立虚机已有R140完整部署包132个真实ELF逐项观察成功，实际最高需求glibc2.38、无额外加载器能力。该旧载荷观察原件单独保留，不能当作R150新包或Ubuntu22.04完整运行通过。
