# 状态文件原生观察

更新日期：2026-11-08。R121提供私有根直接文件的逐项原生身份和系统分配量；Q01/Q02整体、跨进程预算及自动GC仍未完成。

`PrivateStore::visitStorageEntries`要求独占维护资格，逐项调用观察者；支持取消，每64项重验受保护根/占用锁，目录变化或属性失败时拒绝，异常仍释放枚举资源及固定缓冲授信。不会递归、读取正文或打开SQLite数据库。使用者也必须按项处理，不建立无限名称列表；回调收到的是瞬时值，不能将它当作可继续操作的固定文件句柄。

普通文件的`NativeDirectoryEntry`包含逻辑长度、链接数和`allocatedBytes`，以及`identityPlatform`、`volume`和16字节`identity`。平台1为POSIX设备/inode（inode按低字节在前编码，剩余字节为0），平台2为Windows64位卷序号/128位文件ID；与R120的SQLite句柄观察格式一致。Windows从本次属性句柄查询FileIdInfo/FileStandardInfo，POSIX对固定目录fstatat，不额外打开再关闭数据文件，避免释放本进程的POSIX数据库锁。身份/分配量查询不支持或失败时不回退为零。

子目录、符号链接/重解析点和特殊项继续单独排除，不给它们虚构普通文件身份。观察不证明文件属于哪个任务、不保证外部程序没有原地改写，也不能据inode/PID或名称进行删除。原生身份只在对象生命周期内关联；后续持久账本还需核对父目录、对象换代和未决I/O，安全GC继续使用独占维护及已有持久删除凭据。

`client storage`与`serve storage`的JSONL仍为版本1，新增`allocatedBytes`、`sqliteSidecarAllocatedBytes`及各固定类别的`allocatedBytes`，均为非负64位十进制字符串。CLI不输出逐项名称、原生身份或正文。按名称保守合计，硬链接可能重复；稀疏、压缩、克隆及共享块下的系统分配量不等于底层独占物理消耗。

本轮新增验证包括：实际SQLite句柄与目录身份/长度/分配量交叉核对；硬链接相同、等长独立文件不同；真实稀疏大文件；64轮回调异常后复用；枚举之后第二进程仍被SQLite写锁拒绝，原事务提交后该命令成功。完整状态专项继续覆盖热日志不恢复、四千文件常量汇总、排除项、取消/目录变化及真实CLI。双Windows各30完整核心已验，三项新方法通过；四原生专项在30169754全部通过：Windows14条，三个POSIX各15条，零跳过；完整30核心已验4/4，完整协议/部署另按终态原件收验。
