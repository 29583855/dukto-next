# Dukto Next 服务器上传下载使用说明

更新日期：2026-11-11。

如果Windows客户端点击“上传文件”、选好文件后进程退出，见[服务器上传界面故障处理](服务器上传界面故障修复-20261111.md)，应使用包含选择窗口生命周期修复的新版程序。

Dukto Next 支持将本地文件或目录上传到服务器，也支持浏览服务器共享目录并主动下载文件或目录。首次使用需要在服务器端配置共享，并在客户端完成配对；以后可以使用保存的资料连接。

本文以 **Mac 作为服务器、Windows 作为客户端** 为例。Windows、macOS、Linux 也可以交换角色，操作流程相同。服务器端需要运行 Dukto Next 的服务器服务；此窗口不能直接连接普通 FTP、网盘或原版 Dukto。

Windows Server 2012 作为服务端、Windows 11 作为客户端时，也按同一共享与配对流程操作。若客户端提示“私有状态所有者或继承策略不安全”，按[Windows配对权限错误处理](Windows配对权限错误处理.md)先导入配对文件。

## 一、使用前准备

- 两台电脑安装并运行 Dukto Next，网络能够互相访问。首次操作建议在同一局域网中进行。
- 在服务器上准备一个实际存在的共享文件夹，例如 Mac 上的 `/Users/你的用户名/Shared`。
- 确认服务器的局域网 IP。下文以 `192.168.1.20` 为例，实际操作时必须替换为你自己的服务器 IP。
- 服务器防火墙允许 Dukto Next 接收入站连接，默认服务器端口为 **TCP 4646**。

服务器上传下载使用独立的 4646 端口；首页局域网设备收发默认使用 4644 端口，两者的配置和操作入口不同。

## 二、在 Mac 上配置服务器

### 1. 建立服务器身份

1. 打开“服务器”窗口，切换到“本机共享”页。
2. 在“证书对应的本机 IP/主机名”输入框中，将默认的 `127.0.0.1` 改为 Mac 的实际局域网 IP，例如 `192.168.1.20`。
3. 点击“建立身份”。已经建立过身份时，点击“读取身份”查看已有身份。
4. 保存界面显示的服务器 SHA-256 指纹，后续在 Windows 配对时需要核对并填写。

`127.0.0.1` 表示当前电脑自身，不能作为另一台电脑连接这台服务器的地址。若已有证书中的 IP/主机名需要更改，按“证书续期”流程处理，详见[证书续期与指纹迁移](decisions/0015-证书续期与显式信任迁移.md)。

### 2. 配置共享文件夹和权限

1. 共享名称填写 `docs`。这是客户端使用的共享名称，不是磁盘目录路径。
2. 在“本机共享目录”旁点击“选择”，选中准备好的共享文件夹。
3. 根据需要勾选权限。需要完整上传下载时，勾选“浏览”“下载”“上传”。
4. 点击“保存共享”。

| 权限 | 客户端可以进行的操作 |
| --- | --- |
| 浏览 | 查看共享目录中的文件和目录列表 |
| 下载 | 将共享内的文件或目录下载到客户端 |
| 上传 | 将客户端文件或目录写入共享目录 |

### 3. 启动服务并生成配对文件

1. 监听地址保持 `0.0.0.0`，端口保持 `4646`。
2. 点击“启动本机 TLS 服务”。窗口底部应显示本机服务已监听的地址和端口。
3. 保持共享名称为 `docs`，以及所需的“浏览”“下载”“上传”权限勾选。
4. 点击“颁发本共享的配对文件”。窗口底部会显示生成的 JSON 配对文件位置。
5. 将这个 **JSON 文件本身** 复制到 Windows，并将服务器指纹交给 Windows 使用者核对。只复制 Mac 上的文件路径，Windows 无法读取对应文件。

`0.0.0.0` 是服务监听地址；客户端仍应连接服务器的实际 IP，例如 `192.168.1.20`。

配对文件包含一次性配对凭据，应通过可信方式交付，并保存在仅当前用户能够访问的目录中。配对凭据有有效期；如果提示过期，请在服务器重新颁发。

**Windows 客户端的权限准备：**从另一台电脑复制来的 JSON 文件，建议先使用[Windows配对文件导入工具](../scripts/import-pairing-windows.ps1)复制到当前账户的专用私有目录。之后在配对窗口中选择工具输出的新路径。普通下载目录即使只有你在使用，也可能因 Windows 权限继承设置而被程序拒绝，详见[操作步骤](Windows配对权限错误处理.md)。

## 三、在 Windows 上完成首次配对

1. 打开“服务器”窗口，进入“连接与文件”页。
2. 在“已保存的服务器资料”下填写资料别名，例如 `mac-office`。每台新服务器使用不同且未用过的别名；只有确认 `default` 尚未绑定其他地址或指纹时，才继续使用 `default`。
3. 勾选“首次连接：展开配对设置”。
4. 填写以下内容：

| 输入项 | 示例或填写方法 |
| --- | --- |
| 服务器 IP:端口 | `192.168.1.20:4646` |
| 服务器 SHA-256 指纹 | 与 Mac 界面核对一致的完整 64 位指纹 |
| 配对文件路径 | 点击“选择”，选中复制到 Windows 的 JSON 配对文件 |

5. 点击“配对并保存资料”，确认底部提示配对成功。
6. 共享名称填写 `docs`，与 Mac 上保存的共享名称保持一致。

以后使用时填写同一个资料别名，点击“连接”即可，不需要每次重新配对。Mac 端需要继续运行，并保持本机 TLS 服务已启动。

资料别名会绑定服务器地址、端口和证书指纹。首次配对失败也可能保留待配对资料；之后修改地址或指纹，再用原别名点击“配对并保存资料”，会提示“现有资料目标或指纹不同，拒绝覆盖信任”。处理方法见下文“资料冲突的处理”。

## 四、浏览服务器文件

1. 在“连接与文件”页确认资料别名正确，并连接服务器。
2. 共享名称填写 `docs`。
3. “共享内相对路径”先留空，表示共享根目录。
4. 点击“浏览”，查看文件和目录列表。
5. 点击目录条目后，相对路径会更新；再次点击“浏览”查看该目录内容。
6. 返回上层时，点击“上级”，然后点击“浏览”刷新列表。

相对路径填写共享内部的路径，例如 `reports/2026`，不要填写服务器磁盘的完整路径。列表有后续内容时，使用“下一页”继续查看。

## 五、上传文件或目录

1. 确认共享名称为 `docs`。
2. 将“共享内相对路径”设为服务器中已有的目标目录；留空表示上传到共享根目录。
3. 点击“上传文件”，选择本地文件；或者点击“上传目录”，选择本地目录。
4. 选择完成后开始上传，查看窗口底部结果，并在“任务”页查看任务状态。

例如，Mac 将 `/Users/你的用户名/Shared` 配置为共享 `docs`。Windows 将 `合同.pdf` 上传到共享根目录后，文件将保存在 Mac 的这个共享文件夹内。

上传目标必须是目录。若刚刚在列表中点选了某个文件，请先将相对路径改回目标目录，再进行上传。

## 六、下载文件或目录

1. 点击“浏览”，找到需要下载的文件或目录。
2. 点击该条目，确认“共享内相对路径”已经指向目标，例如 `合同.pdf` 或 `reports`。
3. 在“本地保存目录”旁点击“选择”，选择 Windows 上已有的保存文件夹。
4. 点击“下载”，查看底部结果和“任务”页中的任务状态。

例如，选择服务器上的 `合同.pdf`，本地保存目录选择 `D:\接收文件`，下载完成后到这个目录中查看文件。下载按钮不可用时，先检查是否选择了本地保存目录。

## 七、常用传输选项

- **传输并发：**首次使用可以保持默认值 `1`，确认能够正常传输后，再按需要调整为 `2`、`4`、`8` 或 `16`。
- **同名处理：**展开“冲突、重试和总时限”后选择。默认“保留双方（自动重命名）”；也可选择遇到冲突停止、覆盖同名普通文件、跳过同名文件或目录。
- **原请求 UUID：**普通首次传输留空即可；仅在对相同内容进行对应重试时使用。
- **任务状态：**在“任务”页查看、查询和管理任务。需要恢复时选择对应任务，按界面要求补充本地路径，再使用“继续原任务”。

## 八、常见问题

| 现象 | 检查方法 |
| --- | --- |
| 连接不上服务器 | 确认 Mac 已启动本机 TLS 服务；服务器地址是实际 IP，端口是 `4646`；防火墙允许 TCP 4646 入站连接。 |
| 能连接，但不能浏览或传输 | 核对共享名称；服务器共享和配对客户端授权都需要具备对应权限。 |
| 后来才开启上传权限，客户端仍提示无权限 | 除了“保存共享”，还需在“本机共享”中刷新客户端、选择对应客户端，使用同一共享和权限勾选后点击“更新客户端权限”。 |
| 操作失败（4）：现有资料目标或指纹不同，拒绝覆盖信任 | 当前资料别名已绑定不同的目标或指纹；首次配对失败也可能留下资料。按下文“资料冲突的处理”核对旧资料，或使用新别名和新配对文件重新配对。 |
| 操作失败（4）：私有状态所有者或继承策略不安全 | 客户端检查配对文件目录或状态目录时发现所有者、继承设置不符合要求。先按[Windows配对权限错误处理](Windows配对权限错误处理.md)导入 JSON 并选择新路径；仍失败时核对实际状态目录。 |
| 配对失败 | 核对完整指纹、服务器地址及 JSON 文件；凭据过期时重新颁发；提示文件权限不安全时，将凭据保存在仅当前账户可访问的目录并限制文件访问权限。 |
| 下载按钮不可用 | 先选择一个实际存在的本地保存目录。 |
| 点击目录后列表没有变化 | 点击条目只更新相对路径，还需要再次点击“浏览”。 |
| 上传提示目标路径错误 | 确认相对路径指向共享内已有目录；上传到根目录时将相对路径留空。 |

### 资料冲突的处理

出现“操作失败（4）：现有资料目标或指纹不同，拒绝覆盖信任”时，客户端正在保护原来保存的服务器资料。这一步在连接服务器之前执行，Mac 端此时可能没有任何提示。重复点击配对、重启软件或仅换一个 JSON 配对文件，无法解决同一别名下的地址或指纹冲突。

先查看原来保存的资料：保持当前别名，展开“服务器证书变更 / 资料指纹迁移”，点击“读取当前资料指纹”。窗口底部会显示原资料的目标地址、端口和指纹，可与本次输入及 Mac“读取身份”显示的指纹核对。

如果正在首次配置、之前填错过地址或指纹，或者现在连接的是另一台服务器，可以重新配对：

1. 在 Windows“连接与文件”页顶部，将资料别名改成一个未使用过的名称，例如 `mac-office-20261111`。这里修改的是默认显示 `default` 的输入框，**共享名称 `docs` 不需要因此改变**。
2. 在 Mac“本机共享”页，确认所需共享和权限，点击“颁发本共享的配对文件”，将新生成的 JSON 文件复制到 Windows。新资料会使用新的客户端身份；旧文件若已被其他身份使用，不能直接复用。
3. 在 Windows 展开首次配对设置，填写 Mac 的实际 IP 和端口，核对并填入 Mac 当前显示的完整 64 位指纹，选择新复制的 JSON 文件。
4. 点击“配对并保存资料”。成功后，后续连接、浏览和传输均使用这个新资料别名。

新资料保留原资料文件，但不会继承原客户端身份、授权和未完成任务。如果需要继续原任务，应先核对原资料：输入有误时恢复原地址和指纹；若原服务器仅正常续期了证书，并且地址、服务器身份和客户端授权保持不变，使用“服务器证书变更 / 资料指纹迁移”，读取旧指纹、填写核对过的新旧指纹、勾选核对确认后，点击“验证并更新资料指纹”。详见[证书续期与指纹迁移](decisions/0015-证书续期与显式信任迁移.md)。
