# 历史数据库私有根迁移

更新日期：2026-11-09。R152正在验收；安全迁移不代表历史/缓存合计256MiB磁盘预算或全生产写前总配额已完成。

GUI的history.sqlite和固定名称的接收明细receipts.sqlite改用状态父目录下的私有history/根。根进入既有StateSession预算域关联，共享资格覆盖实际数据库连接寿命；根维护不能跨过活动连接。CLI、GUI和旧历史记录中的receipts路径均定位到同一个新库。其他显式Catalog文件名保持原调用语义。诊断仍报告原状态父目录。

旧主库永不自动删除或覆盖。存在旧主库时先只读打开固定SQLite引擎，开启显式读事务并实际读schema以取得共享数据库锁；仅接受无journal/WAL/shm、回滚模式、普通单链接、大小至多256MiB且quick_check通过的对象。固定父目录与SQLite真实原生句柄身份相互核验。源读取直接复用SQLite自己持有的VFS文件，POSIX不会为校验另开再关闭同inode描述符而破坏fcntl锁。源缓存目标1MiB及临时64KiB先取得共用控制授信，复制/散列每次256KiB另外授信，连接关闭后才归还。

私有来源凭据固定版本、根身份、库名、源原生对象、字节数与SHA-256。先持久写prepared，再独占流式发布正文，独立核验目标摘要后原子写complete。准备后无正文则重做同源复制；正文已经发布则只核验已发布内容，符合原凭据才能完成。未知目标、损坏标记、源或目标变化均保留并拒绝，不能靠重新初始化掩盖。正常新库使用时不再要求目标与最初快照相同；它可以继续记录新历史。

新进程整个数据库寿命继续持有旧源读事务。多个新连接可并存，关闭其中一个不解除另一个的旧源锁；旧回滚数据库提交被阻止。最后新连接关闭后旧程序可能再次修改原库，下次打开将因源摘要变化拒绝自动接管，要求核对两个库。首次没有旧源的记录也会拒绝后来出现的旧源，防止静默分叉。此协议协调SQLite参与者，不声称阻止任意外部程序直接改写文件。

新主库的路径核验在POSIX仅通过固定目录属性读取，不额外开关主库文件；实际SQLite打开后再与自身持有的原生句柄比对。Windows保持私有所有者/DACL及普通单链接检查。迁移后新库与旧备份可能同时占用磁盘；当前没有把两者和全部SQLite旁路接入统一写前配额，globalQuotaEnforced仍为false。

本机首轮实际通过两种库的原件保持、多连接旧源锁、源变化拒绝、旁路/损坏源拒绝、准备后和发布后真实进程退出重入；修正路径校验后又通过新主库写事务期间重复核验不释放锁。生产Controller专项验证旧Unicode文本与批次路径在两次重启后仍可打开，原两库摘要保持。完整双Windows和POSIX结果将按精确源码另记，首轮/后续原件保存在docs/validation/2026-11-09/history-state-r152/。

R153补充旧活动接收边界：receipts.sqlite迁移在源读事务内观察旧.admission.lock与.locks目录；任何活动、遗留或未知锁项均保留并拒绝，不按PID或年龄删除，也不在新库误报旧任务已中断。空锁目录可迁移，源摘要保持。跨平台专项结果另按精确源码取证。
