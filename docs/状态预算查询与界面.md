# 状态预算查询与界面

更新日期：2026-11-08。R130将已有持久账本报告接入GUI和CLI；生产写前总额限制、全部目录计量和自动回收继续实施。

在“服务器 → 本机共享”中展开“状态存储预算”，点击“刷新预算”。查询使用当前页面显示的本机状态目录；GUI和CLI指定同一目录时读取同一持久域。只查询已有协调根，不创建域、服务身份、客户端资料或业务根。域不存在、损坏、身份改变或无法取得有界账本锁时明确失败，并清空上一次报告；传输及监听可以继续持有共享资格。

界面显示查询时的总额度、已登记占用、未决预留、剩余额度和超额量，并分别展示历史、元数据、临时正文、未知占用四个类别。后续传输会改变账本，刷新才能取得新的快照。数值保持64位十进制字符串，界面不通过JavaScript浮点数转换字节数。

命令行保留三平台相同入口：

```text
dukto-cli state budget show --state-directory <状态父目录>
dukto-cli state budget show --state-directory <状态父目录> --json
```

`state budget init|set`和`state root bind|show|account`继续使用相同固定四类报告。JSON版本仍为1，保留原字段，增加以下字段：

| 字段 | 含义 |
| --- | --- |
| `available` | 在已登记范围内剩余的账本额度；任一类别透支时为0。类别中的数值还受总额剩余约束 |
| `deficit` | 已登记占用加未决预留超出相应额度的字节数，下限0；总额和各类别分别计算 |
| `capacityState` | 总额为`available`、`total-exhausted`或`overdrawn`；类别还可能为`category-exhausted`或`domain-overdrawn` |
| `wholeDomainAccounted` | 当前为false，不能据此把账本合计当作全部目录的实际用量 |
| `reclaimableKnown` / `reclaimableBytes` | 当前为false/null，可回收量尚未确定，不能当作0或可立即使用的额度 |

`committed`可能包括保守高水位，`reserved`是持久的未决授信。它们不是当前文件逻辑长度与原生分配量的两列直接合计；两者的区别和单根观察范围见[已有状态占用计量](已有状态占用计量.md)。`available`也不是文件系统剩余空间，不会自动删除文件或启用生产配额。`productionQuotaEnforced=false`继续如实输出。

查询持有共享生命周期资格，账本读取只短暂持有原生互斥，不等待网络或SQLite。和原账本打开契约一致：如果存在完整、有效的写前恢复意图，打开可能向前重放；健康账本的查询不改变原字节或修订，损坏意图不会被查询重置。输出不含文件正文、令牌、文件路径或逐项原生身份。

验收包括真实持久未决额度达到有符号64位上限、最大无符号修订的无损序列化、类别/总额分别超额、GUI/CLI报告一致、共享占用下查询、缺失查询不初始化、损坏后清空旧快照，以及360×560和430×700下的真实QML按钮操作和截图。各平台结果按[本轮证据索引](ci-verification-20261108-r130.json)登记；未完成的平台不从本机结果推定通过。
