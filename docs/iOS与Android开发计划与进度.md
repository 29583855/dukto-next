## 1. 目标与完成口径

实现 Dukto Next 的 Android 手机/平板和 iPhone/iPad 版本。保留桌面版的配色、设备卡片、收发流程、服务器页面、任务及历史等使用习惯，并针对触屏、窄屏、横屏、安全区和系统返回行为调整布局。移动端继续与现有桌面端和支持原协议的 Dukto 客户端互通。

功能对齐以本项目桌面版为基准，包括局域网、服务器客户端、本机共享、任务管理和安全诊断；局域网 R6 模式与 Next 服务器模式分别验收。原版协议本身不具备的断点恢复、多通道或认证能力，不因换成移动端而承诺可用。

“完成”必须同时满足：可复现编译、依赖完整、对应安装包可以在目标真机安装启动、功能矩阵通过、传输内容核验一致、桌面回归通过、使用文档及发行说明齐全。源码存在、上游声称测试通过、CI 绿色、模拟器启动及真机完整验收分别记录，不能互相代替。

iOS 后台持续监听和任意时长后台传输受系统限制。该项不得标为与桌面完全相同：产品目标为前台功能对齐，并实现后台收尾、状态保存、回到前台后的恢复/重试和清晰提示。限制必须出现在应用内提示及发布文档中。

### 3.1 先验证工具链，再展开功能

计划建立时尚无Qt5.15移动工具链构建证据。现已取得Android/iOS完整应用编译及开发包验包证据（run45613109226）；真机安装与正式发行要求尚未通过。M0按以下实验逐项验收：

1. 固定 Qt5 补丁版本、CMake、JDK、Android SDK/NDK、Xcode/iOS SDK，以及 OpenSSL/SQLite 的来源和校验值。
2. 构建包含网络、QML、SQL 驱动和加密依赖的最小 Android arm64 应用及 iOS arm64 应用，确认链接和真机启动。
3. 确认 Qt 私有头与运行库匹配、SQL/QML/平台插件完整；iOS 静态插件注册和签名正确。
4. 检查 Android 所有原生 `.so` 的 16 KB 页面兼容及包对齐，不能只检查本项目 `.so`。
5. 区分构建宿主和目标平台：在 macOS 构建 iOS 时，不得继承当前桌面 macOS 的部署目标及打包分支。

Qt6 的 C++17 要求与现有 C++14 约束冲突（见证据中的 Qt 官方源码）。如 Qt5 路线失败，先保留失败日志，评估可维护的 Qt5 补丁或缩小适配面的原生 UI/核心桥接方案；涉及改变 C++ 标准或核心依赖的大范围迁移另行明确，不悄悄升级。

### 3.2 文件、身份与本机共享

- Android 使用 Storage Access Framework 的文档/目录选择与持久授权；iOS 使用文档选择、安全作用域 URL、书签及必要的文件协调。用户授权撤销、提供器离线和云端文件未下载必须能报出可操作原因。
- 不把 `content://` 或文档提供器 URL 强制转成本地绝对路径。对核心需要稳定路径的情况，先使用有大小/空间/数量预算的沙箱暂存，或实现可验证的流/文件描述符适配。
- 源文件复制或流式读取期间需要检查内容是否变化；恢复时重新校验授权、源身份和目标。进度区分传输与最终导出；接收成功必须包括文件提交到约定位置成功。
- 目标提供器不支持核心所需原子替换/重命名时，明示降级或拒绝该冲突策略，保留可恢复状态；不能宣称与本地文件系统完全相同。
- 私钥与认证资料保留在应用私有目录/受支持的系统安全存储中，不能随普通共享目录导出；复核 SQLite VFS、锁及文件权限在沙箱下的语义。
- 手机托管共享只暴露用户选择并授权的范围。后台挂起后停止宣告可服务状态，重回前台重新绑定并刷新设备状态。

### 3.3 发现、端口及生命周期

保留当前默认端口：局域网 TCP/UDP `4644`、头像 TCP `4645`、Next 服务器 TLS TCP `4646`。不为移动端另换默认端口；同设备同端口已有进程占用时给出明确提示。TLS 服务在移动端也按现有配置开放授权端点。

iOS 加入局域网用途说明；按 Apple 要求处理广播/组播所需签名能力和用户授权。需要时申请 `com.apple.developer.networking.multicast`，真机检查签名及实际收发。未取得该能力时，不能把自动发现标为完成。手动 IP 连接仍须处理局域网权限；Bonjour 可另作补充，但不能自动替代原版的广播发现。

Android 按目标 SDK 处理网络及运行时权限。官方文档当前说明：目标 Android 17/API37 及以上需要适配局域网权限；Android16 的早期 opt-in 规则不能当作最终发布实现。按实际发现实现决定 Wi-Fi 组播锁的获取与释放，不长期持锁。

Android 长传输采用适用类型的前台服务、通知及取消操作，处理启动限制、服务超时、进程回收和省电策略；Android15 的 dataSync 时长限制必须覆盖。iOS 只在系统允许的时间内做后台收尾；到期保存状态并停止操作，恢复后检查重试/续传条件，不使用伪装音频等方式维持后台。

### 6.2 正常与异常用例

- 文件样本：空文件、1字节、文本/二进制、中文及 emoji、多层目录、同名文件、大量小文件、超过4 GiB文件。源/目标计算 SHA-256；目录比较相对路径、大小和内容，避免只核验总字节数。
- 网络：首次授权/拒绝/后续启用；同网段 Wi-Fi；广播被拦截的手动连接；AP 隔离；VPN/多网卡；断网、Wi-Fi 切换及目标掉线；端口冲突。跨网段不承诺广播可达。
- 存储：目录授权撤销、外部提供器不可用、只读目的地、空间不足、暂存超预算、覆盖失败、源变化、危险路径、符号链接和权限越界；最终提交失败不得显示“接收成功”。
- 任务：1/2/4/8/16通道；排队/取消/暂停/继续；网络中断、进程重启后的恢复；R6 与 Next 能力提示；重启后未被授权的文档不能悄悄继续读写。
- 认证：过期或用过的配对文件、错误指纹、名称误填、被撤销身份、证书轮换；日志不得泄漏私钥、配对令牌和认证内容。
- 生命周期：前台/后台/锁屏/系统终止/再次启动；iOS 后台到期；Android 服务超时与省电；权限在应用外被更改；所有结果以真机实测记录。

### 6.3 资源、自动化与回归

持续采样进程内存、缓存/暂存占用、文件描述符、任务/日志条数；重复打开页面、取消文件选择、建立/销毁任务及辅助功能激活，检查既有 GUI 内存增长问题没有移植到手机。至少记录30分钟空闲与实际大文件场景、2小时混合压力；长期24小时资格单列，不由短时通过替代。数值阈值在 M0/M1 按基线和设备能力冻结，不能测试完再随意放宽。

Android 至少两台不同厂商/系统版本 arm64 真机，覆盖常规及16 KB环境；iOS 至少一台 iPhone 和一台 iPad 真机，覆盖最低目标系统及当前系统。模拟器不能替代发现权限、后台策略、签名和系统文件提供器的真机验收。没有设备或证书时记录为未验证，不填“通过”。

核心单元/集成测试按平台可运行范围迁移；依赖桌面进程/终端或宿主文件权限的测试分别标记并建立移动替代测试。三类桌面既有核心与 GUI 检查继续执行；不能只看移动流水线通过。

Android 的原生依赖随包提供，不沿用 Windows 的“复制 DLL 到运行目录”方式。iOS 签名覆盖应用和适用依赖；未签名 archive/模拟器 `.app` 不等于客户能安装的 IPA。签名密钥、证书私钥、配置令牌不提交仓库；按 GitHub secrets/受控签名环境处理。

开发前期允许 CI 生成明确标注的未签名诊断产物，但正式交付需要有效签名和对应安装路径。Apple 开发者账号/证书、广播能力及分发配置尚未核实；尚未把它们当作已经具备。App Store 当前 SDK 要求与最低运行系统是两项不同配置，见第8节。

正式交付目录在发行阶段创建：`release/mobile/<版本>/android/`、`ios/`、`checksums/`、`licenses/`、`evidence/`。本轮已把验包通过的真实开发产物放在`DuktoNextMobile/release/development/android/`与`ios/`，含摘要、声明及说明；不作为正式发行。

配套文档包括：移动端快速开始、桌面/手机互传、服务器配对与上传下载、手机共享服务、权限与后台限制、故障排查、编译签名及发行说明。界面仍以现有桌面版为视觉参考，文档中使用实际运行截图。
