# 长期服务定时维护

更新日期：2026-11-09。R144实现生产GUI/CLI的空闲服务后台维护；全局写前配额、历史/缓存元数据回收和Q07整体仍继续实施。

GUI和CLI的TLS监听器使用显式状态父目录与`service`成员构造。启动时按原生产会话登记并验证状态根，固定根的原生身份，同时在监听器整个寿命保留预算域的共享资格。因此空闲监听仍不能被预算配置维护穿过；成员目录的共享占用改为每个实际工作连接持有，使空闲时可以取得成员的独占维护资格。原始目录构造入口供底层使用，不从目录名称猜测预算域，也不自动启用定时维护。

每60秒只尝试调度一批后台维护；监听尚未成功、有活动连接或已有维护时立即让出。磁盘枚举、SQLite和删除都在一个有界工作线程运行，复用既有`cleanupState`的保留期、分页、强身份、删除意图及确认协议。独占成员资格不等待，其他进程正在使用时保持数据并等待下一轮。取得独占后再次核对原根身份，同名新目录不能接管旧监听器的删除资格。

新连接优先：监听线程先请求取消后台维护，再启动TLS工作线程。维护在原有检查点让出；连接在TLS握手后短暂等待成员资格（最多连接超时与5秒的较小者），继续核对原根身份后才能认证。工作连接或公开信息查询发现目录换代即拒绝，不加载新目录的授权资料。关闭监听先取消并等待维护、再取消并等待全部连接；对象析构后才释放预算域资格。涉及外部文件系统调用时不声称硬实时保证。

维护报告仅保留既有有界汇总，调度失败只公开错误码与阶段。取消/其他使用者占用报告`state-cleanup-deferred`；损坏、权限或换代报告`state-cleanup-error`，保持原现场。正常报告为`state-cleanup`。每次保留一个维护槽，不积累后台任务。

本机新增测试实际使用生产定时器、原生共享/独占锁、真实未完成TLS连接、已发布文件及未完成接收正文：验证共享期间让出、空闲后清理、原文件/请求身份/未知项保留、同名目录换代拒绝、停止后归还成员和析构后归还域资格。完整核心和跨平台验收按各自终态另记，不以此文档宣称通过。

此功能仅补齐长期TLS服务空闲维护接线，不清除幂等请求记录，不完成统一256MiB历史预算，不覆盖所有生产写入的磁盘额度。`globalQuotaEnforced=false`、`deliveryComplete=false`、`releaseQualified=false`。
