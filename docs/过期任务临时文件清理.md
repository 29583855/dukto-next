# 过期任务临时文件清理

更新日期：2026-11-07（R111）。

R108增加本机服务器上传任务的清理入口。它回收接收日志中已经记录原生文件身份的未完成临时正文；任务、原请求ID、强清单、逐项处置和接收日志继续保留。客户端重复使用原请求ID仍得到原来的终止任务，不会因清理而创建第二份传输。

先停止使用这个服务器状态目录的GUI、CLI和服务进程，再执行本机维护。普通使用者持有共享锁，清理持有独占锁；有占用时立即拒绝，不等待或抢占活动任务。旧版程序、外部数据库编辑器和跨机器网络目录不在此锁的保护范围。

```text
dukto-cli serve cleanup preview --state-directory <状态父目录> --client <客户端UUID> --task <任务UUID> --json
dukto-cli serve cleanup preview --state-directory <状态父目录> --client <客户端UUID> --task <任务UUID> --after <上一页after> --json
dukto-cli serve cleanup run --state-directory <状态父目录> --client <客户端UUID> --task <任务UUID> --json
```

这里使用`<状态父目录>/service`中的服务器记录，不需要远端IP或网络连接。必须明确指定一个客户端和一个任务，不能传入任意文件路径。`preview`每页最多100个接收文件/目录条目（R110起按同一清单ID混合分页），`more`及`after`供继续翻页；`run`处理整个指定任务，不接受分页参数，不把全部条目积累在内存中。`--json`提供条目行动、是否过期和已清理文件数；标准输出按UTF-8 JSONL编码。

暂停或中断任务默认保留7天；失败或取消任务保留30天。时间按任务数据库中的UTC更新时间计算。未到期、活动、完成或提交中的任务不允许执行清理。预览不会终止任务或删除正文；第一次打开旧任务库可能执行正常架构升级。

执行先在FULL同步事务中持久保存过期凭据，再将暂停/中断任务置为失败，随后逐文件FULL提交删除意图。只有随机`.dukto-UUID.part`名称、冻结清单条目、映射父目录、接收根原生身份和临时文件原生身份全部匹配时才删除。删除后再次FULL确认；进程在删除与确认之间退出，可以用同一命令续做。已经确认删除后出现的同名新文件会保留。

用户源文件、已发布最终文件/目录、复用目录及没有已记录身份的创建中临时项均保留。R110允许清理有完整身份和意图的未发布空临时目录，见下节；普通文件存在提交结果不确定记录时仍拒绝，必须先按原任务恢复核验，不能推定为垃圾。身份被替换、数据库损坏、锁冲突或删除失败均明确报错，现有证据保留。

SQLite旁路文件先验证私有权限和大小，接收库及其旁路合计受单库预算约束。支持由SQLite自己恢复DELETE模式回滚日志；不直接删除`-journal`、`-wal`或`-shm`，遇WAL模式接收库拒绝维护。任务库升级至版本三，版本一/二记录及幂等参数保持；旧版本程序不支持降级打开新任务库。

## 客户端未完成下载正文清理（R109）

R109增加客户端本机维护入口。先退出使用同一客户端状态目录的 GUI、CLI 和后台服务，再预览或执行。维护模式取得状态目录独占锁，并要求任务接收日志没有活动接收者；冲突时立即拒绝。命令作用于`<状态父目录>/transfers`，默认状态父目录为 Qt 的`AppLocalDataLocation`。

```text
dukto-cli client cleanup preview --state-directory <客户端状态父目录> --task <任务UUID> --json
dukto-cli client cleanup preview --state-directory <客户端状态父目录> --task <任务UUID> --after <上一页after> --json
dukto-cli client cleanup run --state-directory <客户端状态父目录> --task <任务UUID> --json
```

`preview`每页最多列出100个文件/目录（R110起）；`run`逐条删除已记录原生身份、且任务绑定和强清单均匹配的未完成下载临时正文，随后清除该文件的块检查点并将文件恢复为`planned`，同一任务可从头重新下载。操作不连接服务器、不变更任务ID或请求幂等记录。重复运行可处理进程在删除正文后、SQLite事务提交前退出的情况；SQLite使用FULL同步。

已完成文件/目录、复用目录、任务历史及清单均保留，不释放任务数量上限。R111允许在`skip_final`持久决定完整证明同一目录、临时项原生身份及冻结清单映射时，协调清理其未发布空临时目录；原skip最终清理位与目录清理位在同一个FULL事务中确认。无最终skip决定、创建身份未知的项仍保留。状态或文件身份不匹配、数据库证据无效、活动锁、SQLite旁路预算超限或其他删除错误会停止并报告错误。R110仅扩展下述可验证空临时目录；入口仍不清理通用缓存或全局过期任务，也不实现总磁盘预算；这些仍是独立工作。

这两种清理入口尚不承担全局自动回收、未知身份临时项回收、元数据删除或总磁盘配额。历史256MiB、活动清单总预算及SQLite所有旁路的全局计量仍是计划中的独立验收项。保留元数据意味着任务数量上限不会通过本命令释放。

服务器端实现见[过期清理核心](../src/core/expiredtaskcleanup.cpp)、[任务过期事务](../src/core/taskstore.cpp)及[原生测试](../tests/expired_task_cleanup_tests.cpp)；客户端实现见[下载清理核心](../src/core/clientdownloadcleanup.cpp)及[客户端清理测试](../tests/client_download_cleanup_tests.cpp)。完整交付状态以[计划](../开发计划与进度.md)为准。

## 未发布空临时目录（R110）

已有两套`preview|run`命令自动包含目录，不增加操作参数。预览条目增加`kind: file|directory`；`after`是两种条目共用的强清单ID。JSON增加`cleanedDirectories`、`preservedDirectories`；服务器已确认清理项按幂等结果计入cleaned，同名新目录不会被再次删除。`run`不积累全部条目数组。

仅处理日志为`committing`、已记录原生身份、随机`.dukto-UUID.dir`名/映射/冻结强清单全部一致的目录。父目录须为原接收器已完成预约且实际身份匹配，顶层核对原接收根；实际查询和删除使用的固定父句柄再次核对该身份。仅系统空目录删除，不递归；目录中出现外部文件即拒绝，保存意图及内容。

删除前FULL提交绑定ID、临时名、目标名、原生身份、原spec SHA及维护模式的意图；删除后FULL确认。客户端同一事务将预约复位planned/清空native并移除意图，支持原任务重新创建目录；服务器保留cleaned确认，重跑只报告原结果。删除前/后进程退出可重入；事务中取消回滚后同样恢复。

临时名消失但最终目标具有相同原生身份时返回`preserved-published`。两者均缺失且没有持久删除意图时明确拒绝未知提交结果；不能推定已经清理。已完成/复用目录和没有身份的创建中项继续保留。R111对skip目录复用完整`skip_final`证明；目录删除后，最终skip和目录意图的清理确认原子提交，允许删除后取消/崩溃重入，缺少对应决定时仍保留。替换父目录、链接/junction/reparse、非目录对象、损坏意图或WAL均拒绝；SQLite确认标志使用完整64位整数核对，不能截断超范围值为0/1。POSIX原生API不提供对任意外部改名的文件系统CAS，不能将本机维护锁宣称为外部进程锁。

R111 Windows UCRT/Qt5.15.19及MSVC/Qt5.15.2的四项清理/skip专项已通过，覆盖真实客户端与服务器skip冲突、接收器/维护器分别删除后的中断恢复及确认事务整体回滚。[本机原件](validation/2026-11-07/skip-directory-r111-local/receipt.json)、[四原生核心原件](validation/2026-11-07/skip-directory-r111-native-core/receipt.json)已核验：各26个CTest、目录专项49条/17个JUnit方法通过；双Mac精确Darwin XFAIL和头像负例既有警告保留。完整协议另验。[实现](../src/core/directorycleanup.cpp)、[测试](../tests/directory_cleanup_tests.cpp)。
