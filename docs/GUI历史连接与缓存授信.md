# GUI历史连接与缓存授信

更新日期：2026-11-09。R146已通过双Windows定向回归，精确源码的四原生完整验收继续。

GUI历史连接此前只设置单库cache_size，未取得进程共用页缓存目标授信，也未配置临时页缓存或禁用mmap。固定Qt连接名还可能使同进程第二个控制器替换第一个连接；初始化中途失败时，Qt注册项可能遗留。

每个控制器现在由独立RAII对象持有数据库和随机Qt注册名。在打开之前，先从共用控制类别取得2112KiB：主库2048KiB、临时库64KiB。实际配置并回读main.cache_size=-2048、temp.cache_size=-64、temp_store=FILE和mmap_size=0。总额或控制预算不足时在开库前拒绝；释放额度后允许重新构造。

正常销毁、历史库损坏、打开/架构初始化失败，以及控制器后续构造失败，均在查询退出后关闭数据库、归零QSqlDatabase引用并移除唯一注册项，最后释放缓存授信。两个活跃控制器互不替换；销毁其中一个后另一个仍可查询原库。

专项实际打开两个生产Controller，验证合计授信和各数据库配置；以真实坏历史文件验证错误后原字节保持、Qt连接及当前额度归还；将共用额度占满验证未创建新库，释放后同位置重试成功。双Windows各Controller 17条实际数据行、生产QML 15条通过，MSVC使用系统PATH。首轮测试错误地要求历史峰值回退，其失败原件保留；后续只比较当前used/dataUsed/controlUsed，未改变生产预算逻辑。

SQLite cache_size是页缓存目标，不能证明SQLite分配器总堆上限；本项也不实现历史文件迁移、历史/接收明细合计256MiB磁盘预算或生产写前总配额。原历史位置、模式、保留期和业务记录语义继续按现有逻辑。
