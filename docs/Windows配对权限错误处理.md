# Windows 客户端配对权限错误处理

更新日期：2026-11-11。

适用场景：Windows 客户端首次配对时提示“操作失败（4）：私有状态所有者或继承策略不安全”。本次用户环境为 Windows Server 2012 服务端、Windows 11 客户端；下面的工具在 **Windows 11 客户端** 上运行。

## 原因

客户端在读取配对 JSON 之前，会检查该文件所在目录和文件的权限。Windows 上要求目录属于当前账户、关闭权限继承，并且只允许当前账户访问。普通下载目录或桌面目录经常保留继承权限，复制过来的 JSON 文件也可能带有其他账户的访问权限，因此会被拒绝。

此错误发生在本地权限检查阶段，尚未建立服务器 TLS 连接。它本身不能证明服务端系统不兼容、端口被防火墙拦截，或证书错误。当前资料名称问题解决后，才执行到了这一步检查。

导入工具会把选定的配对 JSON 复制到 `%LOCALAPPDATA%\DuktoNext-Pairing-随机名称\pairing.json`，并在创建目录、文件时就设置当前账户专有权限。原文件、原目录权限以及现有客户端资料保持原样；凭据正文不会显示在控制台。

## 处理步骤

1. 在服务端确认“本机共享”中共享 `docs` 已保存，并按需要勾选“浏览”“下载”“上传”。服务按钮显示“停止本机服务”表示已经启动，不需要为了本次错误重新建立身份或续期证书。
2. 准备从服务端复制过来的配对 JSON 文件。文件已过期或被其他客户端身份使用时，先在服务端重新点击“颁发本共享的配对文件”。
3. 将工具包完整解压到 Windows 11 客户端，以运行 Dukto Next 的同一个 Windows 账户，双击 `import-pairing.cmd`。
4. 在弹出的文件选择窗口中，选择从服务端复制过来的 JSON 文件。
5. 出现“导入完成”后，复制窗口最后显示的新路径，或保留窗口以便查看。新路径以 `pairing.json` 结尾。
6. 回到 Dukto Next 的“连接与文件”页，保持当前新资料别名，例如 `default-1111`；地址和完整指纹也保持与服务端一致。在“配对文件路径”中粘贴新路径，或点击“选择”找到新文件。
7. 点击“配对并保存资料”。成功后使用同一别名点击“连接”，再进行浏览、上传和下载。

只修改文件所在位置，不修改服务器地址或指纹时，可以继续使用刚才的资料别名。这里的导入工具不会自动替你配对或联系服务器。

## 在项目目录中直接运行

也可以在 Windows 11 上打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File "E:\project\dukto\scripts\import-pairing-windows.ps1"
```

项目放在其他路径时，替换命令中的脚本路径。此命令只对本次脚本进程设置执行策略，不修改系统的持久执行策略。脚本支持 Windows PowerShell 5.1 和 PowerShell 7。

需要指定文件时可以使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\project\dukto\scripts\import-pairing-windows.ps1" -CredentialFile "C:\Users\你的用户名\Downloads\pairing-export-实际名称.json"
```

## 配对后的检查

- 若错误变为“凭据无效”或“已过期”，从服务端重新颁发配对文件，再运行导入工具。
- 若错误变为网络连接失败，再检查服务器 TCP 4646、防火墙及公网地址转发。服务端监听地址可保持 `0.0.0.0`，客户端填写实际可达 IP。
- 若出现证书或身份错误，核对完整 64 位指纹和证书内的服务器 IP/主机名。
- 若能配对但不能浏览或上传下载，核对共享和客户端授权两处的对应权限。
- 若导入后仍是同一权限错误，先确认选择的是工具输出的新路径，且客户端与导入工具由同一个 Windows 账户运行；错误也可能来自客户端已有状态目录，需要结合其实际路径继续定位。

### 文件到期与证书名称问题

图形界面颁发的一次性配对文件默认有效期为 **5分钟**，从服务端颁发时开始计算。复制文件、修改文件名或使用导入工具，都不会延长凭据有效期。到期后应重新颁发 `pairing-export-` 开头的JSON并尽快复制、配对，不能使用服务端内部的 `pair-` 开头JSON。

如果权限错误解决后变成“TLS 证书、主机名或握手校验失败”，还要核对实际证书中的IP/主机名。首次按默认 `127.0.0.1` 建立身份后，仅修改“本机共享”顶部的IP输入框，不会更新已有证书。使用公网IP连接时，证书仍可能只包含 `127.0.0.1`。

长期配置应在服务端展开“证书续期”，在“新IP/主机名”中填入客户端实际连接的IP或主机名，核对当前指纹并确认续期，然后停止、重新启动本机服务，使新证书生效。若已有客户端仍使用旧证书名称，续期名称列表应同时保留该旧名称。已经配对的客户端按证书迁移流程核对新旧指纹；尚未配对且绑定旧指纹的资料可使用新别名和新配对文件重新配对。

CLI也支持连接地址与证书名称分别指定：`--to <实际地址>:4646 --server-name <已核对的证书名称>`。此方式仍须校验完整证书指纹与证书名称；保存后的同一资料别名可以在GUI“连接”中使用。

完整操作见[服务器上传下载使用说明](服务器上传下载使用说明.md)。
