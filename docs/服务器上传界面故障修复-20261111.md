# 服务器界面上传文件故障处理

更新日期：2026-11-11。

## 故障原因

在客户Windows 11上操作旧Windows发行版，“服务器·上传/下载”中已能认证连接，但点击“上传文件”、确认选中的文件后，客户端进程崩溃，Windows记录异常0xc0000374。此次失败发生在文件选择窗口关闭阶段，不能据此认为服务端已经收到文件。

文件选择窗口注册了Qt选择模型的销毁回调。Qt删除子对象时，回调使用的派生类集合已经释放，造成内存损坏。修复版在成员仍存活时先解除回调。该选择器也用于局域网发送文件，因此同一修复覆盖这些入口。

## 正常上传步骤

1. 解压修复版完整目录，运行其中的`dukto-gui.exe`，保留随包DLL和子目录。
2. 点击“服务器·上传/下载”，在“连接与文件”页资料名称填写已配对的`server2012-1111`，点击“连接”。无需重新颁发票据或配对。
3. 共享名称填写`docs`；“共享内相对路径”留空，表示上传到该共享的根目录。上传到子目录时填写服务器上已有的共享内目录，不能填写Windows磁盘绝对路径。
4. 向下滚动到“上传文件”，在弹出的文件窗口中选择文件并点“Open/打开”。“上传目录”用于选择整个本地目录。
5. 在“任务”页查看传输状态。完成后回到“连接与文件”，点击“浏览”刷新服务器文件列表；列表不会因为本地选过文件就代表上传成功。
6. 若下载校验，选择列表中的文件，选好本地保存目录，再点击“下载”。

上传时不需要填写“本地保存目录”，该项用于下载。“原请求UUID”通常留空，只有恢复同一内容时才使用原请求。

## 修复版位置

本机`dist/上传文件修复-20261111/`包含Windows-x64、Linux-x64、macOS-Intel及macOS-AppleSilicon四个目录。Windows已解压，可运行`Windows-x64/DuktoNext-windows-x64-preview/dukto-gui.exe`；旁边ZIP用于交付客户，请完整解压并保留DLL。

如果刚点选某个远程文件用于下载，下一次上传前先点击“上级”返回目标目录，或者清空“共享内相对路径”以回到共享根目录。上传目标应是目录。

## 本机独立启动问题

本机原有旧历史数据库与已完成迁移的记录不一致，导致旧版启动时退出。只读核验两份库所有应用表均为空后，已将两库和迁移标记完整保留到`%LOCALAPPDATA%\DuktoNext\HistoryBackup-20261111-upload-test`，核对备份摘要，再重建空历史。配对资料保持可用，默认数据目录连续两次原生启动检查通过。

此项是本机数据恢复，不是通过关闭历史完整性校验修复上传，也不是要求其他用户删除历史库。其他电脑遇到历史启动错误时，应先保留原件并检查，不要直接清空历史。
