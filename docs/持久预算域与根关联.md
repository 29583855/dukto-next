# 持久预算域与状态根关联

更新日期：2026-11-08。实现范围：`StateDomain`负责协调根和显式成员根的持久关联。生产GUI、CLI、服务器的所有状态入口尚未接入，Q01/Q03整体、256MiB历史总额和自动GC仍未完成。

每个域由一个调用方显式选择的私有协调根保存`state-budget.bin`和`state-domain.bin`。不能把用户的普通数据父目录自动收紧为私有目录，也不能因为目录名是`service`、`clients`、`transfers`或`remote`就认领它。GUI历史与`remote`子树、CLI指定状态父目录之间的映射仍需在生产入口统一接入。调用方须保证`PrivateStore`比域对象存活更久。

`StateDomain::initialize`在协调根独占维护时生成域UUID和协调根生命周期UUID。任一控制文件已存在、已有初始化残片、最低控制额度不足时拒绝；不会覆盖旧文件。普通重开从标记发现域，再核对账本，不要求用户手工记住UUID。

`bind`要求目标根独占维护。先在中央账本登记256字节Metadata，再独占新建并同步该根的固定标记。同一个根的重复登记只校验原登记，不重写、不扣第二份额度；不同成员根进入同一域。普通共享使用只能调用`root`打开已有关联。目标根锁先于短时账本锁；标记读取完成后释放其原生锁，再查询账本，不在持有账本锁时执行取消回调。

每次核对都检查域UUID、协调根生命周期、成员生命周期、两端原生目录身份摘要、根键及中央登记代数。原生身份采用当前平台的卷/设备与对象ID，不含目录修改时间，路径点别名因此不会创建第二份登记。复制成员标记、复制整个协调根、跨域重复绑定、标记损坏/截断、中央登记退役或未决、协调标记换代时拒绝使用。持久标记不含用户绝对路径，普通`PrivateStore`接口保留该名称及其大小写变体。

调用方可保留`Binding`，在后续访问前使用`verify(store, binding)`重读两端关联并拒绝过期观察。这个根观察只证明目录关联，不能替代业务文件的原生身份、任务归属、权限和实际占用核对；不构成删除文件的资格。账本4096槽与固定空间上限保持，中央标记占一槽，每个成员标记占一槽，槽耗尽受控拒绝。

## 跨文件中断

中央账本与成员标记位于不同文件、可能位于不同卷，不声称跨文件原子提交。预扣后、创建标记前退出，会留下已计量的孤立登记；标记已创建但写入/同步失败，会留下不完整标记及对应占用。均不自动退款、不按PID认定已释放。下次发现未知或损坏标记时保留并拒绝覆盖；缺失标记的新显式登记使用新生命周期并再次计量，旧孤立登记继续保留，不能让同一份旧额度被复用。

初始化中断同样保留现场，目前没有自动恢复或清除控制文件的命令。已有正确标记但中央登记缺失/退役时，`bind`也会拒绝，不能自动重新登记。尚需实现受证据约束的孤立登记维护，以及故障注入覆盖真实写入/同步失败。已实现的故障测试覆盖预扣后真实子进程直接退出、残片拒绝及旧观察失效。

## 计量范围

账本自身固定1,056,768字节及每份256字节标记计入Metadata逻辑占用；普通退出不退款。根使用锁保持零字节，目录、文件系统分配粒度、日志及文件元数据的实际分配量仍需通过原生观察接入，不能将本接口的逻辑字节合计称为实际物理总占用。跨卷可用空间准入也尚未实现。

根关联底层没有自动接管现有业务写入。目前没有向GUI/CLI产品流程增加额外初始化要求。后续须将SQLite/VFS、私有原子替换、历史库、清单、匿名临时对象、接收正文及未知遗留项统一纳入同一域，并完成实际写前预留/写后对账和有界维护。`usage()`只代表账本已登记范围。

本轮测试使用真实独立进程和四个线程，核对重开、路径别名、多根幂等、跨域/复制拒绝、退役/损坏/截断、中央失效、额度不足写入前拒绝、独占占用和强退恢复、预扣退出保留及新生命周期。Windows、Linux、macOS的构建和执行资格分别按实际原件登记，不能从配置或单平台结果推断全部通过。
