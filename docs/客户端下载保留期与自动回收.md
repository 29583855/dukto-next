# 客户端下载保留期与自动回收

更新日期：2026-11-09。实现下载临时正文的保留期和业务打开前机会式维护；长期服务定时维护、历史元数据回收及全局写前配额仍继续实施。

`RemoteClient::download` 在 `DurableReceive` 验证任务、清单、目标根和冲突策略后，保存规范编码的 `download-retention-<task>.json`。凭据包含任务、清单摘要、私有根和接收日志的原生身份、UTC活动时间及有界维护游标。传输进度和本地最终校验每分钟最多刷新一次，成功结束时再刷新。时钟后退取原时间与当前时间的较大值。

自动回收至少保留七天，并额外等待一分钟活动采样宽限期。没有保留期凭据的旧任务保持；未来时间、未知版本、非规范编码、错误身份或摘要均不能授予删除资格。凭据不是文件删除授权：执行时仍验证原强清单、接收绑定、目标根、每个临时对象身份和原来的删除/确认协议。已发布文件、提交结果不确定项、跳过策略保留项、未知对象和全部任务请求身份保持。

`StateSession::root` 打开 `transfers` / `remote/transfers` 共享根之前，既有机会式扫描会检查这些凭据；`state gc preview|run` 同样覆盖。维护须取得根独占资格，有活动共享使用者立即让出，不升级已有共享锁。每个下载候选每批最多32个记录，包括保留记录；分页游标持久保存。中途退出可从旧游标重新核对，删除后尚未提交的检查点复用原有幂等恢复。完成维护的凭据不反复扫描正文；再次执行同一下载会刷新活动时间并重置游标。

本功能回收可恢复的未发布正文，清理后同一任务可以从缺失块开始重新下载。它不清除恢复库、清单或有效幂等结果，不以牺牲请求身份腾出元数据空间。扫描/强清单核验仍可受到外部文件系统调用延迟影响，批次时间预算不表示硬实时保证。
