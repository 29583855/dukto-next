# 局域网发现与原版端口说明

更新日期：2026-11-10。

Windows 错误 10048、macOS 错误 48 均表示接收端口已被占用。原版 Dukto 默认使用 TCP/UDP 4644、头像 TCP 4645。同机原版占用 TCP 4644 时，Next 无法监听，旧程序因此不会启动设备发现；用户已确认 Windows 退出原版后恢复。

按用户最新要求，Next 默认继续使用同一组端口，不自动改为备用端口。同机先退出原版或另一实例再运行 Next；端口冲突会显示实际端口及退出占用程序的提示。先前探索的 4648–4678 自动退让方案已取消，未作为本次交付功能。

标准 UDP 4644 仍采用共享广播设置，保留显式自定义端口的 R6 1/2/4/5 公告及原版 `Bye Bye` 退出包兼容。但共享 UDP 不意味着两个程序能同时独占同一 TCP 接收端口。macOS 原版默认 UDP 也可能完全不允许复用。

两端需位于可达的 IPv4 广播网络并允许应用联网。发现使用 UDP 4644，传输使用 TCP 4644，头像使用 TCP 4645。Windows 首次防火墙提示、Mac 防火墙和提供本地网络权限的系统均应允许当前应用；原版已放行不会自动放行 Next。程序不自动修改系统防火墙。

Mac 仍使用最低 12.0 构建目标，按“关于本机”选择 Intel 或 Apple Silicon；安装说明见[macOS12兼容说明](macOS12兼容说明.md)。

本次 Windows → Mac 发送失败截图明确显示代理类型不支持，与前述端口占用为两个问题。原因、修复和实测范围见[局域网发送代理问题说明](局域网发送代理问题说明.md)。
