# 本地诊断与 JSON 导出

更新日期：2026-11-07。以下入口属于 R103 源码；当前 R100 含依赖预览包不包含新增导出功能。各平台实际验证结果以主计划及对应回执为准。

在设置页点击“导出本地诊断”，选择一个尚不存在的 JSON 文件。报告包含程序和运行库版本、配置格式检查、数据目录和接收目录的写入检查、当前实例的监听状态。报告只保存到本地，不自动上传。

Windows、macOS、Linux 使用相同命令。Windows 可以使用 `dukto-cli.exe`，macOS/Linux 可以使用当前目录的 `./dukto-cli`。

```text
dukto-cli doctor --json
dukto-cli doctor --output "已有接收目录" --state-directory "已有状态目录" --report "新报告.json" --json
dukto-cli doctor --config-file "settings.ini" --bind 127.0.0.1 --port 4644 --report "端口检查.json" --json
dukto-cli doctor --state-directory "已有客户端状态目录" --profile default --timeout 5 --report "对端检查.json" --json
```

`--config-file` 指定存在的 INI 文件。诊断在 Qt 解析之前从普通文件有界读取，最大 64 KiB；检查已知的端口、超时、监听地址和接收目录键。不会把任意配置键和值写入报告。系统原生设置使用平台设置接口检查已知键。

目录检查在所选已有目录内创建一个唯一临时文件，写入固定短探针，刷新、同步并清理。不会创建缺失的目录，也不会遍历用户文件。显式指定而不存在的目录返回失败；未建立的默认目录标记为 `not-created`。配置里单独保存的接收目录也会检查。

只有显式提供 `--bind` 或 `--port` 才执行 CLI 的 TCP 绑定探测，完成后立即关闭。GUI 已监听时报告 `active-in-this-instance`。检查不代表 UDP 发现、网络可达性、防火墙规则或系统端口独占的完整资格。已有程序占用相同地址和端口时，CLI 诊断会返回网络错误。

只有显式提供 `--profile` 才连接对端。该检查加载已有配对资料，核验 TLS 身份并认证，再返回实际协商的已知能力布尔值。不会新建配对、修改证书信任、扫描共享文件或创建传输任务。使用 `--to` 临时指定其他地址会被拒绝。撤销、证书变化或资料轮换尚待确认时，需要先处理对应问题。

报告采用 `eventVersion: 1`、`event: doctor`、`reportVersion: 1`。`checks` 内每项有固定 ID、状态、错误码和处理建议；`peer.status` 区分 `not-requested`、`passed` 和 `failed`。`passed` 只表示实际请求的项目通过；未执行的检查保持明确状态。JSON 最大 64 KiB，采用同目录临时写入和原子提交，已有目标会被拒绝，不会覆盖。

退出码沿用 CLI 契约：0 表示请求的检查通过，2 表示配置或参数错误，3 表示网络/端口错误，4 表示访问或身份校验失败，5 表示磁盘或目录写入失败，7 表示取消。多个检查失败时保留所有检查结果，进程采用首个失败的退出码。

此入口不导出访问令牌、私钥、配置值、文件正文或历史任务数据库。完整分阶段日志、所有资源预算、原生保存选择器的三平台实际交互及整个 R10 仍分别验收，不以本地诊断子项代替。
