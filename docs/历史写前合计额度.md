# 历史写前合计额度

更新日期：2026-11-09。R156实施中；测试结果见主计划及独立原件。客户当前已验包仍为R153，本项不自动授予新包或完整配额资格。

GUI `history.sqlite`与固定接收明细`receipts.sqlite`共用持久预算域的History类别，默认256MiB，并同时受域总额限制。生产两个连接均安装固定SQLite驱动的独立策略；策略寿命持续持有历史根及中央共享资格，活动连接存在时不能修改额度或独占维护。显式其他名称的Catalog保留其原有语义，不因此受到历史策略约束。

命名对象按固定角色建立写前高水位包络：两份主库、各自journal/WAL/shm及迁移说明。根登记代数和固定角色生成键，同一角色跨进程只保留一份最高额度。增加先在中央账本内原子检查/同步；锁释放后才执行实际SQLite I/O或迁移复制。额度不足返回SQLite FULL，原生对应写入尚未调用；迁移失败保留旧源、原迁移凭据和已有目标。

包络以64KiB向上取整，最小64KiB；说明原子替换预留新旧两份。它属于保守授信，不是实际占用或可回收量。删库、缩小、回滚和重开均不减少命名包络，避免依靠inode复用、文件名或进程退出推定释放。数据库打开前同时计入两个已存在主库及已存在旁路；原生回调继续观察实际逻辑/分配量，发现超出包络时补充授信，失败保留现场并停止初始化。

匿名SQLite临时对象使用全域固定32槽池，连接内最多64个打开句柄。临时对象在open之前取得持久未决预留；增长通过同一执行者/操作的修订扩展，额度不足不改变旧预留。只有原生delete-on-close成功才结算为零，正常关闭后可再次使用该槽。直接退出、关闭失败、观察失败或第二次预算加锁失败均保留预留；不会按PID消失自动清除。遗留预留的独占原生核对/退款工具仍待接入，槽耗尽受控拒绝。

SQLite引擎锁→短预算锁遵循既有方向；预算锁内不执行SQL、目录枚举、正文写入或网络等待。策略每个SQLite连接独立创建，句柄编号不在独立VFS之间共享。命名包络的本连接缓存只允许省略已有上界内的重复授信，不能减少账本；中央维护资格阻止活动期间降低额度。
