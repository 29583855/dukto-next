# 持久预算账本底层

更新日期：2026-11-08。R122实现固定格式账本与原生互斥底层。生产业务尚未调用它；跨状态根归属、SQLite/VFS、原子替换、正文写入和自动GC继续按实施清单完成。

`StateBudget`在一个受保护的`PrivateStore`根内使用永久`state-budget.bin`。初始化必须取得独占维护资格，以原生独占创建生成；已有或不完整账本保留，不覆盖、不重置。普通状态read/write/remove接口保留这个名称及大小写变体。正常打开必须已有文件，并核对根身份、域UUID、私有权限、普通文件和单链接；复制到另一根会拒绝。

| 格式部分 | 偏移与长度 | 用途 |
| --- | --- | --- |
| 主头及保留区 | 0，4096字节 | 前512字节保存版本、域/根身份、总额与四类别上限、已用/预留和修订；余下字节为零 |
| 写前意图 | 4096，4096字节 | 单槽事务的旧/新头与旧/新槽，修订及校验 |
| 固定记录区 | 8192，4096×256字节 | 活跃、未决、已退役对象；槽满受控拒绝 |
| 文件合计 | 1,056,768字节 | 账本自身计入Metadata；不会按任务数扩张 |

整数使用固定宽度小端编码，每个非空记录保留SHA-256校验和零保留区。它用于损坏检测，不作为防止当前用户恶意修改的密码认证。History、Metadata、Body、Unknown四类别分别有上限，并受总量约束；所有金额在非负有符号64位范围内，溢出拒绝。`maximumCharge`是对象完成单次操作后的绝对占用上界，新增预留为`max(0, maximumCharge-committed)`。

每个对象由调用方提供32字节非零生命周期键，槽内另有登记UUID、对象修订、操作UUID和执行者UUID。登记对同键/同类别/同金额幂等；旧修订、同对象未决操作、不同登记代数均不能重复授信。调用方必须先证明键对应真实对象生命周期；当前底层不会把任意传入键或金额解释为已经证明的业务归属。

`reserve`在返回前持久化未决预留。解锁后才能执行业务I/O，取得原生观察后再`settle`。第二次加锁或观察失败时保留未决额度；异常退出和析构也不退款。另一实例不能冒充原执行者结算，共享使用者不能退役或恢复遗留操作。只有独占维护在取得真实对象证据后才可`reconcile`或对已释放的已结算对象`retire`；PID消失不是释放证据。墓碑和登记代数防止重复退款及槽复用ABA。

真实占用高于预期时，结算仍照实记录透支，拒绝后续新增占用；不增加占用的收缩操作仍可执行。最近一次确切操作的重复结算幂等；新的操作开始后，旧完成通知拒绝。当前接口接收的实际金额仍需未来业务适配器按分配量/逻辑长度策略生成，不能由本轮专项推断完整磁盘配额已生效。

每次单槽提交依次执行：完整意图写入并同步 → 新槽/新头写入并同步 → 意图清零并同步。存在合法意图时只向前重放，头/槽的有效内容必须属于意图的旧或新状态；旧事务不能覆盖后续有效修订。带完整合法意图的数据撕裂可以恢复。意图本身写入或清零发生撕裂时拒绝并保留现场，当前没有自动修复此类损坏的工具；不会将损坏意图当作无预留。

Windows使用不共享删除的固定文件句柄和`LockFileEx`；POSIX使用固定根内`openat`/`O_NOFOLLOW`、0600和`flock`。每实例互斥保护同实例多线程，原生锁协调独立实例与进程。加锁等待支持取消，配置期限0–5000ms；这限制等待锁，不是对文件系统同步延迟的硬期限。取消回调只在尚未持有原生锁时执行。预算锁内不等待网络、业务目录扫描、SQLite锁或用户输入。

单次片段读写最多16KiB，固定格式逐槽审计和查找不建立按对象数增长的列表；每操作计入64KiB应用缓冲授信。初始化先取得状态资格，不通过PrivateStore原子替换或SQLite写账本，避免递归申请预算。锁顺序继续遵守[接入设计](跨进程磁盘预算设计.md)。

专项覆盖两个实际进程争夺最后额度/同对象、直接退出后重开、独占核对、同实例四线程、五种完整意图恢复布局、完成重放、过期意图与撕裂意图拒绝、损坏/错误域/根复制、超32位金额及溢出、4096槽耗尽/复用ABA、真实硬链接拒绝和64轮资源归还。恢复布局是实际文件原件构造的故障夹具，不是物理断电试验；完整业务故障注入和长期资源稳定性继续。

首轮MSVC测试握手错误仅接受LF，实际Windows子进程输出CRLF，导致未处理夹具异常；原日志保留。修正为只接受精确LF或CRLF，分段输出有界等待、启动失败/测试退出回收自有子进程。首轮UCRT构建的QUuid空值赋值歧义也保留，改为显式构造后重新验证。各平台原生结果以独立原件回执为准。
