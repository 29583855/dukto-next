# SQLite原生文件身份与占用观察

更新日期：2026-11-08。R120为磁盘总配额Q02的原生句柄观察基础；双Windows各30完整核心、29份Qt原件及新专项各11条全通过；跨平台验证继续，跨进程预算账本和总配额仍待实施。

预算需要分辨同一文件的不同连接、路径别名和临时对象。R119的连接内序号只用于关联一次打开，不能充当跨进程文件身份。R120通过SQLite实际打开的原生句柄查询对象，不按名称重新打开文件，也不复制正文。

`src/core/sqliteplatform.c`先包含经过CMake摘要核验的原版`sqlite3.c`，再编译本项目的适配函数。上游ZIP、提取文件及Qt驱动保留原字节；编译器直接检查固定版本的`unixFile`/`winFile`类型，适配不猜测私有结构偏移，不把系统QSQLITE插件的句柄交给另一份引擎。

| 字段 | POSIX | Windows |
| --- | --- | --- |
| 原生身份 | `fstat`的设备号、inode | `FileIdInfo`的64位卷序号、128位文件ID |
| 逻辑长度 | `st_size` | `FileStandardInfo.EndOfFile` |
| 系统报告的分配量 | `st_blocks × 512` | `FileStandardInfo.AllocationSize` |
| 链接计数 | `st_nlink`，匿名未关闭对象允许为0 | `FileStandardInfo.NumberOfLinks` |
| WAL共享文件 | 实际共享节点的`hShm` | 实际共享节点的`hSharedShm` |

身份只用于原生对象存续期间的关联，不证明正文不变、永久归属或重启后可安全删除。未来持久预算仍须核对父目录、对象生命周期、活动进程和已有维护凭据；不能只凭inode或PID回收额度。

分配量是文件系统在查询时报告的值，不等同于存储设备最终物理消耗；稀疏、压缩、延迟分配、克隆和共享块须按对应文件系统另行确定保守预算。观察不提供跨多个文件的原子快照，也不约束其他程序直接写入目录。

观察通过包装VFS的`SqliteFileInfoControl`及`SqliteSharedMemoryInfoControl`返回固定大小结构。返回码单独保留；查询失败或不支持不能视为零占用。`kind=0`仅表示本连接没有对应共享文件句柄，不能证明磁盘文件已删除；`kind=2`表示SQLite采用仅内存共享区，不虚构磁盘身份。

POSIX观察直接对已打开描述符执行`fstat`，不另开再关闭数据库描述符，避免意外释放本进程的POSIX数据库锁。共享节点的可变字段在SQLite原生节点互斥内读取，所属连接必须保持有效，不把借用的原生句柄交给调用方关闭。

安装策略时，打开完成、写入、截断、大小提示和共享映射的完成通知会重新观察实际句柄，失败后的潜在部分增长也由实际观察反映。关闭通知保留关闭前的最后观察，`observedAfterCall=false`；不能据此声称关闭后文件消失或自动归还所有占用。未安装策略的正常生产连接不进行逐次属性查询。

共享映射通知的`bytes`按固定平台VFS的实际文件扩展范围计算：POSIX与`unixShmRegionPerMap`使用相同分组，Windows使用实际请求的文件范围；64位乘法及原生`int`范围先检查。`mappedFileBytes`表示共享文件已映射的连续覆盖范围，不是虚拟映射总量或物理分配量。后续预算还需考虑文件系统分配粒度和真实操作结果。

本轮专项覆盖：

- 写入/扩展/缩小前后观察、拒绝写入后的原摘要和长度、关闭前观察语义。
- 两连接与真实硬链接身份合并、等长独立文件区分、匿名临时文件。
- POSIX路径换代后仍观察已打开对象；Windows原生共享规则拒绝路径换代。
- 超过4GiB的真实稀疏文件、逻辑长度与分配量独立核对。
- 实际共享文件身份、系统页分组扩展、解除映射后本连接无句柄与溢出拒绝。
- 生产Qt驱动实际SQL的主库、回滚日志、WAL与排序溢写，以及非法/其他VFS句柄的明确失败。

验收继续以精确源码、原始CTest/Qt报告和平台运行结果为准。当前生产仍未安装总预算策略，`quotaEnforced=false`；本接口通过不授予Q02整体、跨进程账本、自动GC或整体交付资格。
