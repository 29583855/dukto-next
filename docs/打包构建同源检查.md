# 打包构建同源检查

更新日期：2026-11-09。

Windows、Linux 和 macOS 打包器共用 `scripts/package_build.py`。打包前检查 CMake 缓存中的项目名和实际源目录；构建目录属于其他源码时立即拒绝。随后重新配置并清理旧对象，使用 Release 配置编译 GUI 和 CLI。即使源码内容改变后恢复了旧时间戳，也会编译新内容。

打包器记录 CMakeLists.txt、src、ui、resources 和固定 SQLite/Qt 驱动源码的 SHA-256，以及原始 GUI/CLI 程序摘要。编译后与归档前分别复核；输入改变就停止。包内 `package-manifest.json` 的 `buildProvenance` 保存这些数据；`build-refresh.log` 保留实际配置和编译输出。macOS 部署、修改运行库路径和签名仅操作复制到包内的程序。

正常打包命令保持原接口，例如：

```powershell
python scripts/package_windows.py --build-directory build/windows-ucrt --output dist/windows-new
```

```sh
python3 scripts/package_linux.py --build-directory build --output dist/linux-new
python3 scripts/package_macos.py --build-directory build --output dist/macos-new
```

输出目录必须不存在。打包会执行一次干净应用构建，因此需要本机原有编译工具链。CMake 的清理也可能移除同一构建目录中的测试程序；再次执行 CTest 前应先完成全部目标构建。

真实回归使用中文空格路径编译两份 C++14 程序，验证错误源目录、缺失源目录记录、旧时间戳对象、编译后源码变化和程序变化。Windows UCRT 和 Linux 的原始日志位于 `docs/validation/2026-11-09/package-source-r141/`，四平台原生专项由 `package-build-regression.yml` 执行。各平台新包仍须单独完成迁移与业务测试。

该检查防止误用旧构建目录或过期对象。它不授予全局生产配额、完整功能验收、干净系统或正式签名发布资格。
