## 2. R01：暂停和断点续传

适用新版扩展上传、下载及新版对端间文件传输，按能力协商启用。原版 R6 不宣称支持暂停/续传；相关操作应显示可用能力。

1. 暂停是停止发放新块并让已接受的写入完成，释放活动通道与工作缓冲，保留临时文件和有界的磁盘状态；取消明确区分“保留待恢复”与“删除未完成数据”。默认取消删除本任务临时数据，暂停默认保留。
2. 持久状态包含任务 ID、所属身份、对端身份、共享根、源内容标识、目标预约路径、总大小、块大小、已验证块及其摘要、协议版本和更新时间；令牌等短期通道凭据不作为可重用的恢复身份。
3. 发送端为该次任务建立稳定的源内容标识及摘要信息；接收方恢复时重新认证、确认源身份，并复核本地已保存块。仅文件名、大小和修改时间相同不足以认定内容未变化；无法证明一致时拒绝复用旧块，提供重新开始。
4. 数据写入与检查点顺序必须明确。重启后不能直接相信数据库中的“块完成”：按持久化策略确认数据，必要时重读校验；对数据库已记而磁盘未保留的块重新下载，防止系统崩溃后误用脏数据。
5. 续传只请求缺失/损坏块，最终仍做全文件 SHA-256 校验。重新扫描、重新认证和最终校验时间计入恢复耗时；不宣称“立即恢复”或“零额外读取”。
6. 默认仅手动恢复，避免重启后未经用户操作自动大量传输；断网可在当前任务的有限重连预算内恢复。源文件变化、证书变化、无权限和摘要失败不能无限自动重试。
7. GUI 在任务中心提供暂停/继续/重新开始；CLI 提供 `tasks pause`、`tasks resume` 及 `resume --task <ID>`。服务器任务操作需认证，独立本地 CLI 的恢复按本地磁盘记录和目标锁执行，不能同时恢复同一目标。

验收：在 10%、50%、接近完成和最终确认阶段分别断网、结束应用及重启服务；已验证块被复用、错误块被修复、最终哈希一致，且不突破资源预算。源文件改动后必须被识别，原版不支持续传时不伪装成功。

## 3. R02：任务幂等与完成确认

- 创建任务包含稳定的请求 ID。服务端按“认证身份 + 请求 ID”识别重试；相同请求返回同一任务，不新建另一个文件。参数不同却复用请求 ID 应返回冲突。
- 任务状态至少区分扫描、排队、传输、暂停中、已暂停、恢复检查、校验、提交、已完成、取消中、已取消、失败。状态转换和结果写入需可重复处理，不依赖回包恰好收到一次。
- 接收端完成校验和文件提交后记录最终路径、摘要及结果，再发送确认；确认丢失时发送端查询该任务结果，不重新命名复制一份。幂等记录至少保留到对应恢复/结果保留期结束。
- GUI 历史条数上限不能提前删除尚在有效期内的幂等键和最终状态；配额满时先清理已过期记录或拒绝新任务，不能以忘记已提交结果的方式释放空间。
- 服务断开后的“结果未知”不立即变成“文件肯定失败”；GUI/CLI 区分网络失败与已核实的任务结果。无权限查询时不能依据猜测覆盖目标。
- 任何阶段收到 completed（初始重试、就绪恢复、最终确认），均须将任务身份、清单 SHA、总字节、完成字节及条目数与本次冻结强清单逐字段严格比较；错误码须为数值 0、停止请求为空，不允许把 JSON 数值当作规范十进制字符串。下载已完成重试还须重读本地持久清单和实际文件，所有核验完成后才发布 GUI 完成进度。
- 单文件成功和批次完成分别计算；批次存在失败必须返回非成功结果，并列出成功、失败、按策略跳过和未执行项。目录批次不承诺整个目录原子替换。

验收：重复提交创建请求、重复块、重复完成确认及断开发送确认的连接，最终仅有一次文件提交，路径与任务结果稳定。

## 4. R03/R04：文件保护与磁盘资源

| 情况 | 首版明确策略 |
| --- | --- |
| 目标已存在 | 默认自动重命名；支持 `rename / skip / overwrite / fail` 策略，CLI 使用 `--on-conflict`，GUI 对批次统一选择。覆盖必须显式配置，不能默认覆盖 |
| 多任务/进程写同一路径 | 使用任务与目标预约、系统级独占机制防冲突；提交时再次校验，重命名采用唯一名称，不以“先检查存在再写入”替代竞争处理 |
| 文件尚未完成 | 在目标磁盘的临时位置写入，不占用最终文件名；校验通过后执行平台可用的原子重命名/替换。文件系统不支持所需语义时明确失败或采用已验证替代流程 |
| 文件已存在且请求覆盖 | 旧文件保持可用，直到新文件校验并准备提交；中断不能留下被截断的原文件 |
| 磁盘或格式不支持 | 写入前检查空间及单文件大小限制，写入中继续处理配额和空间变化；FAT32 等限制明确报错，不把超限误判为网络问题 |
| 暂停或可恢复任务 | 默认保留 7 天，保存位置和占用可查看；仅清理已过期且不活动的本项目数据，活动任务和用户原文件不在自动清理范围 |
| 任务历史和日志 | 完成历史默认最多 1 万任务/30 天；诊断日志默认总量不超过 50 MiB，超过按轮转策略处理；详细清单分任务存储并按保留期清理 |
| 磁盘元数据 | 历史/缓存元数据初始预算 256 MiB；活动任务清单另受配置的磁盘配额和可用空间限制，SQLite WAL/临时索引同样计量，不能以数据库文件替代无限内存缓存 |

“文件完成”默认表示完整性校验、写入/关闭及文件提交成功；“断电后仍持久”需额外的文件/目录同步及恢复验证，不能把普通 flush 等同于断电保证。恢复会复核磁盘数据，性能报告写明同步策略。批次的空间估算包括临时数据、覆盖时旧文件和元数据，不能按网络压缩量估算空间。

验收：同名、并发写入、配额不足、空间在中途耗尽、临时文件清理和替换阶段中断均不破坏原文件；按配置清理后占用可预测，数据库繁忙不导致无限等待。

## 5. R05/R06/R07：调度、网络与文件范围

- 公平调度按客户端和任务分配全局数据通道/字节配额，排队有上限；单任务申请 16 通道不等于独占服务器。控制/取消请求有独立的小额度，磁盘慢时仍可取消。
- 有限自动重试当前只接受网络错误 3：初始尝试外最多 3 次、250/500/1000ms 退避，多个阶段共用次数及单调总时限；默认 0 次手动恢复。GUI/CLI 共用 --retries 与 --deadline-seconds 的策略，扫描、排队、传输、校验和退避都计时；到期 3/deadline 不重试，用户取消 7 优先。身份、路径、空间及源变化错误直接结束，当前不自动重试磁盘 I/O。原请求/冻结清单/日志保持，详见[契约](decisions/0008-有限重试与任务总时限.md)。
- 首版必须支持 IPv4、主机名解析和可配置端口，多网卡发现去重使用稳定设备身份，不只依赖 IP；在线租约使用单调时钟，设备消失后能过期。
- 明确网卡绑定、VPN/虚拟网卡、DNS 超时、跨网段广播不可达及直连错误。IPv6 直连的支持范围在 P0/P1 固定并实测，未支持时明确反馈；IPv6 自动发现不冒充原版既有能力。
- 必传范围为普通文件、目录结构、空文件及空目录；首版默认不跟随符号链接/重解析点，不读取设备、管道等特殊文件，遗漏项进入批次报告。恢复状态、源扫描和目标检查执行同一规则。
- 保存原始名称与最终名称映射；保留修改时间按目标文件系统能力执行，精度损失写入说明。ACL、所有者、扩展属性、硬链接及跨平台执行权限不做隐含的完整备份承诺，特殊元数据策略在 P0 记录。

验收：两个客户端竞争、断网重试、多网卡重复设备、中文主机名/路径、链接循环、空目录与跨平台名称冲突都有具体结果，不能用“传输成功”掩盖未处理项。

## 6. R08：缓冲预算必须可执行

原有 128 MiB 为应用可控制的传输缓冲预算；Qt/TLS 内部开销、线程栈和内核缓存需另外计量，仍须符合进程工作集和长时稳定性要求，不以“在第三方库里”解释无界增长。

1. 全局按字节授信，涵盖发送预读、接收、待写、跨线程排队及可计量 socket 缓冲。发放新数据前取得额度，写入/消费后归还，取消时全部归还；各连接不能重复拥有同一份“全局”配额。
2. 4/8 MiB 文件块可分成有上限的小片段流式读写，接收端不必把完整块攒在内存里才允许落盘；完成块摘要验证后才记录其可恢复状态。
3. 避免“所有通道都占着半个块，等待额外内存才能写出”的环形等待。验证 16 通道、8 MiB 块、慢磁盘和极小可用缓冲的组合，仍能前进或受控失败。
4. 分配失败时不以同等大小重新申请多个副本；QML 模型、日志队列、Qt 信号队列、TLS 和 SQLite 页缓存均纳入检查。数据库跨线程连接各自的缓存必须受总预算约束。
5. 统计实际在用字节、预留字节、队列长度、Qt 待发送量、线程、句柄和磁盘元数据占用；每秒采样无需拷贝完整任务列表。暂停/恢复、失败和取消都检查配额归还。

S01/S02 测量使用相同并发、相同任务构成和暖机方式，记录进程 RSS/平台等价指标及私有内存，避免拿空闲首小时与高并发末小时直接比较。峰值门槛、长时趋势和分配器保留缓存分别报告，初始阈值仍以主计划为准。

## 7. R09/R10/R11：服务边界、诊断和协议

- 新版共享服务与原版兼容接收分别配置入口。开启新版服务不自动开放原版无认证接收；原版设备模式按已核实的局域网行为运行。认证/证书失败不能通过自动切换旧协议绕开访问控制。
- 配对后可查看/撤销客户端，定义凭据轮换、会话过期和撤销后任务的处理；恢复任务重新鉴权。服务证书变化需验证新身份，CLI 非交互模式以明确错误结束。
- 日志记录时间、版本、任务 ID、阶段、错误码、耗时和必要路径映射；不记录令牌或文件正文。提供本地诊断导出，不自动上传日志；GUI 错误包含可操作建议，CLI 同源错误映射到已定义退出码。
- `doctor` 诊断只检查配置、目录可写性、依赖、端口绑定状态及对端能力；不修改防火墙/共享设置，也不读取整个用户目录。结果可用 JSON 导出。
- 固定协议主/次版本、能力位、握手与数据通道绑定规则、字段长度/字节序、控制帧和路径上限。未知可选能力允许忽略，未知必需能力拒绝；旧版协议入口不发送扩展探测帧。
- 定义帧不完整、长度超限、整数溢出、重复请求、乱序块、超时及认证失败的确定结果；协议测试要覆盖输入边界和版本不匹配。
- CLI JSON/JSONL 的事件版本、任务 ID、阶段、计数和最终结果保持契约；64 位字节数用约定的十进制字符串，防止脚本/界面浮点解析丢精度。新增字段保持向后兼容。

验收：取消访问后无法恢复或查询越权任务，旧/新版协议不混入，错误可关联到任务；结构化输出在协议与 CLI 版本变化时仍能按文档处理。

## 8. R12：先证明能构建，再扩大实现

Qt5 环境准备由开发助手负责：先核实已安装的版本与路径，缺失或不兼容时自行从官方发布源或可追溯的可信来源下载、安装，必要时源码构建，并配置配套编译器、SDK、CMake、Qt 模块和 TLS 依赖。按主计划 5.7 节记录来源、版本、SHA-256、安装位置、组件、命令及日志，随后执行以下探针；不把用户预装 Qt5 作为前置条件。各平台分别在实际目标环境中安装和验证，原版 Qt4 目录不作为新工程依赖。

1. P0/P1 先用最小 GUI、无 GUI CLI、TLS 连接及 SQLite 读写探针验证 Windows x64、macOS arm64/x86_64、Linux x86_64，记录系统/SDK/编译器/Qt/TLS 的准确版本和来源。
2. C++14 是现行约束。Qt5 补丁/平台组合不可用时记录实际阻碍及可继续的核心工作，不擅自改用 Qt6/C++17，也不把未执行的架构检查填为通过。
3. 依赖固定版本与校验值，保存补丁和构建参数；登记源码、Qt/TLS、图标和字体的来源/许可及发布时需附带的文件，复用原版源码前核实版本。
4. 发布分别包含桌面包、CLI、运行依赖、哈希、使用/部署说明及实际支持矩阵。Windows 控制台子系统、macOS CLI 可调用路径和 Linux 运行基线是发布检查项。
5. 自动安装更新暂不扩展；现有更新提示只针对有明确版本、来源和完整性信息的发布产物。安装升级保留配置、恢复记录和用户文件；数据格式迁移失败可回退或从备份恢复。
6. 建立需求 ID→实现提交→用例→结果文件→发布版本的对应记录。代码审查检查中文函数注释与日期、格式、C++14 和已有文件编码；功能状态必须有实际证据。

## 9. 暂缓扩展

首版保留手动并发档位及实测推荐。全自动并发调优、压缩/去重、完整增量目录同步、远程删除/移动、自动公网穿透/中继、完整多用户账号体系和自动安装更新列为后续选项，防止分散全功能复现、提速和稳定性工作。现有文件浏览不默认增加服务器文件管理/删除权限。

## SQLite 页缓存目标授信补充（2026-11-05）

五类生产数据库（旧版扫描、旧版接收明细、强清单、任务库、持久接收日志）均在打开前占用进程共用 128 MiB 应用额度，主库目标 1/2 MiB、临时库 64 KiB，禁用 mmap 并实际回读配置。发送数据线程的只读强清单使用 1 MiB；该线程任务库缓存归入数据额度，管理查询使用控制分类，数据不足时不能借用保留额。SQLite 连接关闭后才归还授信，构造失败也归还。

SQLite 的 cache_size 是页缓存目标，不能当作整个 SQLite 分配器的硬上限；语句、排序、固定连接开销和其他模型/元数据仍需后续预算。不得以本项通过宣告全部 R08 完成。Windows 双工具链 16/16、16 通道双向和额度饱和查询已通过，Linux/macOS 分别按新快照验证。
