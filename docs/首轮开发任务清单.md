## 2. 任务提交要求

每个任务完成时记录：日期、对应需求 ID、准确平台/工具链、构建版本或提交、操作命令、数据集大小/数量、预期和实际结果、日志/截图/哈希位置、遗留问题及下一步。没有新应用构建时，构建版本写“无”，不把参考程序版本当作新软件版本。

必要用例包括协议边界、文件完整性、原文件保护、配额归还、取消/重连与跨线程行为；不为纯文案和目录命名变化编写机械测试。依赖、文档、源码和生成产物分开管理，原版目录不修改。

结果建议保存在 `docs/validation/`，依赖/协议等决策保存在 `docs/decisions/`；这些目录在产生真实记录时再创建，不预填测试结果。
