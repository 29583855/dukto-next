# 认证会话期限

日期：2026-11-05。范围：新版 TLS 服务、独立 CLI、GUI 服务器页。实现与验证状态以主计划和实施进度为准。

每条成功认证或配对的连接都有固定期限，默认 86400 秒（24 小时），本机管理员可设置 1–86400 秒。以单调时钟计算已经经过的时间，修改系统日期或时区不改变它。普通请求、心跳、文件块和同连接凭据轮换均不重新计时；过期后必须新建 TLS 连接并认证。

```text
dukto-cli serve session show --state-directory <状态目录>
dukto-cli serve session set --session-seconds 86400 --state-directory <状态目录>
```

以上命令同样支持 `--json`，三平台共用核心与命令语义。GUI 位于“服务器 → 本机共享 → 认证会话有效期设置”，折叠展示读取、秒数及保存操作，避免挤占连接和文件操作。

本机私有记录 `service/session-policy.json` 必须恰有 `version: 1` 和规范十进制字符串 `seconds` 两个字段。缺省记录采用 24 小时；已有记录损坏、字段多余、版本不支持或数值不合法时明确失败，不静默放宽。合法保存采用私有原子写入；非法保存不覆盖既有值。

连接在 Hello 阶段读取一次策略，在成功认证后计时。保存设置只影响之后建立的新连接，已握手连接保留原策略。服务启动时同样校验配置。HelloAck 通过 `session-lifetime-v1` 能力和 `sessionSeconds` 十进制字符串声明期限；新版客户端严格核验。旧服务未声明能力时客户端显示为未知，不推断无限期。控制连接和数据连接各自认证、各自计时。

期限在业务边界和现有授权巡检中检查，传输/浏览的巡检周期为 250ms。不会在一个协议帧中间截断并插入错误帧：正在读取或发送的帧仍遵循原有帧/网络超时，因此 250ms 不是所有网络状态下的严格断开上界。空闲连接在下次请求或原有超时时处理到期；需要立即禁止访问时使用客户端撤销和停止操作。

到期返回退出码 4、阶段 `session`，提示使用相同资料重新连接并继续原任务。多通道中的其他连接可能先观察到关闭，客户端可先得到网络错误；服务端仍记录实际到期原因。任务中途到期保持 `interrupted` 和持久检查点；使用原任务 UUID、原路径或保存目录与相同配对资料执行 `resume`，重新核对内容后复用已同步块，可调整并发数。不能创建一个新任务并把重新传输当作恢复成功。

若提交已完成而确认丢失，继续使用已有任务查询、同请求幂等和完成确认规则；不回滚已提交文件或覆盖原文件。凭据轮换若已持久完成而连接在确认前到期，也沿已实现的待确认秘密恢复流程处理。

会话期限、配对票据期限、访问凭据撤销和 TLS 证书有效期分别管理。本项不关闭完整证书续期/替换、所有平台原生验证和完整 R09 生命周期要求。
