# 版本三任务必需计量契约

日期：2026-11-06

状态：内部实现；公开服务、客户端与 skip 入口尚未接通，验证结果另按精确提交记录。

旧任务的计量列允许为空。若直接把该规则用于显式跳过任务，恢复时可能丢失跳过证据，再以普通字节进度完成任务。为此，新增内部创建选项 dispositionAccounting，默认为 false；启用时创建参数使用版本三，并把 progress=disposition-v1 及规范冲突策略纳入同一请求摘要。

版本三恰有八个创建字段。未知契约、额外字段及未知策略均拒绝，即使创建摘要被重新计算也不能接受。其内部策略允许 rename、fail、overwrite、skip；默认创建流程和公共策略解析器继续保持原规则，skip 尚未开放。相同请求不能在旧模式与必需计量模式间切换。

首次绑定强清单时，同一任务更新初始化固定零快照。未绑定的任务不能预先出现计量；已绑定的版本三任务必须有合法计量，空列不能解释为旧模式。公开查询增加 accountingVersion=1，原任务的公开结构保持。数据库架构继续为二，创建契约版本与数据库迁移版本分别管理。

暂停后进入 checking 时，将必需计量重置为固定零快照，保留契约，再由执行层读取真实日志重建本轮恢复计量；不得清空快照并降级。转入 verifying、committing 或 completed 仍要求完整字节及全部文件/目录归结，空条目不能绕过。

验证包含四种策略、相同请求模式冲突、全跳过时实际接收零字节而逻辑处理量达到总量、关闭后重开，以及暂停/checking/重新计量。直接修改自有 SQLite 样本，分别删除必需快照、向未绑定任务插入快照、破坏契约；对参数攻击重算摘要后确认查询与分页仍拒绝。旧迁移与旧公开路径另做回归。

后续服务接线必须先完成双方能力协商、十三字段进度及持久回调、最终处置摘要核对与完成历史的只读恢复，再开放公共 skip。当前内部 API 通过不能代替这些端到端验收。
