# 晚期冲突最终跳过与临时清理

日期：2026-11-05。状态：接收核心已实现；原生验证范围见公开验证索引。公开 skip、协议协商和任务最终确认继续独立验收。

准备 `receive` 后，目标仍可能在正文打开、恢复或原子发布时出现。内部 Skip 对安全的同类型普通目标形成最终 `skipped`，保留外部目标；活动预约、链接、特殊文件、类型错误、权限和 I/O 失败继续明确报错。

接收核心增加 `openDisposition()`、`openConcurrentDisposition()` 和 `finishDisposition()`。返回值分别携带跳过状态、子树根和正文块序号；调用者必须先检查处置。旧 `open()`、`openSparse()`、`openConcurrent()` 和字符串 `finish()` 对 Skip 拒绝，避免把跳过路径误认为复制成功。其他三种策略保持原调用语义。

Skip 日志升级为版本四，新增 `skip_final`。原 `skip_decisions` 的 receive 决定不可变；最终表只为该项增加覆盖记录，绑定冻结条目、原目标、冲突对象身份、自有临时名称及原生身份。目录必须在后代准备之前完成最终裁决；后代沿磁盘父索引继承相同跳过根，不遍历外部目录。

最终裁决持有目标预约与普通目标句柄，最后一次取消/授权检查后核对根及目标身份，再 FULL 提交。文件若已按本任务日志身份发布，即使完成确认丢失，也必须恢复为 copied；内容或身份异常不能改判为跳过。

先持久化最终跳过，再清理临时项。清理后单独事务保存 `cleaned=1`，并解决此前清理错误。进程可在最终提交后、删除后或清理确认前退出；重启继续相同决定。目标后来删除或换名不会触发重新接收。跳过项对外确认字节归零，实际已经接收过的网络字节不能被称为 copied；协议/任务层仍须分别统计。

清理只允许日志身份匹配的普通文件或空目录。Windows 固定父目录，以 DELETE 句柄核对原生 ID，并按同一句柄删除。POSIX 固定父描述符，核对 dev/inode、类型及路径后使用 unlinkat，并同步父目录。临时项已被替换、出现链接、身份未知或目录非空时保留并报错；绝不递归删除。POSIX 没有通用路径 CAS，不能承诺抵御外部进程在最后核对与 unlinkat 之间的任意改名。

恢复最多每页 100 条，规范记录最多读取 65,537 字节。最终记录必须有合法原准备和匹配的接收意图，孤立序号、超大字段、非法清理状态及与 completed 意图冲突都拒绝。最多 16 个正文文件句柄与块上下文，跳过释放窗口，不驻留全部项目或后代。

旧版三仅在精确绑定、旧准备记录及所需表字段验证后，原子创建最终表并更新绑定。已有版本四缺表按损坏拒绝，不补建。默认 rename 的版本一及 fail/overwrite 的版本二格式保持不变。

本轮测试包括真实子进程提交后退出、删除后退出和自身发布后退出；准备/打开/恢复/发布竞争、非空目录和替换临时项保护、事务取消回滚、16 文件窗口、旧日志升级及损坏日志拒绝。完整协议、处置日志自动衔接、任务及 GUI/CLI 尚不能据此标为完成，公开 skip 保持关闭。
