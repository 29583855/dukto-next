# 0052：测试子进程提前退出与Qt等待返回值

日期：2026-11-07。范围：测试夹具；生产实现未变化。

原并行处置测试在收到Closed帧后，直接要求`QProcess::waitForFinished(10000)`返回true。Qt5在进程已处于NotRunning时返回false，因此该断言不能独立区分真实超时和提前正常退出。Qt5.15.13上游实现与本机原生运行均证实此语义。

独立Ubuntu原R95二进制整组16行复查保留15通过/1失败（download-4-1）；没有慢服务堆栈。另一个只增加状态日志的副本16行全部通过，退出等待10–22ms。随后明确注入100ms事件泵的单行诊断得到：等待前NotRunning、PID=0；原wait返回false、耗时0ms；NormalExit/exitCode=0。所有诊断保持原生产核心与原测试二进制摘要不变，刺激和自然观察分别保存。

修正仅检查已确认启动的子进程：若已经NotRunning，直接进入原退出状态/退出码核对；若仍运行，继续执行原十秒等待。原并行TLS/落盘/摘要、NormalExit和exitCode=0等检查不变。不增加超时，不重试失败，不改生产取消或线程回收策略。

新增真实子进程四数据行：提前正常退出、提前错误退出37、运行中自然完成、20ms真实超时。错误退出码单独核对；真实超时保持失败并清理自有子进程。Windows MSVC和UCRT各四行加原16组并行TLS通过；Linux新夹具专项与双Mac原生回归继续。

这证明夹具存在可重现竞态；原两次失败当时没有状态采样，不能断言所有历史失败均由该竞态导致。旧失败原件保留，不追改为成功。R96双Mac下载包仍绑定88f33b2，当前生产实现与其相同；新测试未包含在旧包应用源码中。完整资源/GUI/长期/物理网络及正式发布资格继续未完成。
