# 新版协议与服务实现契约

日期：2026-11-04；对应 P3A/P4/P4A、D01–D08、C03/C04、R01/R02/R08/R09/R11。

本记录固定实现边界与顺序。Windows/Alpine Linux 已有服务身份、认证、共享分页浏览和核心强清单/持久任务的实测；完整上传/下载、并行和恢复尚未交付。具体证据见实施进度，本记录不替代功能验收。兼容 R6 的已验证协议不变，不向 R6 端口发送本协议探测。

## 入口、身份和认证

- 新版服务默认 TCP/TLS 4646，可配置；R6 兼容接收为独立配置，开启服务不同时开放无认证接收。端口冲突明确报错。
- 客户端始终主动连接，上传时向服务器发送、下载时由服务器沿该连接发送；客户端不要求开放入站端口。后续每个并行数据连接也由客户端建立。
- TLS 至少 1.2。服务器证书/私钥持久化在受保护的服务配置中；初始化和普通启动分开，缺身份时不临时生成一个新身份冒充旧服务器。
- 首次配对必须核实证书 DER 的 SHA-256 指纹并提供服务端本地生成的有期限、一次性配对凭据。GUI 展示完整指纹供核对；CLI 非交互必须显式提供可信指纹和凭据文件，不停在提示输入中。
- 配对保存证书指纹、客户端 ID 和随机 256 位访问凭据；服务器保存凭据摘要、权限、撤销状态。每次连接认证，数据通道也重新核对服务器身份。证书变化、过期、错误主机/配置和撤销明确失败，不自动转成无认证访问。
- 已固定指纹的自签证书只允许有针对性的信任处理；禁止无条件 `ignoreSslErrors()`。受信 CA 模式仍执行证书链、期限及主机名校验。两种模式分别做正反例握手测试。
- 凭据不通过命令参数、日志、JSON 事件或恢复记录暴露。Unix 文件权限、Windows 账户保护及凭据轮换必须真实实现/验证，不能把 Qt 的权限标志当作 Windows ACL 已完成。

## 帧和输入边界

TLS 内使用 32 字节固定头，整数采用大端；R6 仍为原有小端。

| 偏移 | 字段 | 规则 |
| --- | --- | --- |
| 0 | magic，8 字节 | ASCII `DKTNEXT1` |
| 8 | major，u16 | 首版为 1，不支持的主版本拒绝 |
| 10 | minor，u16 | 首版为 0；按协商能力处理新增可选字段 |
| 12 | type，u16 | 控制请求/响应、数据片段等显式类型；未知必需类型拒绝 |
| 14 | flags，u16 | 首版保留，必须为 0 |
| 16 | correlation，u64 | 当前连接的非零请求序号；响应使用相同值，不作认证或幂等键 |
| 24 | payloadBytes，u32 | 控制最多 64 KiB；数据片段最多 256 KiB 加固定数据头 |
| 28 | reserved，u32 | 必须为 0 |

控制正文为有效 UTF-8 JSON 对象，深度最多 16，不接受重复关键字段或非对象根；64 位大小、偏移、序号在 JSON 中用十进制字符串。解析必须限制正文、数组、字段、嵌套和未完成缓冲，先检查长度/类型再申请空间。不能因为 Qt JSON 解析器容忍重复键就忽略该边界。

首条控制请求为能力协商，随后认证。控制路径最多 4096 UTF-8 字节，文本/名称按纯文本展示；分页同时限制 100 项和序列化后的 64 KiB，不能只限制条数。版本/能力不支持、超时、截断、溢出和畸形报文均返回确定错误并释放额度。

数据连接第一帧绑定已认证的任务、方向、通道和一次性随机票据；票据短期有效、不可跨任务/身份使用，不作为恢复凭据。数据头携带任务内文件 ID、块 ID、片段偏移和实际长度；任务、清单及块身份共同约束落盘位置，不接受客户端直接指定原生绝对路径。

## 授权根与浏览

共享名称映射为服务端本地固定根，分别授予浏览/下载和上传权限。客户端只提交共享名称和相对路径；授权在创建、浏览、传输、恢复和任务查询/管理时重查，不能只在登录时检查一次。

目录浏览使用有界磁盘快照/游标，游标绑定认证身份、共享、路径、快照和期限；文件数增长不能使内存线性增长。快照和 SQLite 临时索引计入磁盘总预算。目录变化、游标过期和越权明确返回，不把空列表当作错误回退。

文件、目录、临时创建、源读取和最终提交均遵守同一链接/特殊文件策略。后续服务器读取也需要原生句柄加固；当前接收端加固不能当作服务端读取已安全的证据。

## 任务、内容身份和完成

创建任务携带独立的稳定 UUID 幂等键。服务器按认证身份和幂等键持久识别同一请求；参数摘要相同返回同一任务，不同返回冲突。连接 correlation 与此键分工明确，断线重连不会丢失幂等语义。

清单逐页上传/生成并写 SQLite，文件 ID 在同一清单内稳定；包括精确相对名称、类型、64 位长度、全文件 SHA-256 及分块摘要。源内容身份绑定这些强摘要和确定的清单编码，不能仅用 size/mtime。消息类型与块头已按下方 codec 基线形成独立测试向量；能力协商和清单编码仍须在对应实现中冻结，不能用平台内存结构直接序列化。

任务状态区分扫描、排队、传输、暂停中、已暂停、恢复检查、校验、提交、已完成、取消中、已取消、失败及断线后结果未知。任务操作限所属身份或显式管理员；撤销立即阻止新的通道、查询和恢复，已有任务按明确的撤销策略停止。

接收方核对块摘要、最终全文件摘要和目标预约后提交，先持久化最终路径/摘要/状态，再发完成确认。确认丢失时查询同一任务，不能再生成一份自动后缀副本。批次有失败不返回整体成功，报告成功、失败、跳过和未执行项。

暂停与取消采用 R01 的不同保留策略；恢复重新认证、核对强内容身份并重读验证已有块。数据同步、检查点记录、最终命名、目录同步和最终状态的顺序须与平台落盘实现一起验证；普通 flush 不表述为断电持久保证。

## codec 实现基线（不表示完整服务已交付）

维护代码 `src/core/protocol.h/.cpp`，首版 1.0。消息数值显式固定：Hello/HelloAck=1/2、Authenticate/Authenticated=3/4、Pair/Paired=5/6、Failure=7、Close/Closed=8/9、List/Listing=16/17；32–49 依次为 CreateUpload、CreateDownload、Task、Manifest、ManifestAck、ChannelTicket、Attach、Attached、Data、BlockDone、BlockAck、Finish、Completed、TaskQuery、TaskState、Cancel、Pause、Resume。未知类型和未协商版本拒绝。

数据正文为 RFC4122 UUID 16 字节、file u64、block u64、offset u32、length u32，均大端；后接 length 字节。file 非零，UUID 非空，片段非空且至多 256 KiB，块内偏移加长度至多 8 MiB。接收者仍须依据任务强清单核对实际块长度、摘要、所有权和授权，codec 不承担业务授权。

控制字段每对象最多 32 个，数组最多 100 项，总节点最多 4096，深度最多 16；字段名解码后最多 64 UTF-8 字节，字符串最多 4096 字节，禁 NUL/非法 Unicode。所有重复键（包括转义别名）拒绝，Qt5 容忍的非法转义也显式拒绝。64 位值只接受规范十进制字符串，不接受前导零/符号/指数/JSON double。

测试的 Hello 头固定为 `444b544e45585431000100000001000001020304050607080000000200000000`，正文为 `{}`。数据线样本和 UUID/最大 u64/8 MiB 边界另见 `tests/protocol_tests.cpp`。解码器最多保留当前一个帧，socket 读取上限由当前还缺字节数决定；畸形帧后封闭解码器，不尝试重新同步。

生产 TLS 通道限制 TLS 1.2 或以上、固定 Qt 读缓冲、串行排空发送缓冲，单帧头/正文共享总期限；25ms 检查原子取消。自签固定指纹仅允许同一有效叶证书的 SelfSignedCertificate 错误；主机名、有效期、其他链错误和握手后指纹必须继续校验，禁止无条件忽略。真实正反例见 `secure-channel.json`；全局额度、公平多任务与受保护身份存储另行实现，不把单通道有界当作全进程预算完成。

## 当前服务与浏览基线

当前能力声明为 `pair-v1`、`auth-v1`、`control-close-v1`、`browse-v1`、`stream-transfer-v1` 和 `task-control-v1`。CLI 的 `serve/pair/auth/list` 与无桌面运行已在 Windows/Linux 实测，Windows 与 Alpine Linux 单通道 upload/download 和公共任务控制已通过独立进程传输与首块后故障恢复验证。服务器 GUI 已接共用核心，Windows 真实上传/下载和 QML 浏览交互通过；完整桌面矩阵继续。

配对和身份使用原生私有权限；Windows 为当前 SID 所有者与受保护 DACL，POSIX 为当前有效用户的 0700 根与 0600 文件。RSA3072/SHA256 身份普通启动只加载，随机 256 位秘密通过 TLS 交付，服务器只存摘要。一次性票据在创建客户端记录前持久绑定身份及令牌摘要，相同身份可在确认丢失后幂等修复。权限/撤销跨进程持久化；凭据轮换的 Windows GUI/CLI 实现和故障恢复已验，见[轮换契约](0004-访问凭据轮换.md)；票据自动回收、会话期限及其他平台轮换仍待补齐。

浏览使用私有目录 JSONL 快照和 HMAC 游标，绑定主体、共享、相对目录、偏移和五分钟期限。最多四个有效快照、每主体两个；创建快照时计量当前状态目录，准入预算为 256 MiB。每页最多 100 项且预留游标空间，整体正文不超过 64 KiB。目录原生身份/修改标记变化、游标越权或过期明确失败。该预算不是其他状态写入者共同执行的全项目总磁盘预算。

扫描中每 250ms、发布快照前及返回页前重新认证并核对当前共享根；共享根改配后不能继续发布旧目录列表。长操作通过 `SecureChannel::checkpoint` 泵送本线程受限 TLS 缓冲事件并检查断开/取消，避免客户端离开后仍扫描完整目录。列表不跟随链接读取外部内容，链接、特殊文件和不支持名称明确标记。列表元数据不构成文件内容原子快照。

## 强清单编码基线

`StrongManifest` 在原生受保护文件上使用 SQLite；缓存 2 MiB、单库最多 256 MiB、临时排序在磁盘，每 256 条或 200ms 提交。目录枚举和内容摘要都提供取消/授权检查点。以 UTF-8 路径字节顺序分配从 1 开始的稳定 ID，父目录先于子项。保留原名，使用 NFC+casefold 独立唯一键拒绝跨平台冲突；拒绝不配对 UTF-16 代理项，不能用 UTF-8 替换字符改变内容身份。

每个普通文件保存精确长度、全文件 SHA-256，以及连续 4 MiB 分块的 SHA-256，尾块使用剩余实际长度，空文件没有块但仍有全文件摘要。按 256 KiB 读取，不把整个块/文件或所有块摘要驻留内存。公开条目为 `id/path/type/bytes/sha256`；目录 `bytes="0"`、摘要空字符串；本机 source 路径不进入网络或内容身份。块分页为 `block/bytes/sha256`。条目页最多 100 项并按 64 KiB 正文字节预算提前切页，块页最多 100 项。

规范身份 SHA-256 输入按以下顺序拼接，所有整数为无符号大端：

1. ASCII `DuktoNext.Manifest.1`，一个 NUL，块大小 u32（4194304）。
2. 每个条目：ASCII `E`，ID u64，名称 UTF-8 字节数 u32，名称字节，目录 `D` 或文件 `F` 一字节，长度 u64，32 字节全摘要（目录为全零）。
3. 紧随该条目的每个块：ASCII `B`，文件 ID u64，块序号 u64，块字节数 u32，32 字节块摘要。
4. ASCII `Z`，总条目数 u64，总块数 u64，总字节数 u64。

独立 Python `hashlib/struct` 样本包含目录 `资料`、文件 `资料/a.bin`（`abc`）与空文件 `资料/empty`，ID 为 1/2/3；固定身份为 `6336657ba5ca0e8364a9ecd122e38b6cd9cddd5ff56b7e7885d45bb757099c8c`。构建者完成全体范围/块/总计检查后才写冻结元数据；只读重载重算身份，拒绝半成品和记录变化。该模块已接入公共单通道服务，Windows 已验证实际双向数据传输；多通道和完整平台矩阵另行验收。

## 持久任务基线

`TaskStore` 使用原生受保护 SQLite、1 MiB 缓存、单库 256 MiB 上限、DELETE journal 与 FULL 同步。全库最多 1024 个任务、每主体 128 个；额度满明确拒绝新任务，重复既有请求仍返回原任务。任务自动过期清理/管理及全项目总磁盘配额后续接入。

主体 UUID 和独立请求 UUID 唯一绑定一个服务生成任务 UUID；创建参数摘要涵盖方向、共享、相对路径、服务端固定根、保留双方文件策略与上传强清单身份。并发档位属于可调整资源请求，不改变内容幂等键。相同键/参数返回同任务，不同返回完整性冲突；其他主体查询、锁定和控制均拒绝。源根只留在私有创建记录，不公开给客户端。重新读取时核对创建参数摘要。

跨进程任务租约确保单一执行者，状态写入使用 SQLite 写事务和修订号比较交换；没有任务执行锁不能推进状态。2026-11-05 v0.24 增加创建后的有限资源等待，服务端获准后才扫描下载源或接收上传强清单；上传客户端为取得强身份仍先扫描本地源。扫描完成绑定实际冻结清单，调用者不能直接把未验证的网络 summary 当作已冻结清单。具体阶段和兼容线序见[有限任务排队](0007-有限任务排队与公平授信.md)。传输后需进入校验、提交，再确认完成；完成要求进度等于声明总量。终态不能再恢复成传输。提交中不能用普通失败/取消覆盖可能已经发布的文件结果，后续必须凭文件提交日志恢复判定。

暂停/取消 API 先持久化请求，工作者到安全点才确认暂停/取消；取消优先于暂停。恢复需先进入检查状态，不能从暂停直接标成正在传输。扫描未完成时允许取消；2026-11-05 起未绑定清单的资源等待阶段也允许暂停，已进入未完成扫描时仍须等强清单绑定后暂停。接收/交换核心已接入公共服务任务状态；查询/暂停/取消/继续入口已实现，独立进程故障验证继续。不能据此勾选完整 R01/R02。

## 文件接收与单通道交换增量

`DurableReceive` 已增加独立文件日志，绑定任务 UUID、冻结清单和目标根。每个文件记录原名、随机同目录临时名、最终名、原生文件 ID、持久状态及已确认连续字节前缀。块检查点必须在完整块 SHA-256 通过并执行文件同步后提交；恢复按 256 KiB 重读已有块，发现损坏或短数据时回退到首个坏块，清除后续确认并重新传输。默认单通道使用连续块前缀；新增 openSparse 允许任意块重读与交错片段，完整块依旧同步后写日志。网络多通道和全进程额度继续实现。

全文件 SHA-256 核对后先保存 `committing` 意图及候选最终名，再执行原生不覆盖命名和目录同步，最后保存 `completed`。命名后、日志完成前进程退出，恢复要求最终名的原生文件 ID、长度和全摘要同时匹配；确认丢失返回同一名称。同名外部文件保留并选择后缀，完成文件被相同内容的新对象替换仍拒绝。临时文件独占创建后、原生 ID 尚未记录的极小窗口若中断，会保留数据并明确拒绝推断；安全回收/重建管理继续接入。不能把该子范围描述为所有崩溃点或断电恢复已验收。

`fileexchange` 在已有 TLS 和已授权任务上下文内执行有界清单/文件交换。清单 `Manifest` 页包含 `taskId/index/kind/value`，顺序发送 summary、entries、blocks、seal，每页有匹配的 `ManifestAck`；页确认表示导入，seal 成功并核对总计后才表示完整持久清单。公开条目不含 source 路径。

文件子交换使用同一个 correlation，Attach 绑定 taskId、file、manifest，Attached 返回相同身份和已重读确认的 block/bytes。256 KiB Data 帧按期望块流式发送，块末 BlockDone/BlockAck 绑定同一身份与 block。跳过的数据前缀仍在发送方重读核对，并逐块交换确认，避免大恢复前缀扫描造成无报文的长时等待。Finish/Completed 用强身份绑定最终提交，Completed 另含最终相对 path。该单通道数据契约已接入公共授权服务与 CLI。目录使用 Attach 的 kind=directory 和 Attached 的最终相对 path 预约父子映射，空目录也逐项确认。数据多连接票据与多通道调度继续实施。

## 长操作与公共任务控制增量（2026-11-04）

文件子交换可发送同 correlation 的 TaskState，正文严格为 `{"state":"busy"}`。清单冻结、恢复块重读和全文件校验每 250ms 发送心跳，收发两端等待实际数据/确认时消费该消息；它不代表持久块确认或任务进度。单帧仍保持固定总期限；长处理继续检查断开、取消和授权。慢读双向恢复已通过超出单帧期限的测试。

TaskQuery/Pause/Cancel/Resume 仅接受规范 taskId。每个请求重新认证，按任务所属主体及当前共享方向权限核对，根改配拒绝。控制响应另含 executionActive，区分请求停止与实际停止。活动租约由原工作者确认暂停/取消；空闲任务由控制连接取得租约后确认，进程退出遗留活动状态改为 interrupted；committing 仍保留结果未知，不推断完成。Resume 取得空闲租约进入 checking，实际数据仍由原 requestId、共享和强身份重新接入。CLI resume 从任务读取固定参数，上传提供原 --path，下载提供原 --output。

## 任务分页与扫描库生命周期增量（2026-11-04）

TaskQuery 额外接受精确的 `{"after":"0"}` 形状，与单任务 taskId 形状互斥。响应为 tasks/after/more；按当前主体的 SQLite rowid keyset 分页，最多 100 项和 64 KiB。服务层按当前方向授权和固定根过滤；公开对象不含 root。列表反映持久记录，实际执行租约仍需单任务查询确认。CLI tasks 支持逐页及 --all；GUI 仅保留当前页，重启后重新认证可找回所属任务。

上传扫描由 TemporaryManifest 持有随机命名的私有 SQLite；先销毁清单及关闭连接，再删除其库和 journal。正常返回、异常退栈及构造失败均尝试回收；回收失败显式记录诊断且不覆盖原数据结果。强制退出可能留下扫描库，不能把此子项当作自动清理/总磁盘配额完成。

## 任意块接收核心增量（2026-11-04）

openSparse 重读当前文件全部已确认块，以块序号乘 4 MiB 定位；坏块独立删除检查点，其后有效块保留。恢复逐页最多 100 条，不加载整文件位图。confirmed 在该模式是已确认块的字节总量，不能用作文件写入偏移。write 仍要求块内连续片段，不同块允许交错；最多 16 个活动块，仅保留偏移和增量 SHA 状态，不缓存整块。重复已确认块、片段乱序、超范围和超过活动块额度均拒绝。只有全部字节已确认、没有部分块且最终全摘要一致才提交。

Windows 专项以真实子进程直接退出验证非前缀块恢复、独立坏块修复、交错写入、尾块、幂等提交与活动块额度。后续网络多通道已按以下增量接通；默认顺序 API 保持单通道前缀语义。

## 独立多数据通道增量（2026-11-04）

`parallel-transfer-v1` 协商支持 1/2/4/8/16 请求档位。1 使用已有顺序链路，其他档位在清单完整导入后通过 ChannelTicket 返回 sessionId/taskId/manifest/token/lanes；服务合计最多 16 数据槽，按可用量降到受支持档位或明确拒绝。票据是随机 32 字节秘密，最多 30 秒内加入，绑定服务目录、主体、任务、清单和数据方向；只存活动进程，禁止进入日志/公开进度。

每数据连接由客户端发起，独立 TLS/Hello/认证，再用 Attach `{sessionId,token,lane}` 加入。服务验证当前授权、根、任务状态，每槽仅准一次加入；附加连接既不接受任意源路径，也不以 taskId 代替认证。每通道工作者拥有自己的网络对象；发送方从私有冻结清单重载只读 SQLite，按 4 MiB 块以 256 KiB 片段读源并核对 SHA。接收网络线程只交给一个片段槽；单一控制线程持有接收日志/QFile，验证 file/block/offset，完整块同步和日志成功后才 BlockAck。

接收端按最多 16 个清单条目的窗口准备文件和目录；普通文件各持一个上下文并共用一份 SQLite。对空闲 lane 在文件之间轮转派发 `{taskId,manifest,file,block}`，同文件允许不同块并行。所有窗口块持久确认后逐文件全摘要及独占提交，按清单顺序发送 Completed `{taskId,manifest,file,kind,path}`；目录也有对应确认。空清单显式 Completed `kind=empty`。最后文件确认之前关闭全部数据通道，避免旧 correlation 心跳残留到后续请求。

接收上下文切换只移动句柄、增量 SHA 和标量，最多 16 文件；不为每个文件单独建立 SQLite，不把十万文件转换成常驻列表/句柄。窗口不是整个批次的原子提交，已完成文件可以先于后续窗口公开；失败不能误报整个任务成功。

共享 BufferCredit 提供 128 MiB 应用预算，SecureChannel 每条 4 MiB，多通道队列每 lane 另计 1 MiB。2026-11-05 起，TLS 数据连接在重新认证/票据验证后原子转换已有授信，数据类总额至多 120 MiB、全类别合计至多 128 MiB；转换失败不改变计数，重复转换幂等，不临时重复申请相同额度。usage 分列 used/peak/dataUsed/controlUsed/dataPeak，数据和控制先后进入都按各自额度检查，析构精确归还。身份握手阶段暂计控制类。旧 R6、所有 SQLite/元数据及模型缓存尚未统一纳入，完整公平和预算仍为开放项，不据此声明 R08 完成。
## 实时字节进度扩展（2026-11-05）

能力增加 `byte-progress-v1`，新客户端仅在服务声明支持时给 CreateUpload/CreateDownload 增加 `byteProgress:true`；字段不允许 false 或其他类型。缺少能力时维持原文件级确认，旧 R6 不发送扩展帧。固定类型 Progress=50，正文精确六字段 taskId、manifest、bytes、confirmed、restored、total，64 位计数都是规范十进制字符串；bytes 表示本次执行实际接收及重验恢复的字节，confirmed 仅包含已同步且 SHA 通过的块，restored 为本轮重新读取校验过的已有块。约束为 0≤restored≤confirmed≤bytes≤total，三计数单调，bytes-restored 不能回退。任务/强清单/correlation/总量必须匹配当前交换，额外字段、错误编码和未协商阶段全部拒绝。

进度由接收控制线程生成，不跨线程访问 SQLite/socket；单通道和多文件并行窗口在片段写入后累加，恢复只计本轮重新验证的块。通常 250ms 至多一条固定快照，最终进度必须在最终文件/目录确认之前发送，防止下一请求阶段遗留尾帧。发送方仅在当前树交换的有界观察者中消费进度；进入下一协议阶段前移除，不能把进度帧冒充块/文件/任务完成。下载服务方持久查询消费进度可能晚于客户端本地快照，独立连接查询是最终一致的观察，不建立跨连接消息因果顺序。

应用事件 `byte-progress` 的 bytes 为已同步确认量，receivedBytes 为实际接收+重读量，restoredBytes 单列；bytesPerSecond 排除恢复重读量并用相邻样本平滑，etaSeconds 无法估算时为 null，估算仅涵盖剩余传输，最终全摘要和提交另行等待。全部字节到达不意味着整个任务 completed。持久任务仅记录 confirmed，GUI 接收单槽合并、CLI 逐行输出；恢复就绪时清除前次瞬时计数与速率，重新验证检查点后再显示。
