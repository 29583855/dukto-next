# 任务固定计量与版本一迁移

日期：2026-11-06

状态：任务库内部 API 与迁移已实现，完整验证中；公开服务/客户机尚未调用此 API，公开 skip 仍关闭。

任务数据库原来只保存 `processed`。加入 skip 后，逻辑处理量可能包含未传输的文件，仅凭这一个数字无法恢复复制、跳过和晚期冲突的差异。本次为任务架构增加可选的固定计量列，为后续公开接线提供真实的持久化入口。

## 架构及兼容

SQLite `user_version` 从1升级为2，在原表末尾增加 `accounting BLOB NOT NULL DEFAULT X''`。旧记录保留空计量值，原创建参数、请求摘要、任务身份、修订和完成结果保持原字节。旧任务公开 JSON 不增加计量字段。新建任务使用显式列名，分页明确使用扩展列之后的 rowid。

创建表、增加列、索引及版本更新都在同一 `BEGIN IMMEDIATE` 事务中。初始化仍使用原跨进程锁、5秒预算及独立连接；任何中途失败回滚架构变更。负版本和未来版本明确拒绝，不能降级或重建为新空任务库。

## 持久 API

`TaskStore::recordAccounting` 要求调用者持有执行租约，任务处于 transferring、修订号匹配且没有停止请求。它使用固定大小 `TransferAccounting` 验证新快照及上次快照间的单调关系，随后在同一 FULL 同步事务中保存计量、逻辑处理量及新修订。非法快照、错误策略或陈旧修订均保留原记录。

当前已经公开的 rename、fail 和 overwrite 策略不得记录跳过字节、跳过文件/目录或丢弃结果。后续 skip 策略仍需单独绑定创建版本、显式能力及恢复规则；本 API 不扩大公开允许策略。

可选计量任务公开查询单列 copiedBytes、skippedBytes、discardedBytes、四类条目计数及 receivedBytes、confirmedBytes、restoredBytes、handledBytes。原 bytes 表示逻辑处理量，实际接收和最终复制量分别可见。所有64位数仍使用规范字符串，不包含本机根路径、凭据或正文。

## 状态约束

已经启用计量的本轮执行不能再通过普通数字进度覆盖 `processed`。进入 verifying、committing 或 completed 前，除总字节达到清单外，还必须归结全部条目；空文件和目录不能通过“总字节已到达”绕过。

暂停、中断和停止状态保留当前快照。进入 checking 时必须将本轮处理量清零并清空可选快照，之后根据真实接收日志重新读取/校验恢复数据，不把上轮数字直接当作本轮有效恢复。已完成任务不重新激活。

读取非空计量列时重新验证字段、字节守恒、策略及与 processed/终阶段条目数量的一致性，损坏数据拒绝使用。空列继续代表旧计量模式；公开 skip 接线必须进一步要求其版本化任务始终具备必需的计量证据。

## 验证要求

独立构造真实版本一表及已完成记录，升级、关闭和重开后逐字段核对原记录，检查新建任务及分页；版本不支持或迁移失败时核对磁盘版本/结构保持。真实任务执行验证持久计量、陈旧修订、停止请求、暂停重开、checking清零、全部空条目归结及终阶段限制。关闭库后直接破坏自有样本的 SQLite 列，确认查询/分页拒绝畸形或不一致证据。完整构建、CTest及公开协议结果另以实际执行报告记录。
