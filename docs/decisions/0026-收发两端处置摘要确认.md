# 收发两端处置摘要确认

日期：2026-11-06。适用 C++14 / Qt5 新版 TLS 协议；GUI 与独立 CLI 使用同一实现。

传输字节全部到达仍不足以证明双方记录了相同的目录条目、最终重命名路径和处置结果。本次增加 disposition-summary-v1 能力，创建请求显式发送 dispositionSummary: true。服务端同时核对本连接的 Hello 声明；未协商、假值、字符串真假和未知创建字段都拒绝。旧客户端未请求此能力时维持原流程，新客户端遇到旧服务器也维持原流程，成功结果不声称双方摘要已确认。

普通任务在逐项持久确认全部完成后进入 verifying。服务端发送52 / DispositionSummary，客户端从本机持久日志独立汇总，逐字段精确比较，再用53 / DispositionAck回送完整同一对象。服务端比较全部字段与请求序号，强制重查身份、共享根和停止意图后才能进入 committing / completed。最终任务响应再次携带同一 dispositionSummary 和 dispositionConfirmed: true；客户端验证最终响应后才报告本次成功。

摘要沿用版本1的规范日志哈希：任务UUID、冻结强清单与冲突策略绑定记录，以及按清单顺序排列的每项规范记录，均加4字节大端长度前缀后进行 SHA-256。摘要包含18字段，覆盖条目、文件、目录、已复制/跳过/未执行和字节总计。任何缺项、附加字段、数字类型变化或错误哈希都不能被宽松转换掩盖。当前公开策略仍只有 rename / fail / overwrite，跳过计数均为零；这一步不开放公开 skip。

历史 completed / committing 重试先执行设计0025的只读当前内容核验。历史 committing 完成原有持久事务后，首个 completed 响应带 confirmationRequired: true，仅表示已核验的历史事实。客户端随后补齐并核对本机证据，再执行52/53交换，接收第二个最终响应。上传缺项仍通过独立认证的100项分页恢复，原连接保留至确认结束；下载逐项重验本机接收结果。历史已完成记录不会因本次确认失败、断线或对端错误被倒退或改写。双方确认只对本次执行有效，不写成历史任务永久属性。

摘要分页仍为100项、SQLite缓存为1MiB；网络只发送一个有界摘要，不发送全量数组。双方长时间遍历每250ms可发送同序号 TaskState {"state":"busy"}。忙帧不能替代摘要或确认，服务端每轮仍处理取消、根身份、授权与会话期限。普通任务摘要错误为完整性失败6；确认断线保留可恢复中断。原正文、接收检查点及用户后续文件不自动删除或修复。

验证使用两套真实 Windows GUI/CLI、全部核心测试、1/4/16通道三策略双向业务和原最终确认/恢复专项。另用自有 TLS 身份的逐帧中继分别改写服务摘要、客户端确认和最终结果，独立计算日志哈希并检查确认前持久状态为 verifying；历史攻击检查 completed 记录保持。中继在一个线程内交替读写 TLS 对象，避免把测试工具的 OpenSSL 并发访问问题计入产品结果。精确跨平台资格与原日志见当前计划和验证索引。

仍需继续公开 skip 的正文裁决、GUI/CLI跳过结果、R6完整策略和全局资源/GC验收。摘要一致证明双方对处置记录达成一致，不构成跨整棵目录的原子快照。
