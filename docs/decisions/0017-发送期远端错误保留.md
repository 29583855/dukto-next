# 发送期间保留远端原始错误

日期：2026-11-05。状态：Windows两套C++14工具链及独立TLS线样本通过；原生真实盘满复验待完成。

## 触发与修复

原生Ubuntu和两种Mac的显式覆盖单通道上传，在首个持久块后实际ENOSPC，服务端拒绝继续接收。旧发送循环仍向同一TLS连接写剩余片段，随后断线可能先于块确认读取，客户端因此报告3/网络错误，掩盖原5/磁盘错误。原失败运行42025282676和42025292135的附件与日志保留，盘满断言仍严格要求5。

单通道发送树现在注册限定关联号的远端错误观察器。发送片段的写等待及帧边界检查点先检查已到达的完整Failure、Progress或严格busy心跳，保留原错误码、阶段和消息；普通块/文件确认留给原业务读取器。退出发送树时撤销观察，包括异常退出。

观察器每次至多处理四帧，沿用现有固定socket缓冲、协议头及控制正文上限；不积累队列，不等待不完整帧，不额外延长超时。请求号不同为完整性错误，非法错误码/消息为配置错误，未协商Progress及非busy状态拒绝。只有写等待启用异步检查；普通read解码器已读入的半帧正文不会被再次当作头部解析。

## 服务端终止收尾及最终资格

Failure写出后，服务端每次最多丢弃64KiB在途正文，至多min(原超时,1000ms)等待发送者观察失败并关闭；避免立即abort在仍有未读上行正文时触发RST、使错误本身丢失。正常传输与任务期限不变，超时/取消仍有上限。无序RST若未送达完整错误，客户端仍只能报网络错误，不能猜测磁盘状态。

最终两套28项独立TLS、各19/19核心及九项业务回归通过，peer-close-r51-final-local-summary.json绑定最终CLI及源码输入。独立夹具中的立即半关闭/在途排空和普通read解码均保留5/receive严格要求；初始夹具失败记录保留。原生真实盘满与新部署包仍待验收。
