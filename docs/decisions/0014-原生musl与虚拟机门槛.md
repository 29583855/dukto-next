# 原生 musl 验证与既有虚拟机失败

日期：2026-11-05。状态：新增手动工作流，实际结果以 Actions 及归档报告为准。

Alpine 3.24.1 虚拟机中的 3b8bf4a 冻结输入已完成独立编译，18/18 CTest 通过，11 组协议测试中 7 组通过、4 组失败。失败为 task-items 原 90 秒、16 通道上传自动重试总期限、单通道会话过期恢复原 90 秒，以及源变化故障原 30 秒门槛。CLI 和 GUI 的前后摘要相同。原报告和失败保持，不改原脚本、超时、测试数据或虚拟机输入。

虚拟机只有一个虚拟 CPU，采用 QEMU TCG。这个事实可能影响吞吐和时限，不能由此断定失败必定来自模拟器，也不能把应用错误排除。为取得独立证据，新增 linux-musl.yml：在 GitHub Ubuntu 原生 x86_64 CPU 上运行 Alpine 用户空间，使用相同原协议脚本及门槛，编译 C++14 GUI、CLI 和全部验证目标。容器共享宿主 Linux 内核，没有模拟另一种 CPU。

镜像先拉取 alpine:3.24.1，记录实际 RepoDigest，再用该 digest 构建验证环境；记录依赖版本、编译器、Qt、OpenSSL、CPU、容器工具版本及 Git 提交。依赖安装由镜像构建执行，全部编译和测试以宿主 UID/GID 对应的普通用户执行，防止 root 绕过权限检查。源码只读挂载，输出单独挂载；前后逐文件摘要复核，原虚拟机和长期测试目录不挂载、不改动。

TLS、19 项核心测试和 30 组协议分别运行，核心失败时后续协议继续，任何失败仍使 job 失败；核心证据在协议开始前上传。Qt Quick 使用 offscreen 与软件渲染，结果只证明相应测试范围，不代表 X11/Wayland 原生桌面、独立包、干净系统、物理局域网或 24 小时资格。

本工作流首次运行与修正后的每次运行分别保留；新平台成功不覆盖原虚拟机失败，也不以增加超时取得通过。只有原报告实际完整结束并核对输入后，才能更新计划中的这个验证子项。
