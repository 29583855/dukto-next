# 跳过结果只读分页核验

日期：2026-11-06

状态：只读查询与客户端结果校验已实现。公开 skip 仍关闭；本决策不表示可向用户选择 skip，也不表示完整跳过流程已交付。

## 范围

`transferItems()` 可分页核验既有 v3/v4 跳过接收证据，并从 SQLite 快照按需读取清单项目。结果区分已跳过、提交中和仍计划处理等状态；跳过项附带对应的跳过子树根。历史原件缺失、损坏或与清单不符时不伪造成功结果。

客户端逐页解析时校验策略与逐项结果的一致性：非 skip 策略不能返回跳过状态；跳过状态须有非零且合法的根；跳过根必须符合目标路径；其他状态不能携带跳过根。违反约束的响应作为完整性错误处理。

## 不变量

- 查询只读，不改写跳过日志、接收日志、任务记录或目标文件。
- 每次仅解析当前页，不把完整清单或所有逐项结果累计到内存。
- 兼容既有 v3/v4 跳过日志格式；对缺少可信证据的条目返回未确认或拒绝，不能补写历史。
- 本查询按页读取，不承诺多个页面之间或整棵目录范围的原子快照。
- 继续使用 C++14、Qt5 和既有 GUI/CLI 共用客户端实现。

## 验证

Windows UCRT/MSVC 各完成 23/23 核心 CTest，新增 `transfer-items-tests` 各 10/10；任务条目、条目失败及上传回执三项实际客户端/服务集成在两工具链均通过。Linux glibc 与 Alpine 原生验证另行记录；任何未完成或失败结果不由 Windows 结果替代。

## 明确未完成

本阶段没有开放服务端策略协商，没有新增 GUI/CLI skip 选择，没有完成跳过源文件删除后的历史恢复，也没有证明传输全目录的一致快照。完整公开 skip 必须继续经过双方协商、逐项实际处置、计量与完成回执验证后才能开放。
