# Windows私有状态读取共享冲突有界重试

日期：2026-11-06。实现保持C++14/Qt5，Linux和macOS仍使用原有安全openat读取。

R85原生Windows运行42188307361在download/root-reconfigure故障注入中返回错误5/read/Windows32，原测试预期3或4且在原目标后置断言前中止。该运行保持failure，不能用后续通过覆盖。受控本机复现证明：另一个进程或线程持有同一私有配置的DELETE访问时，原SourceFile的非删除共享读取会立即返回ERROR_SHARING_VIOLATION。此复现尚不足以确定R85原运行中被占用的具体路径及句柄来源，R85根因仍未证明。

SourceFile新增明确的OpenPolicy::PrivateState，只由PrivateStore的有界小文件read和数据库validateFile使用。Windows在CreateFileW返回错误32时重试，最多21次、累计等待预算500毫秒，每次最多25毫秒。错误5、文件缺失、目录、链接、权限和其他错误不因此变成可恢复共享冲突。持续占用返回错误5/read-busy，保留Windows错误码和尝试次数。

普通传输源默认OpenPolicy::Immediate，保持原即时失败及不共享删除的规则。私有状态重试仍不开放FILE_SHARE_DELETE；已打开对象的普通文件类型、原生身份、所有者及ACL均由原有检查验证，等待后还重新核对私有根ACL。成功读取必须完整且不超过原预算；无空配置、旧缓存或复制替代。Windows瞬时原子配置改配可在句柄释放后读取新配置，随后传输仍检查授权和共享根是否变化。

验收包含两个PrivateStore入口各瞬时释放、永久占用和8轮重复的真实原生DELETE句柄用例；默认传输源仍即时拒绝，原文、大小、临时文件和句柄计数均检查。另由独立进程持有自有配置DELETE句柄，公开CLI实际读取6个场景，持续占用须500毫秒后明确失败，释放后同一配置可再读。双向源变化、撤权、根改配、私有状态权限、文件替换、覆盖占用、证书凭据、skip及恢复回归分别保存原件。

该修复解决已独立复现的私有配置瞬时占用问题。R85原云端根因、物理网络、长期资源、完整GUI交互及正式发布仍须原证据，不因本项局部通过而视为完成。
