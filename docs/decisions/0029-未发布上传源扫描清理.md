# 未发布上传源扫描清理

日期：2026-11-07。状态：实现、双Windows专项及独立Ubuntu隔离验证通过；四平台完整CI和新包另验。

上传请求在网络创建任务前，先冻结源清单。扫描时正常异常会回收本次创建的库，但进程直接退出不能执行析构。R116在开始扫描前持久保存`upload-source-请求.scan.json`，包含请求/主体/路径绑定、UTC创建秒数、私有根原生身份及SQLite原生文件身份。冻结记录发布后移除扫描凭据，冻结清单与幂等记录继续保留。

新增三平台命令：

```text
dukto-cli client scan-cleanup preview --state-directory <客户端状态父目录> --request-id <规范UUID> --json
dukto-cli client scan-cleanup run --state-directory <客户端状态父目录> --request-id <规范UUID> --json
```

退出使用同一`transfers`状态根的GUI、CLI和服务后执行。核心要求状态根原生独占维护锁，并取得扫描及数据库锁；不等待活动进程。只接受单个规范请求UUID，不接受文件路径、任务ID或分页参数。

未发布扫描默认保留604800秒（七天）。未到期返回`retained`；预览到期项返回`pending-cleanup`及库/回滚日志合计字节数，读取不打开SQLite、不修改正文或热日志。执行使用SQLite自身恢复DELETE模式热回滚日志，缓存1MiB纳入共享授信，先申请额度再注册Qt连接，额度失败不遗留连接，库与旁路合计最多256MiB；不手工删除journal、WAL或shm。WAL/shm、架构损坏、不安全权限和链接均拒绝。

在删除前原子同步更新扫描凭据为`cleaning`。关闭SQLite后再次核对原生文件身份，再通过固定父句柄按身份删除普通库，随后移除凭据。删除前、删除后进程退出或取消均可重入；已经删除后出现的同名新对象身份不符时保留并报错。已有清理意图可继续执行，不受时钟回拨影响。Windows原生删除、POSIX固定父描述符、路径核验和父目录同步沿用已有原生实现；不声称POSIX具备抵抗任意外部改名的通用文件系统CAS。

已有冻结记录或`upload-request-请求.json`时返回`preserved-published`，不删除清单、上传/下载幂等或处置记录。缺少扫描凭据的旧库返回`preserved-unknown`；不存在库与凭据返回`absent`。创建SQLite后、写入凭据前退出的极小窗口及历史未知库仍不能依据名称推定所有权。凭据存在而库缺失但无删除意图时拒绝。清理完成后，同一尚未发布请求可以重新扫描源并开始上传。

验证覆盖真实子进程扫描退出和热journal、保留期、预览原字节、删除前后退出/取消恢复、同名替换对象、坏凭据/主体、原生链接、WAL/shm拒绝、损坏SQLite的连接/缓存授信归还、冻结/幂等记录保护及实际CLI。Windows账号缺少原生符号链接权限时明确记录该行跳过，不能记为已通过；POSIX与Mac按实际原件另验。

这是未发布源扫描缓存的一项维护功能。全局自动GC、已发布任务元数据保留/回收、历史256MiB总预算及活动清单总磁盘配额继续按完整计划实施。
