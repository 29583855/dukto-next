`DispositionJournal` 记录调用者已经核实的历史结果。它绑定任务 UUID、冻结强清单的完整摘要及严格策略名称，以独占任务锁、SQLite FULL 同步事务保存每一项。已有日志只验证，不补建损坏的表或将缺失记录推断为成功。默认、失败和覆盖的公开行为保持各自原契约；未完成的 skip 入口继续明确拒绝。

每项包含冻结清单条目、实际相对目标、`copied` 或 `skipped`。顺序必须连续，重复项必须与原始记录逐字段相同。直接跳过以自身为根；跳过目录的每个后代必须沿用该根和目录映射，不能恢复成复制或更换根。父记录按唯一源路径索引有界读取，没有逐级递归或驻留整棵目录树。目录重命名后，子项仍必须位于已记录的父目录。

汇总按最多 100 项分页，重新核对每行、源索引、规范编码和总量；非正 ID 也单独拒绝，不能被分页起点遗漏。读取规范记录最多 65,537 字节，源路径最多 4,097 字符，损坏字段不能直接引起整字段分配。SQLite 主缓存使用 1 MiB 授信，数据库页数限制对应 256 MiB；这不等于整个任务、回滚文件或所有模型缓存的全局预算已经完成。

完成摘要以绑定和每项规范 JSON 的四字节大端长度前缀进行流式 SHA-256。分别报告复制和跳过的文件数、目录数、字节数以及未执行数。跳过字节不能计入已复制、已接收、已校验正文或网络发送量。缺项时只能生成显式不完整汇总，不能发布最终结果。固定摘要向量由 Python 标准库独立生成并与两套 C++14 构建核对。

该组件不观察目标文件系统，不证明真实写入、原生目标身份或授权，也不负责决定是否安全跳过。后续接入必须与原接收日志绑定的根身份和落盘证据一起使用；完成消息丢失后仍需核对原结果，不得重新根据当前同名文件猜测决定。失败和未执行原因继续来自原任务及逐项错误证据，不能从本日志没有 `copied` 推断它们。
