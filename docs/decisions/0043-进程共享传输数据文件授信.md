# 进程共享传输数据文件授信

日期：2026-11-06。关联：计划6.4、R08和0007有限任务排队。

## 范围与约束

扫描、摘要计算、R6发送、新版单/多通道发送、R6临时接收、新版持久接收及Windows覆盖提交共同使用每进程32个`DataFileCredit`。打开数据文件之前申请；资源耗尽返回4/`file-budget`，不在持有其他文件或通道期间等待，避免形成资源等待环。任务仍遵守原有准入、取消、恢复和完整性要求。

这是传输正文文件的额度。目录遍历、Windows属性/删除句柄、Qt/SQLite元数据文件及私有配置不属于这个32文件计数。它不等于全进程OS句柄数。私有配置仍按PrivateStore安全性和有界长度读取，不能在传输文件饱和时使取消或配置校验失去可用性；这些路径的独立总预算继续实施。

## 生命周期与POSIX核验

`SourceFile`仅普通传输策略取得额度，PrivateState保留已有安全校验及Windows共享冲突有界等待。额度成员先声明，确保文件先关闭再归还；构造异常自动归还。

`IncomingFile`和持久`ReceiveFile`在创建/重开前取得额度，正常退出和异常退栈均在设备关闭后归还。IncomingFile提交后到对象销毁可能短暂保留已关闭文件的额度，是保守计量。持久文件切换及关闭使用原有Cursor生命周期。

Windows覆盖提交的固定源句柄具备GENERIC_READ，也必须申请额度；只读取属性的路径复核句柄单独管理。正常、取消和共享冲突异常均先关闭固定源再归还。持久接收先关闭原设备，才申请覆盖固定源的额度。

POSIX原来的路径核验会再打开一次数据文件。现使用固定父目录上的`fstatat(AT_SYMLINK_NOFOLLOW)`，拒绝非法分量、链接、目录、FIFO及其他特殊项；仍复查父目录身份。SourceFile对已打开对象与路径采用完全相同的dev/inode/size/纳秒mtime/ctime序列化；verifyObject保持对象身份语义，持久接收仍核对dev/inode。元数据快照不声称提供文件系统路径CAS；正文始终从已固定设备读取，既有最终摘要/恢复验证继续执行。

## 验证与剩余范围

新增64线程竞争、16真实源加16真实R6临时文件、饱和时私有读取、构造失败/析构归还，以及持久接收rename/overwrite在32边界拒绝、同日志恢复和完成提交用例。POSIX直接测试固定目录元数据读取的非法名字、链接、FIFO、目录、缺项及父目录替换；已有源内容变化和源路径替换用例继续执行。

实际平台结果及首次失败以对应R90验证回执为准，本文不预先授予通过资格。全部缓存分类预算、非数据句柄预算、多任务公平性、磁盘/WAL及长时稳定性仍需独立验收，R08和整体交付保持未完成。
