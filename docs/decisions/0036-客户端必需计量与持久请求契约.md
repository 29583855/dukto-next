# 客户端必需计量与持久请求契约

日期：2026-11-06

服务端支持 `disposition-progress-v1` 后，普通 GUI/CLI 共用的 RemoteClient 声明此能力。新请求仅在服务同时提供处置进度、字节进度、处置摘要三项能力时启用必需计量。旧请求保持原契约；客户端不会因重连到新服务而升级已存在的请求。

## 持久绑定

新上传/下载请求在创建任务之前写入本地 version=3 绑定，显式保存 `progress=disposition-v1` 和冲突策略；服务器的 version=3 任务规格采用同一契约。重试时精确核对绑定原字节。损坏绑定或改变目标、清单、策略返回完整性错误6；服务缺少原新请求必需能力时返回配置错误2，拒绝发生在创建请求之前。

旧上传绑定version=1、旧下载绑定version=1/2继续使用原六字段字节进度。首次连接缺少任一新能力的服务仍可创建旧契约请求，后来服务升级也保持原格式。此兼容不授权新契约降级。

## 实际进度与完成确认

客户端在初始、就绪和最终任务响应核对 accountingVersion。清单尚未绑定时不允许非零计量或处置字段；绑定后使用固定十计数验证规范数字、守恒、上限及已处理量。复制策略中跳过和丢弃计数必须为零。

本轮传输的最终十计数必须逐字段等于实际接收或已校验远端进度快照，并且复制/跳过字节和文件/目录数量必须等于本机独立处置摘要。客户端不会用最终成功回包补造本轮进度。历史重试重新核验当前内容和原接收证据，再核对双方摘要；历史计量仍与本机处置交叉核对。

必需计量下载缺少或不完整的本机处置日志返回完整性错误，原件保持不变。旧契约下载仍可在完整原接收证据支持下重建派生处置。上传发送端缺项仍可依据服务端分页接收证据恢复，恢复结果必须与独立摘要及计量一致。

## 有界资源与公开范围

网络进度仍是固定十三字段，每份计量快照仅固定十字段；请求绑定为一份有界JSON。清单和逐项处置保存在SQLite并分页读取，客户端不累计全部条目。此变更继续遵循 C++14 和 Qt5。

本次只接通必需计量。公开 skip 选项、逐项跳过协商及其实际目标差异仍保持未启用，不能据此宣称完整跳过功能已交付。实际构建与回归结果由本轮验证回执记录。
