# 有限任务排队与公平授信

日期：2026-11-05。范围：同一进程内的新版 TLS 服务监听器。实现及平台验证状态以主计划、实施进度及对应二进制摘要为准。

服务共用一个任务调度器，最多同时执行 2 个任务、登记 100 个等待项、授信 16 条数据通道。上传和下载使用相同额度。每个任务请求 1/2/4/8/16 档，按剩余通道选择不高于请求值的最大合法档位；例如一个任务已占 8 条，另一个请求 16 条时实际获准 8 条。客户端输出 `transfer-admitted` 事件中的实际 `channels`，后续数据票据必须与授信一致。

等待队列按服务私有目录与认证主体区分所有者，同主体保持 FIFO，不同主体按轮次启动。轮到的主体启动一个任务后，仍有等待任务时移到轮次末尾；取消或断开的等待项清除其空轮次。已执行任务不抢占、不动态缩减通道，也不承诺按字节或时长均分带宽。先执行的 16 通道任务可以暂时占满通道，之后的任务等待其释放。

授信覆盖服务端扫描或清单交换、数据传输、校验和完成确认。等待下载不扫描源目录，等待上传不接收强清单，避免大量等待任务同时打开这些数据库和数据工作线程。上传客户端为确定源内容身份，仍须先扫描本地源文件，然后才创建服务端任务；本项不表示客户端源扫描也已纳入服务端调度器。

授信由控制执行者和数据状态共享持有，最后一个持有者退出才归还。控制连接退出时若数据工作者仍清理，不会提前重新授出相同额度。既有数据连接、应用内存和 SQLite 分类限额继续独立生效；控制查询仍使用保留额度。100 是等待结构硬上界，TLS 连接或内存上限可能更早拒绝，不保证任何主机都能建立 100 条等待连接。

HelloAck 声明能力 `task-admission-v1`。支持该能力的新客户端在 CreateUpload/CreateDownload 中增加精确布尔字段 `queue: true`。服务先回复正常 Task 对象，状态 `queued` 并声明 `needManifest`，之后每约 250ms 发送相同关联序号的 TaskState 心跳，内容恰为任务 UUID 和 `state: queued`。心跳仅表示仍在等待，不能当作文件确认或任务完成。

获准后服务发送类型 51（TaskAdmitted），内容恰为 `taskId`、布尔 `needManifest`、规范十进制字符串 `channels`。客户端严格校验关联序号、任务、字段、档位及后续数据票据，再上传清单或等待下载就绪。未声明能力的旧服务仍沿原流程访问；不发送 `queue` 的旧客户端只能立即取得额度，繁忙时返回退出码 4、阶段 `scheduler`，不绕过已有等待者。实际旧版二进制互通结果单独记录。

等待使用非阻塞授信尝试，期间处理网络断开、GUI 断开、持久暂停/取消、撤权、共享根变化及认证会话到期。等待时长可以超过单帧网络超时，但不会刷新认证期限。获准后在扫描或清单交换前再次检查授权、共享根和停止意图。

未绑定清单的排队任务允许暂停及继续；已进入未完成扫描的任务仍按原约束允许取消。等待中进程退出、连接丢失或到期保留原任务为可恢复中断；新连接查询取得执行租约后，能将遗留 `queued`/`scanning` 归一为 `interrupted`。继续复用原任务和请求 UUID，重新核对源内容或保存目录。队列满或旧客户端繁忙拒绝时，保留可恢复记录，可用原请求 ID 重试或在任务列表中找回。

GUI 沿用服务器页的任务区域，中文显示“排队等待”及提示，原查询、暂停、继续、取消入口继续可用；不显示其他主体、队列位置或不可保证的开始时间。CLI 无需增加等待开关，能力协商后自动等待，三平台使用同一核心与参数语义。

本项没有完成跨进程统一资源预算、R6 与新版统一调度、所有元数据/模型/分配器额度、磁盘授信及安全回收。完整主窗口、物理局域网、多网卡和各平台原生验收仍分别保留，不能用本机 TLS 专项或独立服务器面板替代。
