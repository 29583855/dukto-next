# Windows 目标预约创建的瞬时拒绝

日期：2026-11-06。使用 C++14、Qt5，原版 `Dukto/` 不变。

## 已观察的问题

原 Windows CI 的八线程独占提交测试偶发返回磁盘错误，发生在 `TargetReservation` 创建阶段，尚未执行最终改名。诊断后的原生 128 轮保留了两轮失败；本机两套工具链各 64 轮又分别复现了四轮和一轮失败。后者均为 `QLockFile::PermissionError`，Qt 返回后观察到的 Windows 错误值为 `ERROR_FILE_NOT_FOUND`。

Qt 5.15.2 的 Windows 实现先以 `CREATE_NEW` 创建锁；遇到 `ERROR_ACCESS_DENIED` 时，再检查路径是否存在，分别归类为活动锁或权限错误。竞争执行者可以在这两次操作之间释放锁。观察到的 `GetLastError()` 不是原始 `CreateFileW` 的返回值，因此只作为附加诊断，不能据此声称已捕获原生调用的错误码。真实 ACL 拒绝也会产生同一 Qt 分类。

## 实现范围

Windows 仅对 `PermissionError` 进行有界重试，间隔至多 10ms，等待预算 100ms，最多 11 次尝试。剩余预算只计算一次，非正值直接退出，避免负数转换为无符号休眠时间。操作系统调度和文件系统调用耗时不在休眠预算的硬实时保证内。

活动锁的 `LockFailedError` 立即返回未取得预约；`UnknownError` 不重试。持续权限拒绝最终仍返回磁盘错误 5、`conflict` 阶段。实现不删除其他执行者的锁、不放宽 ACL、不绕过父目录固定或原子提交检查。POSIX 仍执行原来的一次 `tryLock(0)`。

## 回归证据

Windows 使用自有临时目录的真实 DACL，只拒绝 `FILE_ADD_FILE`：短暂拒绝约 40ms 后恢复必须在预算内成功；持续拒绝必须保留错误分类。测试等待工作线程并恢复原 DACL 与继承保护位，再执行结果断言。未修复实现的两条失败原件保留。

原八线程压力测试继续核对全部内容、唯一名称、重复提交拒绝和临时文件清理；各轮文本与 JUnit、二进制及输入 SHA 独立保存。跨进程活动预约、大小写别名与无关用户文件保护由现有真实进程测试继续覆盖。后续 CI 的资格按实际提交和原报告记录。

此修复不解决 Intel Mac 凭据轮换或预览包检查点的首次失败，也不表示公开 skip、全部交互、长期资源和最终发布验收完成。
