# 接收文本分页与完整复制

日期：2026-11-06。C++14/Qt5；R93文本共享额度继续有效。

R93保留完整正文及额度，但收到的文本仍一次放入Qt Quick TextArea。正文上限8 MiB不能限制QTextDocument的段落数量：原代码在新测试中仅收到2,049个换行，就建立2,050个文档段落。因此需要同时限制实际布局的字符和段落，而不是截断接收内容或放宽内存门槛。

## 行为

控制器保留完整原文与共享额度，建立有限页索引。每页最多16,384个UTF-16码元、512个显式换行/段落分隔符，不拆Unicode代理对。QML只接收当前页字符串，最多513个段落；正文很长但没有换行时也按字符上限分页。页数索引随8 MiB协议上限有界，大量单字节换行的最大样本为16,384页。

普通短文本保留原布局；多页文本出现上一页、页码和下一页。选择文字后复制当前选区，未选择时“复制全文”复制控制器保存的全部原文，包含未显示页面和原始换行/NUL。历史重新打开建立同样的页索引。翻页、查看和复制不会更改接收内容或协议，不以页面文本替代持久正文。

新接收/历史打开先取得额度，新旧正文及页索引保留到QML同步替换结束。关闭后先清空文本和页索引，再归还额度。QML监听无正文的打开/换页通知，避免把全部原文转换为JavaScript字符串和布局文档；C++原有完成通知保持兼容。

## 验证

原R93代码加同一新测试，2,049换行产生2,050段，明确失败；新实现同样输入最多513段并通过。真实R6入站样本覆盖8 MiB换行、8 MiB长单行、16,384边界代理对、CR/LF/NUL和Unicode段落分隔符。生产QML实际点击翻页、返回、尾页和复制全文，并关闭后从同一历史重新打开；完整剪贴板内容逐值核对。控制器另遍历最大正文的全部页面、逐页核验边界、拼回并与原始UTF-8逐字节比较，避免只测试第一页。

独立GUI进程由现有process_sampling采样RSS/私有内存，继续使用原512 MiB门槛。原QtTest XML、文本日志及业务摘要全部保存。内存峰值包含测试夹具、Qt界面和完整复制缓冲；不能据此宣称所有应用内存都完成分类或真实系统剪贴板长期预算已验证。完整双Windows及原生CI分别记录，不用专项替代整套资格。

本项解决接收只读查看的段落放大。发送编辑器的大量粘贴、全局剪贴板生命周期、SQLite内部和其他模型缓存的完整分类、全平台长期资源与原生GUI仍是独立未完成要求。R93 Intel包的覆盖恢复失败也独立保留，不能由此项UI修复推定解决。

R93 ARM完整CI另暴露空文本进程未取得发送端采样：完整内容/退出码校验之后，因发送端峰值为空而使专项失败。新夹具对至少1 MiB正文仍强制要求两端真实采样；短内容每次保留采样是否取得及独立memoryQualified状态，未采到不填零值或宣称内存资格。所有已采到的值仍执行原512 MiB门槛，最大8 MiB样本与完整性校验均保持。R93原失败不改写为通过。
