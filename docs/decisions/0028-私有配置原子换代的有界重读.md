# 私有配置原子换代的有界重读

日期：2026-11-07。

`PrivateStore`用临时文件和原子替换发布配置。POSIX允许替换正在被读取的文件：读取句柄仍指向旧对象，而固定路径已指向新对象。原来直接复用普通传输源的严格校验，使合法的凭据、授权或共享配置更新也可能成为`6/read`完整性错误。

用精确R113源码的六个实际依赖对象，在独立Ubuntu目录验证：四个读取线程共读取8,000次，单一写入者原子更新500次；6,946次成功，1,054次`6/read`拒绝，没有混合正文或其他错误。这证明私有配置读取存在可重复的竞争；它不证明历史Mac失败中的每一条`6/read`都来自这个具体文件，原失败继续保留。

候选实现只修改私有小文件读取：

- 每次重新打开文件，核对固定根、所有者、私有权限、普通文件类型和调用方大小预算。
- 严格源校验发生`6/read`后，另核对固定父目录中的原生对象身份。只有路径已经指向另一个普通对象时才丢弃旧正文并重读。
- 最多五次。持续换代返回明确的`6/read-busy`，不无限循环。每次释放旧正文和句柄，读取预算仍至多1MiB；尝试次数边界不声称能中断阻塞中的原生文件系统调用。
- 同一原生对象被原地修改时立即保留原错误；目录替换、链接、特殊文件和不安全权限不能作为普通换代重试。
- 普通传输源的`verify`及`verifyObject`行为不变。Windows仍通过禁止删除共享与原有共享冲突预算控制换代，不新增路径替换重读。

验证按平台记录。双Windows已通过各两个完整核心/身份CTest，每套45个JUnit方法。独立Ubuntu已执行实际维护测试函数，1,024次读取与128次原子写入通过；随后四线程8,000次读取/500次更新全部成功，没有重试耗尽或混合正文。普通源被替换、原地修改、不安全权限及链接四个反例均按预期拒绝。Ubuntu候选程序测试前后摘要一致；本轮候选源码、实际函数与精确R113未改依赖对象分别绑定记录。跨平台完整CI和实际凭据轮换故障仍独立验收，不将局部复现当作历史Mac全部错误的唯一根因。此文不授予整个项目、历史失败或正式发布资格。
