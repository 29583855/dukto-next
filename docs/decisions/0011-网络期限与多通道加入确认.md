# 网络期限与多通道加入确认

日期：2026-11-05。状态：实现完成；各平台结果按固定源码和实际报告分别登记。

R6 接收使用用户配置的无进展期限。一次网络读取开始后，先检查取消，再尝试消费 Qt 或系统已经收到的有界数据；确实缺少数据时才检查期限。连接、每次读取和每次有界输出分别计时，本地扫描、目录创建与 SQLite 操作不消耗后续网络等待的期限。本地操作仍需响应取消，内存和 socket 缓冲上限不变。静默连接及不补齐帧的连接继续按原 5 秒配置失败，不通过放宽期限掩盖问题。

独立进程回归在发送前 8 字节后暂停本测试接收进程，将其余数据发至本机，再等待 6 秒恢复。旧 UCRT/MSVC 二进制均把正常文件与非法文本错误地报为网络超时；新版本须分别接收成功和报告 UTF-8 完整性错误，同时保留静默及部分帧停滞的超时行为。这个复现证明了特定调度条件下的缺陷；此前 GitHub Windows 异常帧失败未记录子样本和完整调度，不能据此断言那次失败的根因已被唯一证明。旧异常帧回归现在会在失败中保留样本名。

多数据通道的加入分为两个阶段：

1. 完成认证、任务和授权核对后，独占预约指定槽。重复或过期票据在组内工作者异常传播区之外拒绝，避免取消合法任务。
2. 数据连接完整写出 `Attached` 确认后，才将该槽公布为可调度，并开始观察传输组取消。控制线程必须等所有实际通道都就绪后访问目标和分配正文。

旧实现提前公布槽就绪。接收端立即发现同名目录时，会停止整组；尚在发送加入确认的数据连接因此先触发取消并中止 TLS，客户端可能先看到连接断开，覆盖服务器的真实冲突。固定旧 glibc 二进制的 16 次独立即时目录冲突中实际出现 4 次该误报；每次服务端所有连接及持久任务仍记录 `4/conflict`。新版回归重复 4/16 通道的即时目录冲突，独立核对客户端退出、每条服务连接原因、持久任务及原目标内容，不只检查最终文件是否存在。

这项调整不增加协议字段，不改变请求、强清单、主体和票据绑定。预约和就绪都是最多 16 个槽内的固定状态，不产生按文件数量增长的队列；原加入截止时间、帧大小、并发额度、取消和错误退出规则保留。

本决策不代表全套恢复、全部冲突策略、物理局域网性能、24 小时稳定性或正式发布资格已完成。历史失败保留，后续成功按新的二进制摘要和报告登记。
