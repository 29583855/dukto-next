# 证书续期与显式信任迁移

日期：2026-11-05。核心、GUI、三平台共用 CLI 已实现；Windows 的双向恢复和生产 QML 操作已取得实际证据，跨平台新回归另行记录。正式发布资格不由本子项推导。

## 续期与运行中的服务

`serve info` 公开服务器 UUID、完整 SHA-256 指纹、SAN、起止时间、证书状态和剩余秒数；有效证书不足30天时 `expiringSoon=true`。过期或尚未生效的证书仍可查看与显式续期，普通服务启动、共享管理与网络校验继续拒绝无效期限。损坏材料、私钥不匹配和不安全私有文件始终拒绝，不能以“续期”为名自动重建服务器身份。

`serve renew --fingerprint <当前指纹> [--certificate-days 1..825] [--server-name <名称> ...]` 使用与初始化相同的跨进程身份锁。锁内核对当前指纹，生成新的 RSA3072 私钥和 SHA256 自签证书，保留服务器 UUID；名称未指定时沿用全部原 SAN。新材料在内存中生成并验证成功后，经原有受保护存储的原子替换发布。任何前置条件或生成失败均保留原记录，两个进程使用同一旧指纹时只允许一个更新。默认有效期365天。

授权、配对凭据、共享配置和任务数据库均不被续期改写。现有监听器及其工作线程持有不可变的旧证书快照，续期不会在活动传输中混用新旧证书；全部使用此状态目录的监听器须停止并重新创建后才采用新证书。允许同目录多个监听器，不增加单监听器限制，也不声称有尚未实现的全进程停服锁。`serve renew` 始终返回 `restartRequired=true`，表示须检查并重建运行实例，并非检测到全部外部进程的结果。

监听器公开信息明确 `certificateSource=listener-snapshot`、当前运行指纹、磁盘指纹及其是否不同。`serve info` 的 `certificateSource=stored` 表示磁盘材料，不能将其解释为正在监听的证书。GUI续期后显示磁盘新指纹及重启提示；重新启动后显示实际运行身份。管理员应选择合适的停服时机；任务恢复仍按原任务/请求和内容身份执行。

## 客户端迁移

先通过受信任渠道核对服务器的新旧指纹，再执行：

```sh
dukto-cli profile-info --profile default --state-directory <客户端状态目录> --json
dukto-cli trust --profile default --old-fingerprint <旧指纹> --fingerprint <新指纹> --state-directory <客户端状态目录> --json
```

`profile-info` 只输出公开目标、资料别名、服务/客户端身份、指纹及配对/待轮换状态，不发起网络连接，不包含秘密。

`trust` 持有与资料建立、配对保存及访问凭据轮换相同的资料锁，严格解码两个不同的32字节指纹。当前资料必须已配对且其指纹等于明确提供的旧值，或已等于新值以支持丢失本地确认后的幂等重试。随后使用新指纹与原目标/名称建立正常 TLS 连接，核对原服务器 UUID，认证原主体和访问凭据，并完成正常关闭；全部成功后才原子保存新指纹。目标、名称、端口、UUID和秘密都不改变。错误指纹、证书期限/主机名错误、另一服务、撤权、断网或取消均不能覆盖原信任；没有自动接受网络证书或回退旧 pin 的路径。

若访问凭据轮换本来就处于待确认状态，迁移先验证已保存的新秘密；只在明确的 `4/auth` 拒绝后才验证已保存的旧秘密。TLS、网络、服务 UUID 或关闭错误不得触发此回退。迁移保留两份原秘密和待轮换检查点，不借证书迁移偷偷完成远程轮换；完成指纹迁移后仍须显式执行 `rotate` 确认原轮换。

GUI 在“连接与文件”页折叠展示资料指纹迁移，在“本机共享”页显示证书期限并折叠展示续期。用户能查看当前公开指纹、输入核对值并明确执行；网络错误不能自动触发信任操作。两个入口直接调用与 CLI 相同的核心，不启动辅助 CLI。

## 验证与边界

新增身份单测验证错误前置条件/锁占用不改原文件、生成新私钥且保留 UUID/SAN、运行与磁盘快照区别、损坏拒绝和公开结果无秘密。SAN比较按类型排序，不能将等价名称的容器枚举顺序当成协议要求；初次过严顺序断言失败原报告保留。

`certificate_lifecycle_integration.py` 在真实独立服务/客户端中，对上传、下载各创建实际4MiB持久检查点，4通道暂停，续期并重启，同资料显式迁移，8通道恢复并证明块复用，再用16通道重复相同请求验证无副本；原90秒恢复期限不变。额外覆盖旧监听器不提前采用新证书、错误新旧指纹/错误服务UUID不改信任、待轮换两种远端状态、撤销、独立 OpenSSL 的真实过期/未来证书及两个续期进程竞争。OpenSSL CA说明文字被测试夹具裁成规范 PEM，生产字符串预算不放宽，初次夹具失败保留。

生产 QML 专项通过真实鼠标点击续期和迁移按钮，检查确认状态、期限提示、重启前后认证及原主体/修订保留，并保存截图。新专项已进入共同 CI 和 Windows 验证入口。运行记录、平台范围与剩余失败以计划进度为准。

本实现不提供 CA 签发证书导入、无人值守自动信任、证书私钥导出或运行中热替换。完整三平台主窗口/原生交互、长测、外部部署、签名公证和正式发布继续按总计划验收。
