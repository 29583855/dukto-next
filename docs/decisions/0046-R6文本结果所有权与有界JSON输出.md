# R6文本结果所有权与有界JSON输出

日期：2026-11-06。语言为C++14，GUI与独立CLI共用Qt5核心。

R6文本最多8 MiB。先前工作线程的临时额度不能覆盖排队信号、显示内容及历史重新打开的完整存活期；CLI将整份JSON编码后又转换为QString，控制字符转义可使临时正文显著放大。此次处理这一具体边界，全部缓存分类及Qt文档内部预算仍单独验收。

## 结果所有权

增加注册为Qt元类型的LegacyResult，携带只读JSON和共享BufferCredit。发送在工作线程开始前申请额度；接收在声明核验后、正文reserve之前申请。额度为声明UTF-8字节数的十倍加64 KiB，使用现有120 MiB数据额度，不能借用8 MiB控制保留。该保守授信覆盖已知UTF-8、UTF-16、JSON及校验暂存，不能解释为进程RSS或QTextDocument内存的严格上限。

排队信号、接收方及显示内容共享同一个令牌。结果先销毁JSON再归还额度；赋值用copy-swap持有新旧结果直到交换完成。错误路径清空输入，不保留无正文的文本额度。GUI替换显示时保留旧令牌直到同步替换结束，关闭文本框先清空正文再归还，重复关闭安全。重新打开历史前先检查存储长度并授信，失败保留原显示。

## CLI输出与完整文本

JSON直接写UTF-8；text字段分成最多4096个UTF-16码元的小段交给Qt转义，不拆代理对，避免分配整份最多六倍膨胀的JSON及其UTF-16副本。元数据保留，text键移到最后，JSON语义及完整值保持。普通输出及JSON的设备写失败统一返回磁盘错误5，不能被后续成功退出码覆盖。

最大文本实测揭示Qt5无显式长度的UTF-8转换在NUL处截断。文本校验和接收结果改用constData与明确字节长度，合法UTF-8中的NUL完整保留；原有无效UTF-8及超限拒绝仍须回归。

## 验证及边界

新增核心测试在工作线程结束、QSignalSpy保存两份结果、复制及释放后逐步核对额度；满额时发送不能开始，接收不能分配正文。Controller测试覆盖显示、历史、满额错误及重复释放。真实CLI专项收发8 MiB NUL/控制字符并解析约48 MiB JSON，逐字节与SHA-256核对；另测4096码元代理对边界、空文本、只声明超限长度及三平台通用只读stdout句柄写失败。进程资源采样复用既有512 MiB门槛，测试进程内存不算入被测CLI。

首次夹具遗漏R6文本哨兵的第19字节NUL，原失败保留后修正夹具；最大文本首次遇到生产转换缺陷的失败也保留。后续完整双Windows、原生CI及包结果必须按精确源码分别记录，不能用局部成功覆盖历史失败。
