# 剪贴板可用状态与传输进度解耦

日期：2026-11-07。C++14、Qt5。范围是避免界面查询反复读取剪贴板正文；系统剪贴板和完整编辑器的内存预算仍单独验收。

原来的`clipboardAvailable`属性与传输进度共用`stateChanged`通知，getter每次调用`QClipboard::text()`。生产QML的发送菜单打开时，100次状态通知让隔离剪贴板的正文读取次数由15增至115。失败发生在真实菜单已打开、按钮可用之后；原编译和Qt失败日志保留，不将其当作夹具准备失败。

控制器现在只缓存“正文是否为空”的布尔值，在初始化和剪贴板实际变化时刷新，并以独立通知更新界面。频繁的进度查询只返回布尔值，不请求正文，也不缓存一份待发送正文。显式点击发送时继续重新读取最新文本一次，交给既有UTF-8上限检查和临时授信逻辑，不能发送旧正文。

回归使用隔离的offscreen剪贴板和带读取计数的真实`QMimeData`文本路径，运行生产QML菜单：进度通知不得新增正文读取，清空后按钮必须禁用，替换文本后必须启用，实际点击发送到独立TCP接收端的正文必须完全一致，并检查显式发送只新增一次正文读取。原实现失败和修正后各工具链结果分开保存，最终资格以严格回执及其原始日志为准。

该计数证明的是正文请求次数，不是外部系统剪贴板分配峰值的测量。初始化和实际变化的系统读取仍可能物化外部正文；超大剪贴板的读取前限制、OS生命周期、编辑器粘贴/撤销/布局及完整共享预算继续未完成。R98冻结CLI的长期测试不受此次GUI属性修改影响，旧R99原生CI也继续绑定其已提交源码。
