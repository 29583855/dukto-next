# 发送文本转换前检查与拒绝保留草稿

日期：2026-11-07。C++14、Qt5；这是发送入口的一个子项，不是全部GUI内存预算验收。

原入口先调用`QString::toUtf8()`，再由`LegacyJob`检查8 MiB协议上限并申请额度。巨大输入会先产生本不应存在的完整编码缓冲。QML还在调用后无条件关闭窗口：即使预算不足、地址错误或超限，草稿窗口也关闭。独立生产QML回归在原实现上实际复现了预算拒绝后关闭窗口，原失败报告保留。两次更早的夹具准备失败分别保留；补充窗口激活和实际焦点断言后，才取得上述产品失败，不能把准备失败当成产品缺陷证据。

## 行为及额度

发送前无分配扫描UTF-16，计算Qt默认UTF-8字节数；合法代理对占4字节，孤立代理码元与Qt默认转换一致。字符数已超过原8 MiB上限时立即拒绝，字节数超限也在完整编码之前拒绝。保留原有空文本、8 MiB ASCII、8 MiB中文和emoji能力；不截断内容、不降低协议上限、不改变R6帧。

转换前申请进程共用的数据类临时额度，覆盖Qt编码器按UTF-16码元预留的至多三倍字节容量及固定开销。原始QML文档和系统剪贴板的分配发生在此调用之前，不能计为本项已全面控制。任务仍单独申请既有`legacyTextCredit`，临时额度与任务额度短暂同时存在，任一不足时明确拒绝，不能借用控制保留额。临时令牌的生命周期覆盖局部请求和异常反馈；传入任务的缓冲由任务额度继续负责。

`sendText`返回是否真正启动。启动失败时QML保留编辑器、全文及目标输入，在窗口内显示原错误；用户可原稿重试。成功启动或主动关闭后清空编辑器缓存，收到文本的清空/释放次序继续保留。发送剪贴板的显式操作只读取一次正文，再复用相同检查；剪贴板可用状态查询和系统读取本身仍需完整预算。

## 验证要求与剩余范围

控制器测试使用独立TCP接收端逐字节核对真实R6帧，包含空值、三种最大正文、孤立代理码元、ASCII/中文各超过一字节，以及大输入拒绝；拒绝项不得建立连接，全部路径检查额度归还。生产QML实际点击发送，在额度耗尽时检查窗口和草稿保留、错误可见，解除占用后同一草稿重试并核对接收内容。最终收验身份与各平台结果见主计划和原报告；编译或专项通过不能代替三平台完整资格。

发送编辑器的大量粘贴/撤销/段落布局、QML传参前的副本、系统剪贴板生命周期、所有模型/SQLite内部缓存、句柄/线程预算及长期资源趋势继续未完成。正在运行的R98 CLI长测使用原冻结输入，本次GUI修改不改变其二进制或测试输入；长期结果仍只绑定各自实际身份。原版地址页另有实际点击/滚动观察，只证明所记录的Windows基线行为，不授予全部F04或三平台功能通过。
