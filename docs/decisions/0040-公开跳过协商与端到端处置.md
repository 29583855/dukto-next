# 公开跳过协商与端到端处置

日期：2026-11-06。语言为 C++14，桌面 Qt5 与独立 CLI 共用同一传输核心。

`skip` 保留接收端已有的同名普通文件或目录。目录重名时，原冻结清单中的整棵子树均记录为跳过，不向原目录合并内容。类型冲突、链接或其他不安全路径仍返回错误；“同名”不代表内容相同。

双方须在当前 Hello 声明 `conflict-skip-v1`、`byte-progress-v1`、`disposition-summary-v1` 和 `disposition-progress-v1`。创建请求须同时明确启用后三项。任一能力或字段缺失，在建任务及正文前拒绝，不能降级为重命名或覆盖。跳过任务只能采用版本三持久计量契约。其他策略保持原交换协议。

单通道逐项返回准备和最终处置。多通道在发布票据及启动工作线程前固定显式处置模式：每个有界窗口先确认接收端决定，跳过项没有正文任务；工作线程不能自行决定是否读取或传输源文件。最终发布时才出现的同名目标也受原子提交保护，其原生文件保持不变，已收到的正文计入丢弃量。

每项最终决定写入持久日志，跳过子树继承同一原始根 ID。收发双方核对完整处置摘要，任务计量分别记录复制、跳过、实际接收、确认、恢复及丢弃。逻辑已处理量包含跳过，GUI 和 CLI 必须显示真实复制与跳过量；不能以总处理字节声称全部复制。

上传沿用 R86 冻结源清单；已完成历史仅重新校验实际复制源。跳过源删除后，相同请求可继续核验原历史。上传缺少或截断发送回执时，按独立认证的有界接收明细恢复；矛盾证据拒绝。下载历史使用原接收、处置及冻结清单，只读核验；跳过源或跳过目标删除不要求重建目录。实际复制源丢失或变化仍拒绝完成确认。

公开入口为 CLI `upload/download --on-conflict skip` 和服务器页“跳过同名文件或目录”。恢复沿用原任务策略，改变并发数不会改变任务处置语义。R6 兼容模式保持原行为。

验收须包含真实 GUI/CLI 接线，双向 1/4/16 通道，跨页目录、空项、中文、大正文、原生目标保护、双方处置及计量交叉核对、源删除历史、能力降级和迟到冲突。中断、重启、资源及原生平台证据分别记录。物理网络提速、全局历史回收、长稳测试及正式签名/公证继续遵循主计划，不因本策略通过而视为全部交付完成。
