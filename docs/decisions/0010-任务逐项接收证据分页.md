# 任务逐项接收证据分页

日期：2026-11-05。实现范围：新版 rename/fail 的接收记录；确定本地逐项失败原因已增加可选扩展，边界见0012；完整 R03 的 skip/overwrite、全面失败处置/汇总及 R6 策略继续待实现。

`dukto-cli task-items --profile office --task <UUID> --state-directory <客户状态目录> --json` 查询一页。`--after <上一页after>` 继续，`--all` 逐页输出 JSONL。普通终端输出同样展示每项，不需要 GUI。GUI 在服务器的“任务”页提供“逐项明细”和“下一页”，一次保留一页，按当前资料与任务隔离显示。

上传查询服务端接收日志；下载查询本机接收日志，沿用原资料、请求和保存根绑定。另一台机器缺少下载日志时返回 `available:false` 和 `local-receipt-unavailable`，不能用服务器发送完成推断本机复制成功。查询仍要求服务器在线、当前身份有效及原共享权限有效。

能力名为 `task-items-v1`，不能从版本号推断。旧端没有该能力时，在新增请求发送前明确拒绝。沿已有 `TaskQuery`/`TaskState` 帧承载：`{taskId,itemsInfo:true}` 只读任务元信息；`{taskId,itemsAfter:"0"}` 仅提供上传的接收明细。字段数量、UUID 和十进制游标严格校验。这两类请求不取得执行租约、不修改任务修订或推进中断状态。每次响应前重新认证及核对当前共享根。客户端跨页重新连接、认证、关闭，避免大量页耗尽一个控制会话的请求数量上限。

单页最多 100 项，条目数组最多 `ControlLimit-2048` 字节，完整响应小于 64 KiB。游标按冻结强清单的连续 ID 前进，末页 `more:false`，不能空页自循环。SQLite 主键范围查询只读取当前页；不每次重新遍历整个强清单，不读取文件正文。每个只读库使用已支持的 1 MiB 缓存目标并计入控制授信，禁止 mmap，临时数据落盘。读事务固定这一页接收日志的视图，页之间允许活动任务继续前进；这不是整个批次跨多页的全局冻结快照。

页身份包含任务、方向、策略及强清单摘要；元数据与原任务总项数/字节数交叉核对。接收日志必须匹配任务、清单、目标根、原策略，单项规范信息也须与本页清单匹配。下载另核对服务器、客户主体、原请求、共享及本地根绑定。返回内容只含相对路径，不公开源绝对路径、凭据、原生文件身份或临时文件名。数据库连接只读，查询不修复、重建或创建缺失日志。

| 字段 | 含义 |
| --- | --- |
| `path` / `target` | 源清单相对路径 / 接收根内实际名称；尚无接收记录时 target 为空 |
| `disposition:copied` | 当时已完整校验、同步并提交到日志的项目 |
| `not-executed` | 尚无该项持久接收记录；不能据此断言之后也不会执行 |
| `planned` / `receiving` / `committing` | 准备 / 接收 / 提交意图；提交中不能推断最终结果 |
| `confirmedBytes` | 当时持久日志的检查点；查询未重新读取正文 |
| `taskState` / `taskError` | 服务器任务状态和批次错误码，不是每项失败原因；下载端本地拒绝后服务器任务可能为 interrupted |
| `currentContentVerified:false` | 查询历史证据，没有声称当前文件重新校验通过 |

已完成任务缺少接收日志时明确返回 `receive-journal-unavailable`；未绑定强清单时返回 `manifest-pending`。损坏、身份不匹配、权限失败或非法游标均不能伪造成成功空页。非法游标退出 2；主体无权访问退出 4；记录完整性错误退出 6。`available:false` 的查询可退出 0，调用方必须检查该字段，不能用查询退出码代替传输结果。

文件在传输后被修改或删除时，日志仍可提供历史证据；此入口不重新写入、恢复或重验文件。跨页汇总、每项失败归因、skip 的无正文处置和 overwrite 原子替换仍按 0009 的完整契约实现，不能把本查询子项标记为整个 R03 已完成。
