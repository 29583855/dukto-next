# Windows 覆盖共享占用与同任务恢复

日期：2026-11-06。

Windows 的原子替换会受外部文件句柄影响。独立 Win32 实验中，源文件被普通读取句柄占用返回错误 32，目标文件被读取句柄占用可返回错误 5；释放后原调用成功。这证明了一种可复现的故障机制，尚不能确定历史偶发错误 5 的具体占用者。

## 有界等待

覆盖保持同目录 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`。不先删除用户原件，不回退为复制，也不强制关闭外部句柄。父目录在整个操作中固定；已同步的接收临时文件按持久日志中的卷号与原生文件 ID 固定。读取句柄允许共享删除以完成原子改名，同时拒绝共享写入。

每次尝试重新核对源路径仍是已验证对象，并拒绝目录、设备、重解析点和只读目标。只有错误 5、32、33 允许等待：总等待预算 500ms、最多 21 次，间隔约 25ms；等待以 5ms 短间隔观察取消、授权与整个操作期限。预算约束本程序增加的等待，不能保证操作系统调用自身永不阻塞。错误保留实际系统码和尝试次数。

源路径重开核对和目标预约不能提供文件系统路径 CAS；同一用户的外部进程仍可改动名称。本项不扩大既有安全承诺。

## 恢复语义

占用预算耗尽返回磁盘错误 5，阶段为 `commit-busy`。服务任务保持 interrupted，接收文件日志保留 committing，暂存文件及原件保持供恢复核验。CLI 显式 `resume --task ...` 继续原请求与任务；新接收实例必须重新核对暂存文件身份、长度与 SHA-256，然后尝试原子发布。已发布但确认丢失时仍沿用原有提交证据核验。

只有该共享等待阶段保留为可恢复中断；完整性、目标类型和其它不可恢复错误沿用原有终态规则。失败和取消任务不因此重新激活，磁盘错误也不会进入只针对网络错误的自动重试。下载客户端的磁盘失败通过连接退出保留服务端中断；两方向均经真实 TLS 测试核验。

文件完成前，双方处置日志不得提前记 copied。恢复完成后，接收端与发送端记录必须与相同冻结清单、目标名称和实际正文一致。

## 验证

Windows 原生子进程持有真实读句柄，覆盖目标或源短暂占用、持续占用、取消、只读/目录变化、源替身、写入保护与目标移走。接收核心另验证 9MiB 数据已持久保存后恢复同一日志，不重传正文。

真实 TLS 专项覆盖 1/4/16 通道、上传/下载、短暂/持续占用，共 12 场景。它观察自有日志进入 committing 后继续持锁，检查原件，释放后核对同一任务、最终 SHA 及双端处置。首轮发现服务将占用写成 failed 而禁止 resume，原始失败日志保留；修正采用 interrupted，未放开 failed 状态转换。

另外修复跨平台传输测试的文件检查范围：临时扫描库是 `upload-<UUID>.sqlite`，持久发送处置是 `upload-disposition-<task>.sqlite`。检查只匹配前者及 SQLite 附属文件，并要求后者保留。原双 Mac 打包与 Alpine 运行的误判失败保留；新代码必须重新执行原生运行及迁移包验证。
