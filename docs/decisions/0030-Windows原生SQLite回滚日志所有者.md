# Windows 原生 SQLite 回滚日志所有者

日期：2026-11-07。状态：修复、本机双Windows完整核心及GitHub Windows两轮专项通过；其他原生回归另验。

R116 的 Windows 原生核心测试在真实热回滚日志处失败。隔离诊断两轮都返回 `4/identity`；补充诊断两轮均记录 `user=0 token-default=1 builtin-admins=1 elevated=1 other-allowed=0`。SQLite 在提升后的进程中使用令牌默认 Administrators 组作为新日志的所有者，继承的访问控制仍只允许当前用户。普通状态文件必须由当前用户所有的规则因此误拒绝了这类日志。原失败和诊断原件均保留，不能将测试未捕获异常直接描述成生产 GUI/CLI 崩溃。

新增 `PrivateStore::validateSqliteJournal()`，仅在持有独占维护锁时接受合法私有键和精确 `.sqlite-journal` 后缀。原生对象、固定私有根、普通文件以及校验前后的身份检查继续执行，日志还必须只有一个硬链接。

Windows 只有同时满足以下条件才接受组所有者：当前进程已经提升、文件所有者是内置 Administrators 组、该所有者等于当前令牌的默认所有者。DACL 仍只允许当前 TokenUser；NULL DACL、其他账户、复杂 ACE 和无当前用户授权均拒绝，令牌查询失败也拒绝。普通数据库、根目录、凭据、配置、锁及 `read/write/validateFile` 不使用此例外。POSIX 仍要求当前有效用户和无组/其他账户访问权限。

只有已知上传扫描库的 DELETE 回滚旁路调用新接口；WAL/shm、未知文件和未持有维护锁的调用不获得该资格。清理仍先预览核验，再让 SQLite 自身恢复热日志，保留原有七天期限、原生对象绑定、持久删除意图及共享缓存预算。

测试使用真实 SQLite 溢写与进程退出生成日志，核对维护锁和键边界、普通文件严格规则、Everyone/other-read 权限拒绝、硬链接与符号链接拒绝，以及拒绝后库、日志和清理凭据原字节不变。继续运行完整热日志恢复、真实 CLI、取消、进程退出重入和缓存额度耗尽测试。各工具链及原生结果按实际原件记录，不从旧版本或编译成功推导新版本完整通过。

此修正不完成全局自动 GC、未知身份历史临时项、全局磁盘预算或完整跨平台交付。
