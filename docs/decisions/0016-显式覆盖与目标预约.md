# 显式覆盖与目标预约

日期：2026-11-05。对应主计划 v0.49。Windows UCRT/MSVC 已完成本节列出的本机验证；新实现的 Linux/macOS 原生验证及实际包资格另行记录，完整 R03 仍未完成。

## 使用与执行端

新版 `upload` / `download` 接受 `--on-conflict overwrite`。GUI 在“传输选项”选择“覆盖同名普通文件”，说明完整校验后才替换文件、目录合并并保留无关项。恢复沿用原任务策略，不能用当前下拉框或恢复参数改变策略。默认 `rename`、原有 `fail` 和旧日志保持原有含义；`skip` 仍明确拒绝。

上传由服务器执行覆盖，下载由客户机执行覆盖。新增独立能力 `conflict-overwrite-v1`；仅有 `conflict-fail-v1` 的服务不能执行覆盖。客户端在发送文件正文之前拒绝缺少能力的对端。非默认策略进入版本二创建摘要、任务查询、接收日志与下载请求绑定，相同请求 ID 更改策略为完整性错误。R6 接收尚未开放覆盖选择；其默认文件/目录发布已参与本节的预约。

## 文件和目录

文件正文始终写入同目录独占临时文件，分块校验并同步检查点，完成全文件 SHA-256 和文件同步后持久记录 `committing` 意图及新临时文件原生身份，再原子发布。Windows 使用不允许复制回退的 `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`；Linux/macOS 使用固定父目录描述符的 `renameat` 并同步父目录。拒绝目标目录、链接、重解析点、特殊对象和只读文件；不预先删除或截断原文件。需要同时容纳原文件和新临时文件的空间，不能预支覆盖后才释放的空间。

已有普通目录通过安全目录适配取得原生身份并持久记录，后代沿该映射处理，保留目标中不在源清单中的项。新目录继续使用原生不覆盖发布。若目录发布期间出现外部同名对象，明确报冲突并保留临时证据，不猜测归属或递归删除。目录合并采用逐项提交，整个批次不具有事务回滚语义。

## 预约和恢复

覆盖文件从打开至完成/释放游标期间持有目标预约；同一日志最多 16 个当前/暂存游标，不按整个文件数保存内存锁表。目标父目录固定，文件名 NFC 和大小写折叠后的 SHA-256 生成 `.dukto-target-<摘要>.lock`。默认重命名、fail、目录发布及 R6 默认提交也参与相同预约；重命名避开已预约候选，其他策略明确报冲突。Linux 上额外串行化大小写别名是保守规则。正常退出清理预约；设置 QLockFile 的时间失效为零，死进程按进程身份检测接管，不能按任意时间抢占活动执行者。未知内容的同名预约文件会阻止操作且保持原样，测试不允许将它作为陈旧锁删除。

恢复先重新取得预约，再核对日志里的新文件原生身份和全摘要。如果发布已发生，仅确认同一个文件；若该结果后来被替换或改写，报告完整性错误。最终目标不是同一结果且临时证据已消失时拒绝再次覆盖。真实崩溃测试同时覆盖原策略恢复，避免默认重命名路径留下陈旧预约文件。

预约用于同一主机上采用本适配的新执行者之间的协调。它不是对外部程序、旧版本或网络文件系统多主机写入的强制锁。POSIX 的普通路径重命名不具备比较并交换语义；类型检查与发布之间，同一用户在程序外任意改写末分量的竞争无法用任务锁完全排除。目录描述符和不跟随链接规则防止把正文写到链接指向的外部文件，但不能宣称任意外部并发编辑都具有事务隔离。断电、非常规文件系统及跨主机共享盘仍需独立验收。
