# Windows空闲系统线程池有界回收

日期：2026-11-06。编译标准仍为C++14，生产代码及其资源限额保持原实现。

R89及R90的Windows UCRT并发隔离专项曾在任务全部结束后观察到线程数从6增至8，超过原来的基线+1门槛。失败运行、原断言和原始日志保留，不能用其他实例成功覆盖。

对精确R90二进制的三次独立诊断保留原专项及原返回样本。前两次为6→7→5，第三次实际复现6→8→5；第三次原断言仍然失败。新增两个线程的原生入口均为同一ntdll.dll的0x24990。匹配模块RSDS身份的微软公开PDB将该地址精确解析为TppWorkerThread，位移为0。该复现解释了同类系统线程池暂留造成的采样失败，不意味着能追溯证明已经退出的首次失败进程的全部线程来源，也不代表完整软件已经通过稳定性验收。

新采样器在每次正常0.3秒等待后记录资源数值和相邻的原生线程入口快照。原RSS、句柄及线程数值断言保持不变。当且仅当线程数超过基线+1、快照完整且所有新增入口都等于该进程基线已有的ntdll入口时，最多再观察60秒，每5秒记录一次。只有线程数实际回落到原门槛内才返回回收后的样本；原始超限值、全部观察和实际耗时同时写入报告。应用入口、未知入口、查询失败、数量不一致或持续超限均不能据此得到通过。POSIX保留原采样方式。

这项改动明确调整了Windows系统线程池暂留的观察时限，不能声称测试输入或采样时序未变。它没有调高线程、句柄或RSS门槛，没有减少传输轮数，也没有修改生产线程池或Windows系统配置。

最终验证分别使用相同R90生产二进制执行MSVC/UCRT正式并发隔离专项，均通过。真实Python子进程额外保持16个应用线程时，采样器在约0.33秒内拒绝系统池宽限；真实Windows私有线程池从5增至10、关闭后回落到5，约5.4秒完成观察并保留超限原样本。独立Alpine仅验证POSIX采样导入及原行为，没有借此声明协议通过。

代码与结果见tests/idle_resources.py、tests/parallel_isolation_integration.py及docs/validation/2026-11-06/thread-idle-r91e-windows/receipt.json。全局线程预算、完整长期资源趋势和正式发布仍需分别验收。
