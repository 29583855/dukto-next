# R6收发与目录映射共享缓冲授信

日期：2026-11-06。实现使用C++14/Qt5，适用于Windows、macOS、Linux；原生资格按精确提交分别收验。

R6兼容入口此前限制了单次256KiB读取与512KiB的Qt输入缓冲，但没有把这些固定工作缓冲计入新版共用的BufferCredit。接收路径的roots.sqlite也单独设置了2MiB主缓存，未申请共享授信。多个兼容监听器与新版TLS在同一进程运行时，这两个路径会漏计。

每个R6 Wire在扫描或网络正文处理前申请2MiB数据类额度。该保守工作额度覆盖256KiB分片、精确读取时的临时副本、Qt的512KiB输入及排空前最多256KiB输出；每次写入显式拒绝超过256KiB。读取上限、网络无进展期限、原版帧格式和接收完成语义保持原定义。

接收socket先接管描述符，再在构造函数体内申请授信；若授信拒绝，已构造socket的析构仍关闭连接。正常析构顺序先关闭socket，再释放额度。接收目录映射先申请SqliteCacheCredit(2048)，再建立数据库；主缓存2MiB、临时页缓存64KiB、临时内容落磁盘且关闭mmap，设置后读回核对。连接、查询和临时数据库先清理，最后归还缓存授信。

授信与TLS、并行片段队列、历史库和其他已接入数据库共用同一进程的128MiB总额；数据类不能占用8MiB控制保留额。额度不足返回4/budget，不等待不可取消的内存锁，不把拒绝视为成功，也不更改R6线格式。接收失败后仍保存实际失败结果，监听器可在资源归还后继续接收。

验证必须覆盖：发送前拒绝；socket、历史库和目录映射三个不同失败位置各12轮真实TCP接收拒绝；每轮关闭连接、归还授信且清除Qt数据库连接；额度归还后同监听器成功接收；实际停在文件正文前观察2MiB Wire加两个2112KiB数据库缓存，取消后临时文件/额度清理。另执行原R6线格式、超时、CLI及新版调度/并行隔离回归。首次失败与成功复查分别存档。

本项仅补齐固定R6工作缓冲与目录映射缓存。R6完整文本及跨线程消息/GUI历史模型、所有类别的独立限额、全部路径统一任务与文件句柄授信、磁盘/WAL总配额和安全GC仍需继续。预算单位按正式计划为每个进程，多个独立CLI进程的操作系统总资源由长期压力验收另行测量；不新增跨进程共享内存额度要求。零TODO标记不等于完整交付。
