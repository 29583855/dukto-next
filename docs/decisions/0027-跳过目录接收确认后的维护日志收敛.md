# 跳过目录接收确认后的维护日志收敛

日期：2026-11-07；实现批次：R113；编译标准：C++14。

维护器FULL保存目录删除意图后退出，原接收器可以继续完成已持久化的最终跳过，将`skip_final.cleaned`置1。此前维护器再次进入时，看到自己的`directory_cleanup.cleaned`仍为0便拒绝，导致合法恢复顺序无法收敛。R113先用未修改的R111产品在客户端/服务器、删除前/删除后四种真实子进程退出组合中复现相同错误，四行回归均失败，原件保留。

新的行为沿用完整最终跳过证明、冻结清单、原接收目录预约、临时原生身份和维护意图校验。接收器已确认且维护意图待确认时，只读预览返回`pending-confirmation`；执行仅在FULL事务中核对两份原证明并补齐维护确认。此分支不再次查看、打开或删除原临时路径，因此后来同名的新目录及其内容保留。普通维护删除仍走原生身份匹配的空目录删除路径。

确认事务允许合法的接收确认位0或1，但仍要求严格SQLite整数、精确原证明和唯一匹配行；目录确认必须从0更新到1。任一写入失败，事务整体回滚。反向的“维护已确认、最终跳过未确认”仍拒绝，损坏的任一证明也拒绝。没有持久最终决定的skip对象不据此获得清理资格。

本机UCRT/Qt5.15.19与MSVC/Qt5.15.2各四项完整CTest通过，目录专项各59条数据行、19个JUnit方法。新增四种真实退出/接收器恢复/维护顺序和六种损坏证明反例；每种正例还验证只读预览、SQLite trigger强制确认失败后的回滚、重复维护、再次接收恢复及同名新目录正文不变。服务器样本验证共用接收日志恢复，不改变过期任务终态，也不重新授予远端传输权限。

243份应用及测试输入在本机测试前后逐字节冻结，修改的C++文件保持UTF-8无BOM/LF，函数使用中文日期注释，格式与C++14审计通过。首轮收集器误用UTF-8读取Windows Qt失败日志而退出，原CP936日志及收集失败保留，后续仅按原编码读取，没有改写原始日志。
