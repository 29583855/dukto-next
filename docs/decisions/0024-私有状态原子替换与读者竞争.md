# Windows私有状态原子替换与读者竞争

日期：2026-11-06。适用：C++14/Qt5的PrivateStore；POSIX提交路径保持原实现。

## 原始问题与证据

精确3fbec42的四runner完整运行42083656124已结束。Ubuntu、macOS arm64和x86_64各38协议通过，Windows为40/41；失败发生在真实传输中执行serve share add变更共享根时，返回5/identity：私有状态原子替换失败。五种原生环境各21核心通过，Alpine另38协议通过。原运行和缺失失败子报告如实保留，不能写成完整矩阵通过。

本机Win32探针使用普通只读句柄复现MoveFileExW错误5；测试自有句柄释放后可以原子替换。此前SourceFile不共享删除，短时间读配置会产生这一类竞争。没有跟踪到原CI的具体占用句柄，因此仅确认机制和修复验证，不声称原CI占用者已唯一确定。

## 决策

- 保持同一私有目录的随机临时文件、当前账户ACL、完整写入与FlushFileBuffers，然后MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)。
- 仅对系统5/32/33有界等待：最多21次，新增等待预算500ms，约25ms间隔。预算约束新增等待，不能限制操作系统调用本身的耗时。
- 每次尝试重新核对私有根ACL及目标：普通文件、非只读、无重解析点、归属和权限安全；不放宽安全校验，不先删原配置，不复制回退。
- 持续占用返回退出码5，阶段identity-busy。失败保留旧配置并清理本次临时文件；占用释放后由调用者显式重新执行命令。
- 不改变传输源的SourceFile共享规则；不允许授权失败静默继续，不对磁盘类错误增加网络自动重试。
