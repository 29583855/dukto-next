# 本机客户端管理

日期：2026-11-05。对应 R09、P3A；本项只补齐服务器本机的主体查看与选择，完整会话和证书生命周期另验。

服务器 GUI 的“本机共享”页提供“刷新客户端”和“下一页”，显示有效及已撤销身份。点击身份填入管理用 UUID，并显示当前修订和各共享的浏览、下载、上传权限。授权修改或撤销成功后重新读取第一页，选中身份的权限随当前列表更新；当前页没有该身份时明确提示重新选择。共享、客户端、远程文件和任务各自使用独立模型与游标。

CLI 在服务器本机执行：

```text
dukto-cli serve clients --state-directory <服务状态目录>
dukto-cli serve clients --state-directory <服务状态目录> --cursor <上一页after> --json
dukto-cli serve clients --state-directory <服务状态目录> --all --json
dukto-cli serve grant --state-directory <服务状态目录> --client <客户端UUID> --share docs --allow-browse --allow-download --json
dukto-cli serve revoke --state-directory <服务状态目录> --client <客户端UUID> --json
```

列表使用本机受保护的服务状态目录，没有新增远程列举客户端的 RPC。远端主体仍只能查询其被授权的共享和所属任务。

`clients` JSONL 事件包含 `eventVersion=1`、`event=clients`、`entries`、`after`、`more` 和 `message`。每个条目精确包含 `client`、十进制字符串 `revision`、`grants`、布尔值 `revoked`。凭据、凭据摘要、配对票据和私钥均不进入公开结果。

UUID 按规范小写且无括号排序。单页最多 100 条，同时限制完整事件不超过 64 KiB；最长授权会使一页少于 100 条，必须按 `more` 判断。游标为空或规范非零 UUID。`--all` 逐页输出并检查游标前进，不累积全量结果；空尾页保留传入游标且 `more=false`。

枚举最多扫描 1024 个主体文件，仅保留下页最小 101 个候选键；单条记录仍受私有存储和协议限制。损坏文件名、记录和异常授权明确报错，不能展示为有效的空身份。认证与列表复用严格元数据校验；撤销及错误秘密仍按统一认证拒绝处理。

列表不是冻结快照：每页读取原子发布的当前记录。并发新增且排序在现有游标前的身份需要从第一页刷新才能看到，授权也可能在分页期间变化。授权修改始终由生产核心再次验证，不依赖 GUI 显示的旧页。

验证见[执行进度](../执行进度.md) v0.21：真实 TLS 双主体配对、授权更新、轮换、撤销及认证拒绝；107 身份按字节限额分页；单元测试覆盖 100 条边界、损坏记录和非法游标；生产 QML 通过鼠标选择、撤销后更新及翻页。三平台都保留同一实现和 CI 项目，各平台结果按实际执行记录。
