# 跳过历史只读完成核验

日期：2026-11-06。状态：本机验证中；公开 skip 尚未开放。

接收任务完成后重试，必须分别核对实际复制结果和历史跳过决定。不能因为目标现在存在就推断已经复制，也不能因为历史跳过目标后来被删除而改为重新发送。

`DurableReceive::verifyCompleted` 使用原接收日志的只读事务。它要求任务、清单、目标根原生身份和冲突策略匹配；skip 只接受完整 v4 证据，不迁移旧日志、不补建缺库、不执行临时文件清理。

准备决定及晚期跳过的规范校验由 `ReceiveSkipProof` 共用。每次只查询当前项及一个父索引，验证继承关系和原接收意图，字段读取有界；无需将整个目录树放进内存。晚期跳过必须已经持久完成临时项清理；缺项、额外记录或未完成接收不能通过完成核验。

已复制文件仍固定原生对象，按 256 KiB 片段重新计算完整 SHA-256，并在片段之间响应取消或授权检查。已复制目录必须仍为原对象。历史跳过仅证明原决定，核验不会访问已跳过的目标树或读取发送源。

原 `verified(id, path)` 回调只接收已核验的 copied 项；新增显式处置回调返回 copied/skipped 及原始跳过根，供上层和原处置日志逐项比对。调用者必须在整个核验成功返回后才能发布完成状态；任何逐项回调都不能单独代表整任务成功。

验证范围包括：混合目录与文件、全跳过、打开前冲突、收完正文后的冲突、目录发布竞争、跳过目标删除、正文篡改、同内容对象替换、15 种日志损坏、缺库不创建，以及反复取消后连接和日志字节保持不变。原 rename/fail/overwrite 流程和双端摘要通过公共入口另做回归。

此项只是公开跳过接线的一部分。任务计量、明细分页、服务器与客户端完成历史、能力协商、CLI/GUI 和资源/故障验收全部完成前，`checkedConflictPolicy("skip")` 继续拒绝公开请求。
