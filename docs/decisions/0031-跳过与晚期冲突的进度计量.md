# 跳过与晚期冲突的进度计量

日期：2026-11-06

状态：内部接收和真实 TLS 交换已接线；公开 skip 仍须完成任务持久化、协商和历史恢复验收。

`confirmed` 只能说明数据已经同步，不能说明最终文件已复制。接收完整正文后，外部进程可能在最终发布前创建同名目标；skip 策略此时保留外部目标，先前传输的正文属于丢弃。直接把同步量当成复制量会使历史结果及进度失真。

## 固定计数

`TransferAccounting` 只保存十个标量及两个边界，不保存文件集合、事件队列或正文。条目按冻结清单的连续 ID 顺序归结，空文件、复制目录及跳过目录同样计数。真实文件处置及跳过根仍由接收日志、强清单和处置日志验证，本计量模块不代替磁盘提交证据。

| 字段 | 含义 |
| --- | --- |
| bytes | 本轮实际接收与恢复重读字节之和 |
| confirmed | 其中已经同步并确认的字节 |
| restored | 本轮重新读取并校验过的恢复字节 |
| copiedBytes | 最终处置为复制的文件字节 |
| skippedBytes | 最终处置为跳过的文件字节 |
| discardedBytes | 接收正文后才最终跳过的字节，包含恢复重读的正文 |
| copiedFiles / copiedDirectories | 最终复制的文件/目录数量 |
| skippedFiles / skippedDirectories | 最终跳过的文件/目录数量 |

逻辑处理量 `handled = confirmed - discardedBytes + skippedBytes`。网络速率只使用 `bytes - restored` 的增量。准备阶段跳过不会增加网络或复制量；晚期跳过同时增加 skippedBytes 和 discardedBytes，不重复增加 handled。网络剩余量为 `total - skippedBytes - (bytes - discardedBytes)`。

例如任务共100字节：复制40字节、准备阶段跳过50字节、完整接收10字节后因竞争而跳过。最终网络/恢复接收总量50、复制40、跳过60、丢弃10、逻辑处理100；不能显示“复制100字节”。

## 严格验证

所有字节及数量使用规范十进制字符串，拒绝浮点、负数、前导零、缺字段和额外字段。收到的快照先在候选对象中完成校验，失败保持已接受状态不变。

原始计数及逻辑处理量必须单调。恢复增量不能超过本轮新增接收和同步增量，不能把过去的网络数据改类为恢复；丢弃增量不能超过新增跳过字节；复制或跳过字节增加时必须同时归结新的文件。全部计数还必须满足同步/接收、字节守恒及清单条目上限。最后一项归结后，复制与跳过必须准确覆盖总字节，所有收到的数据均已同步。

加法先核对剩余额度，守恒式先减后加，支持 `qint64` 最大值而不发生有符号溢出。条目总数上限沿用强清单的1000万项。

## 协议与调用边界

旧版 `byte-progress-v1` 保持原六字段。内部显式处置计量启用后发送十三字段：原六字段加上七个处置计数。两端须以同一冻结条目数构造观察者，严格拒绝六字段/十三字段混用。

目前公开服务能力和 CLI/UI 仍不声明 skip；下一步需要显式协商扩展进度、持久保存固定计量，并用最终处置摘要交叉核对。只有这些路径和历史恢复通过后才开放公开入口，内部十三字段构造参数不代表公开兼容承诺。

接收端在准备跳过的 `Attached`、目录的 `Attached`、普通文件的 `Completed` 以及并行窗口最终 `Completed` 之前归结并发布必要进度。发送端只接收验证后的进度，不自行根据源文件大小累计。交换结束仍须等待处置摘要、任务提交和最终确认，进度达到100%不直接声明任务完成。

## 验证范围

独立计量测试覆盖混合处置、恢复后晚期冲突、全部跳过、空条目、64位上边界、百万条目固定计数以及畸形/回退快照。真实单 TLS 与独立服务器的4/16数据通道测试在两个方向核对最终进度和独立处置日志；真实 TLS 另验证旧协议及扩展字段攻击。执行结果以本轮原始日志和回执为准，不能借给未验证的公开任务路径。
