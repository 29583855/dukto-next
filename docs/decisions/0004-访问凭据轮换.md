# 服务器访问凭据轮换

日期：2026-11-05。对应 R01/R02/R09/R11；Windows UCRT/MSVC 已实际验证。Linux/macOS、服务器证书更新及完整会话有效期另行验收。

客户端保持相同 UUID、服务器信任指纹和授权，仅替换访问秘密。服务器在同一修改锁内重新验证原凭据，原子写入新摘要并递增修订号；不保存旧秘密或新秘密明文。旧配对票据不能重置已轮换身份。撤销、授权修改和轮换使用同一跨进程锁，撤销后不能通过轮换恢复权限。

## 使用与恢复

```text
dukto-cli rotate --state-directory <客户状态目录> --profile office --json
```

GUI 在服务器“连接与文件”页点击“轮换凭据”。操作必须使用已配对资料，CLI 不从参数读取新秘密；共用核心生成随机 256 位秘密并写入当前账户的私有目录。

1. 客户端取得该资料的跨进程锁，先持久保存 `pendingCredential`，再发送远程变更。并发轮换明确返回繁忙，不另建候选秘密。
2. 服务端持久切换成功后才发送确认；客户端核对同一主体后，将 pending 提升为当前秘密并删除 pending 字段。
3. 请求发出前程序退出，重试先试 pending；只有服务器明确返回认证拒绝时才用原秘密提交同一候选值。网络、证书和协议错误不会被当成认证拒绝。
4. 服务器切换后回包丢失，重试以 pending 认证成功即可完成本地保存，不再次切换或递增修订号。
5. pending 尚待确认时，普通 GUI/CLI 操作提示继续轮换；不要删除资料、重做首次配对或手动替换秘密。使用相同资料再次执行 `rotate` 或点击同一按钮即可继续。

资料的旧格式仍可读取；pending 存在时严格核对格式、长度、已配对状态及与当前秘密不同。迟到的配对确认不能覆盖更新后的秘密、目标、信任或 pending 检查点。

## 活动任务和协议

双方通过 Hello 显式协商 `credential-rotation-v1`。消息 `RotateCredential=10` 只接受一个 `credential` 字段，为 64 位小写十六进制字符串；响应 `CredentialRotated=11` 返回原主体、当前授权和规范十进制修订号。新秘密仅在认证 TLS 正文和本机私有资料中存在，不写到命令参数、事件、任务库或诊断日志。对端未声明此能力时明确拒绝。

旧控制/数据连接在下一次认证安全点停止；生产传输通常每 250ms 重查，实际响应还受网络/磁盘影响。认证失效期间任务记为 `interrupted` 并保留已同步块；使用有效新凭据重新校验并继续原请求/任务，不重复提交文件。撤销的原主体即使有检查点，也不能查询或恢复。共享根改配、内容变化等其他错误继续沿原有规则处理。

轮换不会自动暂停本地其他客户端进程；其旧连接会收到认证/网络错误，再用更新后的同一私有资料恢复。GUI 当前只允许在普通操作槽空闲时点击，防止本面板自己同时发出轮换和文件操作。未重新鉴权的旧凭据不会因持有公开任务 ID 而获得权限。
