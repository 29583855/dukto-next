# 生产状态会话与 CLI 接入

更新日期：2026-11-08。R126 将 CLI 服务、客户端及维护入口接入 `StateSession` 的持久根登记和共享协调资格。这是业务生命周期的接入；SQLite、原子替换、临时正文和未知对象的写前授信尚未接入，不代表生产总配额已经生效。GUI 旧目录映射和普通历史安全迁移继续实施。

CLI 使用 `--state-directory` 选择普通状态父目录。首次业务使用在其私有 `budget/` 中建立协调域，随后为实际打开的 `service/`、`clients/`、`transfers/` 成员登记。父目录权限保持原样，已有 `history.sqlite`、`receipts.sqlite`、资料和用户文件不会被移动、删除或重写。外部配对文件仍按原私有读取规则访问，不认领其所在目录。

默认额度如下，使用既有 `state budget show/set` 查询、按修订修改。已有配置完整沿用，成员登记失败不会重置为默认值。

| 范围 | 默认字节数 | 大小 |
| --- | ---: | --- |
| 合计 | 21474836480 | 20 GiB |
| 历史 | 268435456 | 256 MiB |
| 元数据 | 1073741824 | 1 GiB |
| 临时正文 | 17179869184 | 16 GiB |
| 未知 | 268435456 | 256 MiB |

默认值是可调整的账本准入配置，不是磁盘预分配或可用空间保证。目前只有固定账本和根标记在该账本中计量，实际业务数据尚未进入合计；正文额度不能据此解释为当前传输的大小上限。历史上限仍不超过既定 256 MiB。

`StateSession::root` 返回的共享所有权同时保留协调根共享占用。工厂临时会话销毁、句柄复制或另一个同域进程退出，都不能提前归还仍在使用的协调资格；最后一个业务根和会话关闭后才允许配置独占维护。CLI 服务即使处于空闲监听，也在整个监听器和工作线程生命周期内保留业务根。退出进程由操作系统释放原生锁，持久登记和业务文件保持，不按 PID 退款。

打开时核对当前成员标记、中央登记、域及目录原生身份。首次登记必须取得成员根独占维护，释放后以共享方式重开；不原地升级共享锁。初始化或成员首次登记的原生占用竞争最多短暂重试五秒，并在预算锁外检查取消。ACL、链接、不完整控制区、未知版本、复制标记和目录换代直接拒绝；不清除残片或重新初始化已有损坏域。显式维护遇到成员共享占用立即让出，不参加业务启动重试。

只读占用命令 `client storage` / `serve storage` 使用 `StateSession::observe`：不建立预算或成员标记，保留旧未登记私有根的观察行为；已有协调域则共享持有，并核对存在的成员标记。观察没有把未登记的旧文件加入预算，也不提供删除资格。诊断中的外部资料读取和 GUI 各入口还需在后续目录映射接入时继续处理。

核心工厂只接受固定直接根及显式传入的旧 GUI 位置 `remote/service`、`remote/clients`、`remote/transfers`。这些名称只限定程序能定位的位置，实际绑定仍以原生身份和中央登记核对；不能用文件夹名称证明文件可删除。R126 CLI 业务使用直接根。GUI 目前保留旧 `remote/` 状态；其与 CLI 访问旧位置时的协调域发现尚未统一，不能将本轮授予 GUI/CLI 全部入口共同预算资格。

本机两种 Windows 工具链专项已通过：返回对象的资格寿命、配置保持与标记准入、只读观察、维护立即拒绝、损坏与复制拒绝、取消、两个真实进程同时首次登记、直接退出、中文空格目录、原历史与资料保持，以及真实 CLI 空闲监听阻止配置。首轮夹具使用 `QProcess::terminate()` 未结束 Windows 控制台服务，保留原失败；改为 `kill()` 核对强制退出后的内核锁释放，原 30 秒等待门槛不变。这不授予该夹具跨平台优雅停机资格，既有信号/恢复验收继续保留。
