# 已有状态占用计量

日期：2026-11-08。实现语言及标准仍为 C++14，GUI 使用 Qt5，命令行在 Windows、Linux、macOS 保留独立入口。

R129 新增命令，给已有状态文件登记持久的 Unknown 占用，供后续统一配额使用。该功能要求既有预算域和已绑定的状态根；停止占用同一目录的 GUI 监听或 CLI 操作后执行：

```text
dukto-cli state root account --state-directory <状态父目录> --state-root clients --json
dukto-cli state budget show --state-directory <状态父目录> --json
```

`--state-root` 可以是 `service`、`clients`、`transfers`、`history`。命令不隐式创建缺失的域或成员根，也不迁移其他位置的历史。GUI 服务器页公开的状态目录与 CLI 参数对应关系见 [目录共享](GUI与CLI状态目录共享.md)。

计量逐项读取直接普通文件的属性，不读取正文、不将全部目录项放入内存。每项取逻辑长度与原生已分配长度中的较大值；同一观察的高水位持久保存，重复执行不重复增加，增长补差额。文件缩小或消失不会自动退款。同名替换及改名保守另计，旧记录保持；硬链接按名称保守重复计量。已验证根标记的 256 个逻辑字节已计入 Metadata，仅额外分配部分计入 Unknown。

JSON 的 `inventory` 返回逻辑长度、原生分配量、本次新增量，以及未覆盖目录、链接和特殊项的计数，64 位整数以十进制字符串表示。人类输出也显示相应合计；报告不输出文件名、原生对象身份或正文。目录、链接、FIFO 等特殊项原位保留且不递归，不能将单根报告视为整个状态域已完整计量。

协调根和成员根都必须取得独占维护资格。运行中的生产会话会阻止维护；取消或进程退出后，已成功落盘的部分计量继续保持，后续可以继续。真实已有占用超过配置额度时仍照实登记为透支，不能因额度不足把它当作不存在。固定记录槽耗尽或整数溢出会受控报错，已经登记的记录保持。

本命令只完成已有直接文件的未知占用登记，不证明任务归属，不授予删除资格，不进行自动回收。原生身份可能复用，因此也不能仅凭该身份退款或删除。未接入生产写前配额的状态仍明确返回 `productionQuotaEnforced=false`；统一写前限制、全部根和临时对象归属、普通历史安全迁移、跨卷处理、有效幂等保留和自动 GC 继续实施。当前命令不能保证后续生产写入被额度拦截。
